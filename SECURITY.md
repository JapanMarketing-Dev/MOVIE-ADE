# Security

## Reporting a vulnerability

Please do not report vulnerabilities in public issues. Use GitHub [private vulnerability reporting](https://github.com/JapanMarketing-Dev/MOVIE-ADE/security/advisories/new) instead ("Report a vulnerability" on the Security tab of this repository).

Include steps to reproduce, affected versions and the expected impact. We will reply as soon as we can. Please keep the details private until a fix is released.

## Supported versions

The latest release and the `develop` branch.

## How MOVIE-ADE handles sensitive data

- Transcription API keys are encrypted with the OS keystore and stored on your machine (or kept only for the current session where encryption is not available). They are never sent to the developers.
- Recordings, images and findings are saved in `.ade-movie/` inside the project you open.
- MOVIE-ADE talks to external services only for features you choose: audio for transcription when you pick OpenAI or a compatible server, agent usage display (queries each provider's API with your own Claude / Codex login), sending to GitHub (through your own `gh` CLI), update checks (GitHub Releases), and Whisper model downloads (Hugging Face).
- Crash reports: the app sends crashes and unhandled errors to Sentry (on by default; turn off in Settings → Privacy). Reports contain the stack trace and OS / CPU / app versions. Home and project paths, URLs, terminal output, transcripts, findings, email addresses, API keys and IP addresses are removed or not collected. Development builds (`pnpm dev`) also send, tagged `development`; E2E runs and unit tests never send. Forks can point `FERRET_SENTRY_DSN` (old name `MOVIE_ADE_SENTRY_DSN` still works) at their own Sentry or set it empty. Details: `site/docs/privacy.html#crash-reports`.

## Release authenticity

The installers are not code-signed by Microsoft yet, and the download server (Cloudflare R2) holds both the installers and their manifest. So every release also has `SHA256SUMS` and `SHA256SUMS.sig`, signed with the Ferret release key. The key is kept apart from the download server: only the release workflow job that has no R2 credentials (and the maintainer's machine) can sign, and publishing stops if the signature is missing or does not match. Ferret's update check verifies the signature with the key built into the app before it offers a new version, then downloads the installer itself and keeps it only if its SHA-256 matches the signed `SHA256SUMS`. The download page does the same check in your browser with the same key before it saves a file.

## Rules we keep (each one is pinned by a unit test)

These come from security reviews. `test/unit/security-3.test.ts`, `test/unit/security-4.test.ts`, `test/unit/security-5-net.test.ts`, `test/unit/security-6.test.ts`, `test/unit/security-7.test.ts` (and the tests they point to) fail when one is broken.

- **Agent permissions.** By default Ferret starts Claude Code with `--dangerously-skip-permissions` and Codex with `--dangerously-bypass-approvals-and-sandbox`, in every project and for agents started automatically or by hand, and marks registered project folders as trusted for both. This is the user's chosen default. The user can turn it off in Settings → Agents → Skip permission prompts; agents then start in their normal mode and ask before trusting a folder. Launch arguments the user types are used as written. While it is on, an agent working in a cloned repository can follow that repository's instructions (agent instruction files, hooks, settings) and edit files or run commands without asking. The main process decides this (`resolveAgentLaunchPolicy`), not renderer defaults. It splits the saved command and arguments into words once, applies the rule to those words and starts the agent only from the result: permission-skipping and folder-trust flags come only from that setting or from the arguments field written plainly, and a launch is refused when one is placed in the command field or hidden with quotes or backslashes (`test/unit/security-5-agents.test.ts`).
- **Release authenticity.** Anything users download must be checkable against a key that is not stored with the download. A release without a valid signature is not promoted and not offered by the update check. The signing key is never given to GitHub Actions: CI only builds and tests, and signing, drafting the release and uploading to R2 are local steps that hash the files built on the same machine. Update metadata, signatures and installers are fetched without following redirects away from the download server.
- **Project-driven network requests.** Opening or previewing project files must not make network requests the user did not choose. Remote images in Markdown previews stay blocked until the user clicks "Load remote images" for that page. Project HTML opens in the built-in browser as `ade-page://project/<path>`, served by the main process only from inside the open project, with a Content-Security-Policy that keeps scripts, styles, images, fetch, forms and frames on the project itself; the page cannot navigate, open tabs or pop-ups to other sites by itself (the user types an address to go there). The address bar does not open `file:` URLs. Automatic Git work (status, the file tree's colors, the background fetch) runs with hooks, fsmonitor, `ext::` and local-path transports turned off, and the background fetch runs only for a remote the user approved in the footer, stored outside the project (`test/unit/security-7.test.ts`).
- **Public endpoints.** On the anonymous feedback relay, rate limits are checked before reading or parsing attacker-sized input, narrower limits are checked before shared ones (a denied request never uses up the global limit), and idempotency keys are claimed in one atomic step before any visible side effect.
- **Crash reports.** Every kind of data listed above as removed has a scrub sample in the tests, including IPv4 and IPv6 addresses.
- **Executables come from trusted places.** Built-in agents, account logins, Git, ripgrep, whisper.cpp and the Claude Code / Codex command lines that organize findings start from an absolute path found on absolute `PATH` entries outside the project, never from the project folder, on every OS; the main process resolves the path before the shell starts, so shell startup files cannot change which program runs, and in an SSH project the remote shell applies the same rule before running the agent. On Windows every terminal also tells `cmd.exe` not to search the current folder. Logins run from the local home folder, not the project, even while an SSH project is open.
- **Release identity comes from the signature.** Version, platform and download path are read from the names in the signed `SHA256SUMS` of that version, and the manifest must list exactly the signed files. What the user saves is the file whose bytes were checked against that signature: the app downloads and checks the installer itself, and the download page checks it in the browser. No page or app hands out an unchecked installer link.
- **Automatic updates install only signed bytes.** The background update downloads only the file named for this computer in the signed `SHA256SUMS` of that version (the macOS `.zip` in the separately signed `UPDATE-SHA256SUMS`), only from the download server, and installs it only if its size and SHA-256 match; the hash is checked again right before it is handed to the installer. The app does not read electron-updater's `latest*.yml`. Development builds and E2E runs never install (`test/unit/auto-update.test.ts`, `e2e/auto-update.spec.ts`).
- **Sign what you built, from fixed inputs.** The release key signs only hashes computed from the installers on the signing machine; the copy on the download server is compared with them and never supplies the signed values. The local Linux build uses a container image pinned by digest, Debian packages from a fixed snapshot date and pnpm pinned by hash, and records the commit and inputs next to the installers. The download page reads release metadata and signatures with a byte limit while streaming and a time limit (`test/unit/security-5-release.test.ts`).
- **Check the file you opened.** Project reads and writes check the opened file handle against the project's real path after opening, and never truncate before that check. Paths that were checked and then reopened are not trusted: recordings, after-shots and project media are streamed from the checked handle, and a directory listing is discarded if the folder it read is no longer the same folder inside the project. Files added from outside the project are copied only if the opened file is the one that was measured, and the size and count limits are enforced while copying, so a source that grows or is replaced after the check is stopped and the partial copy removed (`test/unit/security-6.test.ts`).
- **Consent is never URL state.** Loading remote images in a preview needs a one-time, unguessable grant that the main process issues to the page's own button for that document. Links, typed URLs and restored sessions cannot create it, and saved project URLs never keep it.
- **Automatic work is bounded in total.** Anything that runs when a project opens (directory listings, review history, the Linux folder watcher) has a count, byte and time budget, not only a per-item limit. Cleaning up old recordings never delays the window: it runs later in small slices, each with its own count, byte, delete and time budget (`test/unit/security-5-net.test.ts`).
- **Keys go only to approved addresses.** Saved keys, `apiKey` / `apiKeyEnv` and headers read from environment variables are sent only to the provider's preset address or to an address the user approved in a Ferret dialog that names it. The main process keeps that list; addresses coming from the settings screen do not count as approval, and addresses already in the settings are not carried over as approved when updating; a custom address is approved once with Test connection. Terminals get a decision-model relay token, never the key. Each token has a limit on calls, calls per minute, tokens and cost, and each project has a daily limit. The limit is reserved before a request is sent, at least 1/16 of the token's limit even for the first request, and a response that does not report its usage counts as its reservation. The relay accepts only the decision request format (model, state, questions, images), replaces the model with the configured one, and reserves the request's worst-case tokens and cost in full before sending; a request that would not fit is refused, and endpoints without a price are counted at a high default price unless they run on this computer. Requests that carry a key never follow redirects. Changing or removing a saved key ends every relay token and in-flight request that might use the old key. A token stops working when its terminal closes, when the decision settings change, or when its limit is used up; requests it already started are cancelled at that moment, and a request body that does not arrive within 30 seconds is cut. The daily project limit is kept in a file in Ferret's own data folder, so restarting Ferret does not reset it (`test/unit/security-6.test.ts`).
- **Project changes are made relative to an opened folder.** Creating, renaming, moving, copying and deleting project files and review data go through `src/main/pinnedDir.ts`: the parent folder is opened and checked, the change is made relative to that folder, existing names are never replaced, and folders are moved to a quarantine name before their contents are deleted. Replacing a parent folder with a link during the change does not reach outside the project.
- **Public endpoints, continued.** The feedback relay groups source addresses (IPv6 by /64) and reserves a shared budget in one atomic step before creating any per-source state or reading a body, giving it back whenever the source's own attempt, address or installation limit refuses the request, before or after the body is read (`test/unit/security-5-release.test.ts`, `test/unit/security-6.test.ts`). The global issue quota is taken last, just before the GitHub call, and released on every rejection. User text is posted as a literal block and the app version and OS details as inline code, so nothing the sender controls can create GitHub references or mentions. A GitHub call whose outcome is unknown keeps its idempotency claim and media and is not retried or sent another way.
- **Capture and clipboard follow the user's own action.** The main process accepts app requests only from the main frame of the Ferret window. Starting a recording, taking a screenshot of the window and listing screens or windows need a click or key press in Ferret just before (one recording and one screenshot per action), stay within the target and sound sources the user picked, and show a recording mark in the window title and macOS Dock. Only the hidden recording window may capture video; the camera is never used. Text a terminal program sends to the clipboard (OSC 52) is copied without a confirmation, but only while the Ferret window has focus and up to 128K characters; requests to read the clipboard are never answered, and the app's own screen never receives clipboard text from the main process: Ctrl+V in a terminal asks the main process to paste, which it does once, right after the key press, while the window and a terminal have focus. A screenshot does not include a browser view that shows a local file. A reviewed page can write to the clipboard once, right after the user clicks or types in that page (`test/unit/security-5-capture.test.ts`).
