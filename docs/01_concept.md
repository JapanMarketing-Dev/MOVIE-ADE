# 01. システム概要 — MOVIE-ADE

最終更新: 2026-10-02

## 一言で

**画面を操作しながら「喋って・ペンで囲む」だけで、大量のUIフィードバックを「画像＋テキスト＋URL」に分解してコーディングAgentへ渡すデスクトップADE。**

## 背景と課題

- Claude Code などのコーディングAgentは十分に優秀。ボトルネックは「どこが悪いか・どうして欲しいか」を人間が伝える部分に移っている。
- 現状の伝え方は、アノテーション（要素をクリックしてコメント入力）やテキスト入力。指摘箇所が多いと入力量が膨大になり、面倒で続かない。
- 動画をそのままAgentへ渡すのは不向き。Agent側での解釈が難しく、コンテキストも大量に消費する。

## 解決策

人間は**いつも通り画面を触りながら、声とペンで指摘するだけ**。ADEが裏で録画し、指摘した瞬間だけを切り出して、Agentが従来どおり読める形式（画像＋テキスト）へ分解する。

```
① 録画開始 → ② 画面を操作しながら喋る・ペンで囲む・テキストを置く → ③ 停止
   → ④ ADEが指摘ごとに「画像＋テキスト＋URL＋要素情報」へ自動分解
        （文字起こしは端末内。指摘への整理はLLM = 自分の Claude Code / Codex のサブスクで実行）
   → ⑤ 一覧をさっと確認（不要な指摘の削除・文言の修正）
   → ⑥ 送信 → Claude Code などのAgentが受け取り修正
```

Agentに届くもの（例）:

```markdown
## 3. [01:42] 申し込みボタンの色が薄い
- 要望: 「申し込む」ボタンの色を濃くし、押せることが分かるようにする
- 発話（原文）: 「このボタン、色が薄くて押せるように見えない。もっと濃くして」
- 画像: ./03.png   ← ペンの赤丸入り
- URL: http://localhost:3000/pricing
- 要素: button.plan-cta（テキスト「申し込む」）
- 直前の操作: トップ →「料金」をクリック
```

## 2つのモード（MTGで使えることが重要）

| モード | 画面 | 使う場面 |
|---|---|---|
| **フィードバックモード** | レビュー対象の画面だけを大きく表示。録画・ペン・テキストの最小限のツールバーのみ。ターミナルやコードは出ない | 1人でのレビュー、**MTG（打ち合わせ）での画面共有** |
| **エディタモード** | 内蔵ブラウザ＋Agentのターミナル＋指摘一覧 | 指摘の確認・Agentへの送信・修正作業 |

MTGでは、フィードバックモードの画面をZoom / Meet などで共有（または対面で投影）し、画面を見ながら話す。**自分の声と相手の声の両方**を録り、ペンとテキストも入れられる。MTGが終わると、会話の中から指摘と決定事項が「画像＋テキスト」に分解され、エディタモードでそのままAgentに渡せる。打ち合わせの議事メモ起こしと、Agentへの指示書きの両方が不要になる。

## 価値の核（これだけに絞る）

| 絞る価値 | 内容 |
|---|---|
| 入力コストをほぼゼロに | タイピングしない。喋る・囲むだけで指摘が成立する |
| MTGがそのまま指示になる | 打ち合わせ中の会話とペンが、終了時には指摘一覧になっている |
| Agentが読める形に変換 | 動画ではなく、指摘単位の画像＋テキスト＋URL。コンテキストを節約 |
| 1ボタンで渡す | 分解結果をそのままAgentのプロンプトへ送る |

**やらないこと**: 並列Agent管理、git worktree、diffレビュー、エディタ、モバイルコンパニオン、クラウド共有、チーム機能。「動画レビューができるだけ」に徹する。

## ベンチマーク

「harder」は Agent向けターミナルマルチプレクサの **herdr**（確認済み）。詳細な比較と、採用する点・やらない点は [04_benchmark.md](./04_benchmark.md)。

| 製品 | 種別 | 強み | フィードバック手段 | 本システムとの関係 |
|---|---|---|---|---|
| [Orca](https://github.com/stablyai/orca) | ADE（Electron / MIT / mac・win・linux） | 並列worktree、内蔵Chromium、任意のCLI Agent対応 | **Design Mode**（実装上は Grab と Annotate）: 要素をクリック → HTML・CSS・切り抜き画像をプロンプトへ。diff行コメントをバッチ送信 | 画面構成（内蔵ブラウザ＋Agentターミナル）と、PTYへプロンプトを流し込む受け渡し方式を参考にする。指摘は1件ずつクリック＋テキスト入力で、量が多いと重い |
| [herdr](https://terminaltrove.com/herdr/) | ターミナルマルチプレクサ（Rust / Apache-2.0） | Agentの状態検知（working / blocked / done / idle）、セッション永続化 | なし（ターミナルのみ） | 視覚フィードバックは対象外。Agent実行基盤としての位置づけのみ参考 |
| [FeedbackRecorder](https://github.com/magnuslandahl/FeedbackRecorder) | 録画→ブリーフ変換（Electron / MIT） | 画面＋音声録画 → whisper.cppでローカル文字起こし → 画面変化でキーフレーム抽出 → プロンプトをコピー | 録画＋ナレーション | **最も近い先行例**。ただし内蔵ブラウザなし（URL・DOM情報なし）、Agentと別アプリ（コピペ受け渡し） |
| [Clipy](https://clipy.online/for-agents) | Agent向け画面録画（Chrome拡張＋クラウド） | クリック座標・発話中の指示箇所・コンソールログを構造化し、リンクで共有 | 録画＋ナレーション | クラウド経由。ローカル完結ではなく、ADEとも統合されていない |

### 差別化（シャープにする点）

1. **MTGで使える**: 画面共有に出せるフィードバックモードと、双方の声の記録。先行例はいずれも1人でのナレーション録画が前提。
2. **ADE一体型**: 内蔵ブラウザ・録画・Agentが1ウィンドウ。録画停止 → 確認 → 送信が途切れない（コピペ・アプリ切替なし）。
3. **声＋ペンが指摘の単位**: 先行例は「画面が変わった瞬間」をキーフレームにする。本システムは「人が喋った・囲んだ瞬間」を指摘として切り出すため、指摘と画像が1対1で対応する。
4. **Web固有の情報を同梱**: URL、指した要素のセレクタ・テキスト、直前の操作。Agentが該当コードを特定しやすい。
5. **追加課金なしで動く**: 分解に使うLLMは、ユーザーが契約済みの Claude Code / Codex をADEが非対話モードで呼び出して実行する（APIキー不要）。動画と音声は端末から出さず、LLMに渡すのは文字起こしと操作ログだけ。APIキー利用・ローカルLLMは差し替え可能な選択肢として設計に残す。

## 段階

| フェーズ | 対象 | 内容 |
|---|---|---|
| 1 | Web | 内蔵ブラウザでのレビュー（スマホ幅表示を含む）。**MVP** |
| 2 | スマホ | エミュレータ（Android Emulator / iOS Simulator）のウィンドウをレビュー |
| 3 | デスクトップアプリ | 任意のアプリウィンドウをレビュー |

フェーズ2・3は、ADEの外にある実際のウィンドウ（エミュレータやデスクトップアプリ）をそのまま操作し、ADEがそのウィンドウを録画する方式。エミュレータもデスクトップ上の1ウィンドウなので、**フェーズ2と3は同じ録画エンジン**で実現でき、デスクトップアプリのフィードバックも可能。声・ペン・分解・Agentへの受け渡しはフェーズ1と共通。

## 高速であること

ADEとして「待たされない」ことを要件にする（起動、ターミナル入力、録画中の操作、停止から指摘一覧まで）。目標値は [02_requirements.md](./02_requirements.md) 7章、Electron採用の検証結果は [03_design.md](./03_design.md) 1章。

詳細は [02_requirements.md](./02_requirements.md)、[03_design.md](./03_design.md) を参照。
