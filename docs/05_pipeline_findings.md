# 05. 技術検証の結果 — 分解パイプライン

実施日: 2026-10-02 ／ 検証機: Apple M4 Pro・macOS 26.6.2

**前提と限界**: Macのみ（Windows・Linuxは未確認）。音声は macOS の合成音声で、実際の人の声より認識しやすい。各条件は1回ずつの実行で、数値にはばらつきがある。素材は約5分（1人レビュー、指摘20件）と約8分（2人のMTG、22話題うち要確認7件）で、90分の録画は未確認。操作ログと静止画は台本から合成した。

## 1. 結論

| 項目 | 結論 |
|---|---|
| 文字起こしの既定 | ローカル whisper.cpp ＋ `large-v3-turbo`。GPUが使えない端末は `small` |
| OpenAIのSTT | 設定で選べる選択肢にする（1人レビューの高速・高精度化、対面MTGの話者分離、低速端末） |
| 停止 → 下書き一覧（目標10秒） | 達成。停止時に残る処理は約1〜2秒 |
| LLM整理の品質 | Claude Code（sonnet）・Codex とも、全条件で指摘の漏れ0件・捏造0件 |
| LLM整理の時間（目標: 5分の録画で60秒） | Codexは達成（53〜57秒）。Claude Codeは22〜97秒とばらつき、安定しては達成しない |
| LLMの既定 | Codex。使えなければ Claude Code（sonnet） |

## 2. 文字起こし

### ローカル（whisper.cpp、Metal使用）

| モデル | サイズ | 処理時間（274秒の音声） | 文字誤り率 | 重要語の検出 |
|---|---|---|---|---|
| tiny | 74MB | 2.5秒 | 16.5% | 6/9 |
| base | 141MB | 4.1秒 | 10.1% | 6/9 |
| small | 465MB | 5.9秒 | 4.5% | 7/9 |
| large-v3-turbo（量子化 q5_0） | 547MB | 10.9秒 | 1.9% | 9/9 |
| **large-v3-turbo** | 1549MB | 9.5秒 | 1.7% | 9/9 |

- `tiny`・`base` は指摘の核になる語を落とし、後段のLLMでも回復できないため使わない。
- 量子化版は非量子化版より遅かった。
- **逐次処理は必須。** 無音の多い音声（MTGのPC音声系統）をファイル全体で一度に処理すると、同じ文を20回以上繰り返す誤認識が起き、誤り率が52.6%になった。無音区切りで逐次処理すると3.9%。
- 逐次処理（2秒以上の無音で区切る）では、停止時に残る最後の区切りの処理が1.0〜1.6秒。
- **GPUなし（CPUのみ）**: `large-v3-turbo` は実時間の0.84倍かかり逐次処理が追いつかない。`small` は0.32倍・誤り率4.7%。

### OpenAI のSTT API（公式ドキュメントで 2026-10-02 に確認）

| モデル | 時刻 | 話者分離 | 料金 |
|---|---|---|---|
| `gpt-transcribe`（現在の推奨） | なし | なし | $0.0045/分 |
| `gpt-4o-transcribe-diarize` | 区間単位 | あり | $0.006/分 |
| `whisper-1` | 単語・区間単位 | なし | $0.006/分 |

- 精度は `gpt-transcribe` がローカルと同等〜やや上（誤り率1.7〜3.4% 対 1.8〜3.9%）。
- **`gpt-transcribe` は2系統のMTG（マイク＋PC音声）に使えない。** 時刻を返さないため1区間に2人の発話が混ざり、二重取りの除去が機能しない（回り込みの除去0/28件、自分の発話を15件誤って失った）。ローカルは28/28件を除去し、誤除去は1件。
- 話者分離（`gpt-4o-transcribe-diarize`）は、マイク1本に2人が入った音声で98%一致。対面MTGで有用。2系統録音できるオンラインMTGでは不要。
- 料金（録画1時間）: `gpt-transcribe` 1系統 $0.27、話者分離 $0.36。1リクエスト25MBまで（約13分）。

## 3. LLMによる整理

| 素材 | 実行方法 | 時間 | 漏れ | 捏造 | 要確認の誤判定 | 誤変換の補正 |
|---|---|---|---|---|---|---|
| 1人レビュー | Codex | 53〜57秒 | 0/20 | 0 | 0 | — |
| 1人レビュー | Claude Code（sonnet） | 22〜59秒 | 0/20 | 0 | 0 | — |
| 1人レビュー | Claude Code（haiku） | 97秒 | 0/20 | 0 | 0 | 2/2 |
| MTG | Codex | 85秒 | 0/22 | 0 | 0 | 7/7 |
| MTG | Claude Code（sonnet） | 108秒 | 0/22 | 0 | 0 | 5/7 |

- 色コードやpx値など「言っていない具体値の追加」も0件。
- 過結合は1件（MTGで、別々の2話題を1件にまとめた）。
- Claude Code の時間のばらつきは、思考トークンを使うかどうかで決まる（同じ入力で59秒と22秒）。時間帯で分割した並列実行は効果がなかった。
- 下書きを先に表示する設計のため、LLMが60秒を超えても操作は止まらない。

### 動作確認済みの起動方法

```
claude -p --output-format json --json-schema '<スキーマ>' --model sonnet --effort low \
  --tools '' --strict-mcp-config --permission-prompts none \
  --disable-slash-commands --setting-sources ''

codex exec --sandbox read-only --output-schema <schema>.json -o <out>.json \
  -C <セッションフォルダ> --skip-git-repo-check --ephemeral --ignore-user-config --ignore-rules -
```

- プロンプトは標準入力で渡す。
- Claude Code: `--setting-sources ''` が必須（レビュー対象リポジトリの CLAUDE.md が指示に混ざるのを防ぐ）。結果は `structured_output` から読む。
- Codex: `--ignore-user-config` が必須（ユーザー設定のモデル指定で失敗し、ユーザーのMCPサーバーが起動して入力が外部へ渡りうる）。出力スキーマは全オブジェクトに `additionalProperties: false`、全キーを `required` にする。

## 4. 検証で見つかり、設計に反映した点

| # | 問題 | 対処（03_design.md に反映済み） |
|---|---|---|
| 1 | 掛け合いが続くMTGで、下書きが巨大な1件になる（8分で5件） | まとまりに30秒の上限を設けて再分割（27件になった） |
| 2 | 環境に `ANTHROPIC_API_KEY` があると、サブスクではなく従量課金APIで実行される | 子プロセスの環境変数を掃除してから起動し、サブスクで実行されたことを確認する |
| 3 | ページ遷移の完了前に話し始めると、遷移前のURLが指摘に付く | URL・要素・直前の操作は、選ばれた画像の時刻から引く |
| 4 | ペンで囲んだだけ（発話なし）の指摘が検証で捨てられる | 引用と書き込みの両方が無い場合だけ捨てる |
| 5 | LLMに発話を書かせると遅く、捏造の余地がある | 引用は時刻だけ返させ、本文は文字起こしから引く |

## 5. 検証中に発生した費用

- Anthropic API: 上記2の問題に気付く前の2回分が、サブスクではなくAPIキーで実行された（数円程度）。以降はサブスクで実行。
- OpenAI API: 文字起こしの比較で約 $0.46。
