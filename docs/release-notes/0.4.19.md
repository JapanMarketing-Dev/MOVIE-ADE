Ferret 0.4.19

- Terminals open faster. Ferret keeps one shell ready in the background, so a new shell tab shows its prompt right away instead of waiting about a second for your shell profile to load. Agent tabs (Claude Code, Codex and others) no longer wait for the login shell's PATH before starting: Ferret uses the PATH it found last time and refreshes it in the background. Set `ADE_TERMINAL_PREWARM=0` to turn the ready shell off.
- Copying a command that Claude Code or another agent wrapped over several lines in a narrow terminal now gives one line, so pasting it no longer runs half a command. Ordinary multi-line output keeps its line breaks.
- The browser, its tabs and URL history now belong to the project. Switching projects replaces the open tabs with that project's tabs, and switching back restores them (with back/forward history while Ferret stays open). Logins and cookies are still shared between projects.
- Pages behind a Cloudflare "Verify you are human" check no longer loop forever in the built-in browser. When a site answers with a Cloudflare challenge, Ferret reloads it once with an honest Electron user agent.
- Import from your browsers: Settings > Import from browsers reads the password CSV you export from Chrome, Edge, Safari or Firefox, stores it encrypted, and adds a key button to the browser toolbar that fills the sign-in form on the matching site. History from Chrome, Edge, Brave, Arc and Safari can be imported as address-bar suggestions. Delete the exported CSV after importing; it is plain text.
- Decision model: new OpenAI preset for the Decisions API (`gpt-6-luna`, images supported), using your OpenAI API key. Ferret's relay converts requests and answers, so agents use the same steps as before.
- The file tree now shows `.env` files (dimmed when `.gitignore` ignores them). Only `.git` and `.DS_Store` stay hidden by default.
- Less background work: the agent status check no longer lists every process each second, the built-in browser stops repositioning itself while Ferret is minimized, and the Resource Manager polls less often while closed. The Resource Manager now explains that 100% is one CPU core and names the heaviest process under each terminal (for example a build an agent started).
