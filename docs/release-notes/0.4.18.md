Ferret 0.4.18

- Fixes crashes that could close Ferret on Windows. Closing Ferret (including restarting for an update) could stop the same terminal twice, which crashed the app. A terminal resized just before its command finished could also throw an error in the background. Terminals now use node-pty 1.2, which also fixes a race in the Windows console code when a shell exits while a terminal is resized, opened or closed.
- Lower memory and CPU use on every OS: a shell that exits by itself no longer leaves a background thread behind on Windows; terminal output pauses the shell when the screen falls behind instead of queueing without limit; the Resource Manager on Windows samples processes at most every 15 seconds and not while Ferret is minimized; closing many terminals at once on macOS and Linux lists processes once.
- macOS and Linux: terminals no longer leak a file descriptor per shell (macOS) or pass Ferret's open files to shells (Linux).
- Crash reports now say what kind of crash happened (out of memory, invalid memory access and so on), which module it happened in, and roughly how much memory Ferret was using. The crash dump itself is still never sent.
- Fewer false alarms in crash reports: a failed update check or Windows process sampling right after waking from sleep is reported only if it keeps failing, and a pause while Ferret is closing is no longer reported as a freeze.
