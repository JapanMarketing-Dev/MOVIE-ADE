使用 Ferret

发送给 Agent

在内置终端中运行你的编码 Agent，一键把审查交给它。Claude Code 和 Codex 是常见的例子，但下面列表中的任何 Agent 都可以使用，你自己添加的 CLI 也可以。你也可以为在其他地方运行的 Agent 复制指令。

快捷键显示为

#审查反馈

反馈 标签页中的每张卡片支持：

  • 直接编辑标题和请求
  • 切换 发送 / 不发送
  • 观看录制（跳转到对应时间）和 替换图片（选择另一帧）
  • 确认、删除

按进度筛选 按状态显示或隐藏反馈（例如 仅显示 等待你检查的反馈）；全部显示 会清除筛选。

要调整反馈的顺序，可以拖动卡片标题左侧的手柄，或选中手柄后按 ↑ / ↓。编号、feedback.md 以及发送给 Agent 的内容都会按新顺序排列。启用筛选时，只在可见的反馈之间调整顺序，隐藏的反馈保持原位。一次评审涉及多个页面或文件时，反馈只在各自的分组内移动。顶部的 反馈排序 可在 手动（拖动顺序）、录制时间 和 进度（未处理在前，已完成在后）之间切换；按进度排序时，该顺序会保存为手动顺序。

顶部有 撤销、打开文件夹、拷贝给 Agent、整理 和 发送给 Agent。没有成为反馈的语音列在 已排除的语音 下，点击 恢复为反馈 可以把它找回来。没有实际意义的话语也不会成为反馈，同样列在这里：语音识别有时会从静音中凭空生成的句子（例如“Shh.”或“谢谢观看”）、只有“嗯”之类语气词的话语，以及没有笔迹标注时单独的“好”或“OK”。

#在内置终端中运行 Agent

打开项目时，Ferret 会为 设置 → Agent → 打开项目时启动 中的每个 Agent 各启动一个终端标签页，位于项目文件夹中。默认是 Claude Code 和 Codex，启动时跳过权限确认，并开启 Claude in Chrome：

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

你也可以改为从支持列表中任选 Agent（按你选择的顺序启动），或者一个都不选。

你自己打开的 Agent 也以同样的方式启动。Ferret 还会为 Claude Code 和 Codex 把项目文件夹标记为受信任，因此它们不会询问该文件夹。若要以普通模式启动（在信任文件夹、编辑文件或运行命令之前都会询问），请关闭 设置 → Agent → 启动 Agent 时跳过权限确认。每个 Agent 的命令和参数位于 设置 → Agent（命令）和 settings.json（agents.launch）中，并按你写的原样使用。要在不使用 Claude in Chrome 的情况下启动 Claude Code，请在那里删除 --chrome。如果参数中已经选择了权限模式（例如 --permission-mode plan，或 Codex 的 --sandbox workspace-write），就不会再添加跳过确认的参数。

如果没有选择任何 Agent，则会打开普通的 shell。+ 菜单可以打开 新建终端、在新标签页中启动你的任意 Agent，或跳转到 Agent 设置…。它的搜索框还能查找标签页、已保存的 URL 和文件。

把文件拖放到终端。从访达（Windows 上为文件资源管理器，Linux 上为文件管理器）把文件、文件夹或图片拖到终端窗格上，它们的路径会以空格分隔输入到该窗格中，不会按 Enter。Agent 运行时也是如此：Claude Code 会把拖入的图片路径当作图片读取。从 文件 拖出的行（选中后可一次拖多个）也同样处理：终端位于项目文件夹中时，路径相对于项目文件夹；用 cd 切换到其他位置后则为绝对路径。包含空格或其他特殊字符的路径会按 shell 加上引号：zsh 和 bash 中为 '…'，命令提示符中为 "…"，PowerShell 中为 '…'。

标签页会显示 Agent 的状态：运行中、等待输入、完成（未读）、空闲。完成（未读） 表示在你查看其他标签页时 Agent 已完成；打开该标签页后会变为 空闲。侧边栏也会以同样的方式标记每个项目，无需切换项目就能看到：Agent 运行时显示移动的条形，有 Agent 在等你时显示问号，该项目的 Agent 都已完成而你还没打开标签页时显示对勾。

通知。打开 设置 → Agent → Agent 完成或需要我确认时通知我 后，当项目中的所有 Agent 都已完成，或某个 Agent 正在等待授权或回答时，会收到系统通知。正在查看的标签页不会显示任何通知。点击通知即可切换到该项目并打开该标签页。

拖动以拆分。拖动一个标签页，或通过手柄拖动一个窗格（标签页拆分后才会显示手柄），然后放到：

  • 窗格边缘靠外的四分之一处：向左拆分 / 向右拆分 / 向上拆分 / 向下拆分
  • 窗格中央：作为标签页打开（窗格离开所在的拆分，成为独立的标签页）
  • 整个终端区域四周的细条上：将整个区域向左拆分 等（有 2 个或更多窗格时）
  • 标签栏上：作为标签页放在此处

移动时进程会继续运行，变空的标签页会自动关闭。键盘拆分：

操作macOSWindows / Linux
新建终端⌘TCtrlT
向右拆分⌘DCtrlShiftD
向下拆分⌘⇧DAltShiftD
关闭窗格 / 标签页⌘WCtrlW

#重启后恢复终端

Ferret 退出时，会记住每个项目的终端标签页：顺序和分割、每个标签页打开时的文件夹、运行的 Agent 和账户，以及每个屏幕最多 2,000 行文字。下次启动 Ferret 时，标签页按相同顺序恢复。先显示之前的文字，接着是一行淡色的 — 接续上次（2026-10-05 14:30）—，然后在同一文件夹中启动新的 shell。

Agent 标签页会接着之前的对话启动：Claude Code 使用 --continue，Codex 使用 resume --last，继续该文件夹中最近的一次对话。如果多个标签页在同一文件夹、用同一账户运行同一个 Agent，只有第一个会继续对话，其余的重新开始，因此不会有两个标签页继续同一个对话。如果该文件夹中没有 Claude Code 的对话，或项目位于 SSH 主机上，则正常启动。

重新打开已关闭的终端。终端 → 重新打开已关闭的终端（终端获得焦点时按 ⌘⇧T / CtrlShiftT）会恢复你在此项目中最后关闭的标签页或窗格及其文字，并以同样方式继续其 Agent 的对话。最多保留最近关闭的 10 个终端，重启后也会保留。

历史记录只以不带颜色的纯文本保存在 Ferret 的数据文件夹中（terminal-restore.json，只有你本人可读），不会写入项目。从 添加账户 打开的登录标签页和一次性命令不会保留。要停止保存，请关闭 设置 → Agent → 保存终端历史并恢复，已保存的内容也会被删除。旁边的 删除已保存的历史 可随时删除。

#发送给 Agent / 拷贝给 Agent

  1. 点击 发送给 Agent。默认（自动（当前标签页或正在运行的 Agent））会发送给当前终端标签页中的 Agent，或某个正在运行的 Agent。使用按钮旁边的箭头（选择要发送给的 Agent）可以指定某个 Agent 或标签页。
  2. Ferret 会把指令写入 Agent 的输入框并提交。在终端中查看进度。

如果没有正在运行的 Agent，Ferret 会先启动一个，并在它就绪后立即发送。当 Agent 正在等待权限确认的回答时，不会发送任何内容。请先在终端中回答。

拷贝给 Agent 会把同样的指令放到剪贴板，供在其他地方（另一个终端、IDE 或应用）运行的 Agent 使用。只有切换为 发送 的反馈会被处理。视频永远不会包含在内。

#用判定模型做验收检查

开启后，你的编码 Agent 会在你查看之前逐条对照反馈把自己的工作检查一次。Ferret 本身不做任何判断：它给 Agent 提供一个判定模型（任何兼容 System One 的 API），并在 feedback.md 中告诉它如何使用。判定模型是 Agent 自己的检查，绝不是向你提问：Agent 不会问你任何问题。你只需比较 BEFORE 和 AFTER，然后按 OK 或 NG。

  1. Agent 实现这些反馈。
  2. 对每条反馈，它截取一张 AFTER 截图（与 BEFORE 静帧相同的视口和页面状态），然后向判定模型发送一个请求，包含反馈文本、“完成条件”一行以及 BEFORE/AFTER 图片。
  3. 每次你把反馈发送给 Agent 时，判定模型每条反馈最多调用一次。没有第二次评判，也没有循环，因此一个始终不说 "done" 的模型也无法让 Agent 一直忙下去。
  4. Agent 读取那一次的结果。当 P(done) 不低于阈值（默认 0.7）且选择为 done 时，该反馈通过，原样交给你。否则，如果结果显示出 Agent 能修复的明确差距，它可以再改进一次修复并重新截取 AFTER，不再评判。
  5. 无论哪种情况，Agent 都把该反馈设为 待检查，附上它的 AFTER、那一次的分数，以及最多一行说明。超出范围的反馈，或无法访问的判定 API，都不会让工作停下来：该反馈不带分数进入 待检查。
  6. 在 反馈 中，每条等你处理的反馈都会把 BEFORE、AFTER 和分数作为参考材料展示出来。OK 会把它标为完成；NG 加上评论会把它作为新的请求发回给 Agent，在那里它会再被评判一次。Agent 在终端中给出的最终“已完成 / 未完成”列表包含每条反馈的分数，以及是否又改进了一次修复。

在 设置 → 判定模型 中进行设置，并开启 在 Agent 指令中加入判定模型检查。预设只会填写字段；每个字段都可以编辑，自定义 可用于任何兼容的 API。

使用 Ollama 时，先安装它（Clef / Clef Flash 需要 0.35.1 或更高版本），然后在终端中拉取模型。Ferret 不会运行安装程序：

ollama pull clef-flash

密钥来自密钥字段（与你的其他 API 密钥一起保存）、你指定的环境变量（应用的环境、项目的 .env 或 ~/.ferret/.env），或 settings.json 中的 apiKey。额外请求头可以用 ${VAR} 从环境变量读取值。

密钥如何不进入提示词

Agent 永远看不到你的密钥。Ferret 在 127.0.0.1 上运行一个本地中继，并给每个终端提供 FERRET_DECISION_URL（中继地址，带有每个终端独立的令牌）、FERRET_DECISION_MODEL 和 FERRET_DECISION_IMAGES（在一个版本内，旧的 MOVIE_ADE_DECISION_* 名称也会一并设置）。中继添加密钥和请求头后原样转发请求，因此提示词、feedback.md 和 Agent 的对话记录中都不含机密信息。每个终端的令牌最多可调用 500 次、每分钟 30 次、2,000 万 token 和 5 美元（已知费用时），每个项目每天最多 2,000 次和 20 美元；达到上限时中继会返回 429 并说明原因，新打开的终端标签页会得到新的令牌。更改判定模型的设置后，已打开终端的令牌将失效，之后打开的终端会使用新设置。

Cloudflare 与 System One 文档有两处不同（已对照实际 API 确认）：图片必须是 data URI（data:image/jpeg;base64,…，否则返回 422 "image must be an embedded base64 data URI"），并且应答被包装为 { "result": { … }, "success": true }（错误返回为 { "success": false, "errors": [ … ] }）。Cloudflare 预设会把 图片编码 设为 data URI，Agent 通过 FERRET_DECISION_IMAGE_FORMAT 获得该值，指令也会告诉它们在存在 .result 时读取它。中继对两个方向都原样传递。若要使用 Global API Key 而不是 API 令牌，请把 认证 设为 无密钥，并添加请求头 X-Auth-Email: ${CLOUDFLARE_EMAIL} 和 X-Auth-Key: ${CLOUDFLARE_API_KEY}。

只有 Clef 和 Clef Flash 能读取图片。使用仅文本的模型时，请关闭 发送 BEFORE/AFTER 图片；这时 Agent 只根据文本判定，可靠性较低。

Ollama 与大图片

Ollama 0.35.0 把 /v1/systemone 请求限制在 64 KiB，因此带截图的请求会以 HTTP 413 失败。指令会告诉 Agent 把两张图片都缩小到宽度不超过 1024px 的 JPEG（质量约 70）。如果仍然得到 413，请把 Ollama 更新到 0.35.1 或更高版本，或改用 Cloudflare Workers AI。

#底栏中的 API 用量

判定调用都经过中继，因此 Ferret 可以统计它们。底栏中 Agent 用量表旁边的项目会显示判定模型以及今天的调用次数、token 数和费用（例如 clef-flash · 42 calls · 18.3k tok）。点击它可以查看今天、本月、按项目、按模型和按类型（判定 / 转写 / 整理）的统计，以及最近 50 次调用。

只有在 API 报告费用时（Vercel AI Gateway 会报告），或你在 设置 → 判定模型 中设置了每 100 万 token 的价格时，才会显示费用；否则显示“—”。只记录元数据（时间、项目、模型、状态、延迟、大小、图片数、token 数、费用），绝不记录图片、文本或密钥，记录保存在 ~/.ferret/usage/decision-YYYY-MM.jsonl，每月一个文件。

该设置以 agentPrompt 保存在 settings.json 中。

#在 GitHub 上为 Ferret 点星

在你第一次 发送给 Agent 之后，以及完成的审查达到 3、10 和 30 次时，Ferret 可能会请你在 GitHub 上为它点星。它最多询问 3 次，每次至少间隔 3 天，并且录制时从不询问。在 GitHub 上点星 会通过你自己的 gh 登录点星（如果没有 gh，则打开 GitHub），不再询问 会停止提示。你也可以通过 帮助 → 在 GitHub 上为 Ferret 点星 点星。

#常用服务的 CLI

设置 → 常用服务的 CLI 列出常用服务的命令行工具，安装后智能体就能操作这些服务。安装是可选的：只装需要的即可，一个都不装也能使用 Ferret。每一行显示是否已安装及版本、服务网站的链接，以及在新的终端标签页中运行适用于你的操作系统的官方安装或登录命令的按钮：

  • Git 托管：GitHub（gh）、GitLab（glab）
  • 托管与部署：Vercel、Netlify、Cloudflare（wrangler）、Firebase、Fly.io、Railway、Heroku
  • 云：AWS、Google Cloud（gcloud）、Azure（az）
  • 数据库与后端：Supabase、Neon、PlanetScale、Turso
  • 错误与监控：Sentry（sentry-cli）、Datadog（datadog-ci）
  • 支付：Stripe
  • 容器：Docker、kubectl
  • 移动：Xcode Command Line Tools（仅限 macOS）、Android Platform Tools（adb）、Expo EAS、fastlane
  • 虚拟机：UTM（仅限 macOS）、Lima、Multipass
  • AI 与模型：Ollama

如果某个工具在你的操作系统上没有一行式的官方安装命令，文档 会改为打开它的安装页面。安装完成后，列表会自动重新检查。
