Erweiterte Installation

Prüfen Sie die Signatur eines Downloads, bauen Sie Ferret aus dem Quellcode, holen Sie eine ältere Version und erfahren Sie, wie Updates funktionieren. Für die Installation von Ferret brauchen Sie nichts davon.

#Alle Downloads

Die Dateien werden über Cloudflare R2 ausgeliefert, nicht über GitHub Releases, und nur die 10 neuesten Versionen werden aufbewahrt. Die Download-Seite listet sie alle auf.

BetriebssystemDateien
macOS (Apple silicon / Intel)Ferret-<version>-mac-arm64.dmg, Ferret-<version>-mac-x64.dmg
Windows (x64 / arm64)Ferret-<version>-win-x64.exe, Ferret-<version>-win-arm64.exe (Installer)
Linux (x64)Ferret-<version>-linux-x86_64.AppImage, Ferret-<version>-linux-amd64.deb

Releases bis einschließlich 0.1.x wurden unter dem alten Namen veröffentlicht, als MOVIE-ADE-<version>-…. Die Namen Ferret-… gibt es ab 0.2.0.

#Download prüfen (signierte SHA256SUMS)

Jedes Release enthält eine Datei SHA256SUMS und deren Signatur SHA256SUMS.sig. Die Signatur wird mit dem Release-Schlüssel von Ferret erstellt, der getrennt vom Download-Server aufbewahrt wird. Ein auf dem Download-Server veränderter Installer kann daher keine gültige Signatur mitbringen. Der öffentliche Schlüssel wird nicht vom Download-Server bezogen: Holen Sie ihn aus dem Repository (build/release-signing/allowed_signers (öffnet in einem neuen Tab)) oder kopieren Sie ihn von hier:

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

Sein Fingerprint ist SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ. Dieselben Dateien sind auch an jedes Release auf GitHub angehängt. Prüfen Sie die Signatur mit ssh-keygen (enthalten in macOS, Windows 10 und neuer sowie Linux) und vergleichen Sie dann den Hash Ihres Downloads mit der signierten Liste:

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

Brechen Sie ab, wenn ssh-keygen nicht Good "ferret-release" signature ausgibt oder der Hash nicht in der Liste steht. Nach Updates suchen in Ferret führt dieselbe Prüfung mit dem in die App eingebauten Schlüssel durch und bietet keine Version an, deren Signatur nicht passt. Unter macOS können Sie außerdem die Developer-ID-Signatur und die Notarisierung mit spctl -a -vv /Applications/Ferret.app prüfen. Bei Releases bis einschließlich 0.3.0 vergleichen Sie mit den Hashes in releases/<version>/manifest.json.

#Ältere macOS-Versionen

Für Versionen bis 0.2.0 Build 2: Wenn macOS meldet, dass der Entwickler nicht überprüft werden kann, schließen Sie den Dialog, öffnen Sie Systemeinstellungen → Datenschutz & Sicherheit, klicken Sie neben der Meldung zu Ferret auf Dennoch öffnen und bestätigen Sie mit Öffnen. Wenn gemeldet wird, die App sei „beschädigt“, entfernen Sie das Quarantäne-Attribut:

xattr -dr com.apple.quarantine /Applications/Ferret.app

#Aus dem Quellcode bauen

Voraussetzungen: Node.js 20+ (CI und lokale Entwicklung verwenden 22), pnpm und git.

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

So erstellen Sie Installer (Ausgabe in dist/release/, Konfiguration in electron-builder.config.cjs). Der Linux-Build läuft nur unter Linux.

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

Die Skripte build:<os>:dev erzeugen nur eine entpackte App (--dir), was für lokale Tests schneller ist.

Unter Windows verwendet pnpm install die mitgelieferten vorkompilierten Binärdateien von node-pty, statt sie neu zu bauen (dafür wären die Visual Studio C++ Build Tools nötig). Setzen Sie ADE_FORCE_NATIVE_REBUILD=1, um einen Neubau zu erzwingen.

Wenn das Terminal meldet, dass node-pty nicht geladen werden konnte, führen Sie pnpm rebuild:native aus.

#Updates

Ferret sucht beim Start, alle 6 Stunden und beim Klick auf Nach Updates suchen (Fußzeile → Updates) nach einer neuen Version. Es lädt latest.json vom Download-Server (R2) und prüft die Signatur der SHA256SUMS dieser Version mit dem in die App eingebauten Release-Schlüssel. Eine Version mit nicht passender Signatur wird nicht angeboten.

Wird eine neue Version gefunden, lädt Ferret sie im Hintergrund herunter und zeigt den Fortschritt unter Updates. Der Download wird nur verwendet, wenn Größe und SHA-256 mit der signierten Liste übereinstimmen. Sobald sie bereit ist, zeigt Updates an, dass sie beim nächsten Schließen von Ferret installiert wird: Beenden Sie Ferret wie gewohnt, und beim nächsten Öffnen ist es die neue Version. Sie müssen kein Installationsprogramm selbst herunterladen oder ausführen, und Ferret startet nie von selbst neu – Agents arbeiten also weiter, bis Sie es schließen.

Um sie sofort zu installieren, klicken Sie unter Updates oder in der Fußleiste auf Neu starten und aktualisieren. Arbeitet ein Agent in einem Terminal oder läuft eine Aufnahme, fragt Ferret zuerst nach; die bisherige Aufnahme wird vor dem Neustart gespeichert.

InstallationsartWas heruntergeladen wirdWie es installiert wird
macOSFerret-<version>-mac-<arch>.zip, aufgeführt in UPDATE-SHA256SUMS und mit demselben Release-Schlüssel signiertwird an den Updater von macOS (Squirrel.Mac) übergeben, der auch prüft, dass die neue App dieselbe Developer-ID-Signatur hat; wird beim Schließen von Ferret installiert (oder mit Neu starten und aktualisieren)
Windowsdas Installationsprogramm (.exe)läuft nach dem Schließen von Ferret ohne Fenster; mit Neu starten und aktualisieren öffnet sich danach die neue Version
Linux (AppImage)das neue .AppImageersetzt beim Schließen von Ferret das gestartete AppImage; mit Neu starten und aktualisieren öffnet sich danach die neue Version
Linux (deb)das .debInstallationsprogramm öffnen speichert es in Ihrem Download-Ordner und öffnet es in Ihrer Softwareinstallation

Um nur zu aktualisieren, wenn Sie es möchten, schalten Sie Automatisch aktualisieren unter Updates aus (oder setzen Sie "autoUpdate": false in settings.json). Ferret lädt dann nichts von selbst herunter und installiert nichts: Klicken Sie auf Herunterladen, wenn eine neue Version angezeigt wird, und dann auf Neu starten und aktualisieren. Entwicklungs-Builds (pnpm dev) laden nicht im Hintergrund; Herunterladen speichert das geprüfte Installationsprogramm in Ihrem Download-Ordner.
