Fehlerbehebung

Häufige Probleme und ihre Lösungen. Die zitierten Meldungen sind die, die die App auf Deutsch anzeigt.

#Installation und erster Start

Linux: Unter Ubuntu 23.10 und neuer kann das AppImage beim Start mit einem Sandbox-Fehler abbrechen, weil AppArmor die User Namespaces einschränkt, die die Sandbox von Electron nutzt. Installieren Sie stattdessen das .deb.

#Aufnahme des Bildschirms oder eines Fensters schlägt fehl (macOS)

Meldung: Für die Aufnahme des ganzen Bildschirms oder eines anderen Fensters ist die macOS-Berechtigung „Bildschirmaufnahme“ nötig.

  1. Klicken Sie im Dialog Aufnahmeziel auf Systemeinstellungen öffnen.
  2. Datenschutz & Sicherheit → Bildschirm- & Systemaudioaufnahme: Aktivieren Sie Ferret.
  3. Starten Sie die App neu und klicken Sie dann auf Erneut prüfen.

Für die Aufnahme mit dem Ziel Integrierter Browser ist keine Berechtigung nötig.

Wenn Sie Ferret unter macOS aus dem Quellcode starten, startet pnpm dev eine umbenannte, ad hoc signierte Kopie von Electron, die ebenfalls Ferret heißt (scripts/prepare-dev-electron.mjs). Sie erscheint daher als eigener Ferret-Eintrag in diesen Listen. Beim ersten Start fragt macOS erneut nach dem Zugriff auf Bildschirmaufnahme und Mikrofon, danach nicht mehr. Entwicklungs-Builds verwenden einen Mock-Schlüsselbund (--use-mock-keychain), daher erscheint keine Schlüsselbund-Abfrage: Cookies und Schlüssel, die in einem Dev-Build gespeichert werden, sind mit einem festen Schlüssel verschlüsselt, nicht mit dem echten Schlüsselbund. Setzen Sie ADE_DEV_REAL_KEYCHAIN=1, um den echten Schlüsselbund zu verwenden.

#Mikrofon lässt sich nicht öffnen

Meldung: Mikrofon konnte nicht geöffnet werden. Prüfen Sie die Berechtigung in den Systemeinstellungen.

  • macOS: Systemeinstellungen → Datenschutz & Sicherheit → Mikrofon, dann Ferret aktivieren.
  • Windows: Einstellungen → Datenschutz und Sicherheit → Mikrofon, dann Desktop-Apps den Zugriff erlauben.

Ohne Mikrofon erzeugen Stiftkreise trotzdem Befunde, sie enthalten aber keine gesprochene Anfrage.

#Die Gegenseite eines Meetings wird nicht aufgenommen

Wenn Auch die Gegenseite aufnehmen eingeschaltet ist und der Ton Ihres Computers nicht aufgenommen werden kann, zeigt Ferret eine dieser Warnungen und nimmt Ihr Mikrofon, das Video und den Stift weiter auf.

  • Ferret darf kein Systemaudio aufnehmen. (macOS): Aktivieren Sie Ferret unter Systemeinstellungen → Datenschutz & Sicherheit → Bildschirm- & Systemaudioaufnahme, beenden Sie Ferret, öffnen Sie es erneut und starten Sie dann eine neue Aufnahme.
  • Für die Aufnahme der Gegenseite ist macOS 14.2 oder neuer nötig.: Aktualisieren Sie macOS. Bis dahin wird nur Ihr Mikrofon aufgenommen.
  • Windows hat den Zugriff auf das Systemaudio nicht erlaubt. oder Es wurde kein Audioausgabegerät gefunden.: Aktivieren Sie Lautsprecher oder Kopfhörer unter Einstellungen → System → Sound (Windows) oder schließen Sie sie an und starten Sie dann eine neue Aufnahme.
  • Systemaudio ist nicht verfügbar. (Linux): Installieren Sie PulseAudio oder, wenn Sie PipeWire verwenden, pipewire-pulse.
  • Die Aufnahme der Gegenseite wurde beendet: Das Audioausgabegerät wurde gewechselt oder getrennt.: Der Rest der Aufnahme läuft ohne die Gegenseite weiter. Nehmen Sie den Rest mit Weiter aufnehmen auf.

Erscheinen die Worte der Gegenseite auch als Ihre, nimmt Ihr Mikrofon Ihre Lautsprecher auf. Verwenden Sie Kopfhörer.

#Kein lokales Modell / whisper-cli nicht gefunden

Meldung: Kein Transkriptionsmodell auf dem Gerät gefunden. Das Audio wird gespeichert; nur Stiftbefunde werden verarbeitet.

Laden Sie in den Einstellungen ein Modell herunter oder wählen Sie eine vorhandene ggml-*.bin. Wenn die Einstellungen whisper.cpp (whisper-cli) wurde nicht gefunden anzeigen, installieren Sie es (Anleitung), stellen Sie sicher, dass es im PATH liegt, und öffnen Sie die Einstellungen erneut. Paketierte Apps, die aus dem Finder oder Explorer gestartet werden, sehen den PATH Ihrer Shell möglicherweise nicht. Installieren Sie es daher an einem Standardort, etwa dem von Homebrew.

Ein Modell-Download, dessen sha256-Prüfung fehlschlägt, wird verworfen. Versuchen Sie es erneut.

#Terminal: node-pty konnte nicht geladen werden

Das passiert, wenn Sie Ferret aus dem Quellcode starten und node-pty für eine andere Node- oder Electron-ABI gebaut wurde.

pnpm rebuild:native

#Agent nicht gefunden / „An Agent senden“ sendet nicht

  • Claude Code: Nicht gefunden (oder der Name eines anderen eingebauten Agents) oder command not found: … im Terminal bei einem selbst hinzugefügten Agent: Die CLI ist nicht installiert oder liegt nicht im PATH. Ferret startet eingebaute Agents nur über einen absoluten Pfad in einem PATH-Ordner außerhalb des Projekts, nie aus dem Projektordner. Prüfen Sie, ob der Befehl in Ihrem normalen Terminal funktioniert, verwenden Sie Installieren unter Einstellungen → Agents oder tragen Sie einen absoluten Pfad als Befehl dieses Agents ein.
  • Der Agent wartet auf eine Bestätigung. Antworten Sie im Terminal und senden Sie dann. Beantworten Sie zuerst die Abfrage des Agents.
  • Die Eingabe des Agents ist noch nicht bereit. Warten Sie, bis der Agent vollständig gestartet ist.
  • Der Text wurde eingegeben, aber nicht gesendet. Drücken Sie im Terminal die Eingabetaste.
  • Öffnen Sie zuerst ein Terminal.
  • Startargumente können nicht geparst werden: Unclosed quote. Korrigieren Sie die Anführungszeichen in den Argumenten des Agents.
  • Schreiben Sie … in die Startargumente, nicht in den Befehl. oder Schreiben Sie … ohne Anführungszeichen oder Backslashes in die Startargumente. Schreiben Sie diese Option als einfachen Text in die Argumente des Agents. Um Agents ohne Berechtigungsabfragen zu starten, aktivieren Sie Agents ohne Berechtigungsabfragen starten unter Einstellungen → Agents.

#Aufnahme startet nicht

  • Öffnen Sie zuerst einen Projektordner.
  • Öffnen Sie zuerst eine zu prüfende URL.
  • Die Seite wurde nicht geladen. Öffnen Sie eine URL, die angezeigt wird, und nehmen Sie dann auf. Prüfen Sie, ob der Dev-Server läuft. Keine Verbindung zum Server. bedeutet, dass an diesem Port nichts lauscht.

#OpenAI-Schlüssel oder Endpoint nicht gesetzt

Kein OpenAI-API-Schlüssel gesetzt … oder Der Transkriptions-Endpoint (Base URL / Modell) ist nicht gesetzt …: Tragen Sie ihn in den Einstellungen ein oder wechseln Sie zu Auf dem Gerät (kostenlos). Das Audio dieser Aufnahme ist bereits gespeichert.

#GitHub-Fehler

  • GitHub CLI (gh) nicht gefunden. Installieren Sie gh.
  • Nicht bei GitHub angemeldet. Einstellungen → GitHub / GitLab → Im Terminal anmelden.
  • Kein origin-Remote. oder origin ist kein GitHub-Repository. Prüfen Sie git remote -v.
  • Repository nicht gefunden oder kein Zugriff. Prüfen Sie gh auth status und GH_TOKEN.

#Fehler melden

Eröffnen Sie ein Issue unter github.com/JapanMarketing-Dev/ferret/issues (öffnet in einem neuen Tab) mit Ihrem Betriebssystem, der App-Version (Fußzeile → Updates) und den Schritten zur Reproduktion. Hängen Sie keine Inhalte aus .ferret/ an, die private Bildschirme zeigen.
