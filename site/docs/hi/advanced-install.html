संदर्भ

उन्नत इंस्टॉल

किसी डाउनलोड का हस्ताक्षर जाँचें, Ferret को source से build करें, कोई पुराना version पाएँ, और देखें कि अपडेट कैसे काम करते हैं। Ferret इंस्टॉल करने के लिए इनमें से किसी की ज़रूरत नहीं है।

#सभी डाउनलोड

फ़ाइलें GitHub Releases से नहीं, बल्कि Cloudflare R2 से दी जाती हैं, और सिर्फ़ 10 सबसे नए versions रखे जाते हैं। डाउनलोड पेज इन सभी की सूची दिखाता है।

OSफ़ाइलें
macOS (Apple silicon / Intel)Ferret-<version>-mac-arm64.dmg, Ferret-<version>-mac-x64.dmg
Windows (x64 / arm64)Ferret-<version>-win-x64.exe, Ferret-<version>-win-arm64.exe (installer)
Linux (x64)Ferret-<version>-linux-x86_64.AppImage, Ferret-<version>-linux-amd64.deb

0.1.x तक के releases पुराने नाम से, MOVIE-ADE-<version>-… के रूप में प्रकाशित हुए थे। Ferret-… नाम 0.2.0 से शुरू होते हैं।

#डाउनलोड की जाँच करें (हस्ताक्षरित SHA256SUMS)

हर release में एक SHA256SUMS फ़ाइल और उसका हस्ताक्षर SHA256SUMS.sig होता है। हस्ताक्षर Ferret की release key से बनाया जाता है, जो डाउनलोड server से अलग रखी जाती है, इसलिए डाउनलोड server पर बदला गया installer किसी मान्य हस्ताक्षर के साथ नहीं आ सकता। Public key डाउनलोड server से नहीं ली जाती: इसे repository (build/release-signing/allowed_signers (नए टैब में खुलता है)) से लें या यहाँ से कॉपी करें:

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

इसका fingerprint SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ है। यही फ़ाइलें GitHub पर हर release के साथ भी जुड़ी होती हैं। ssh-keygen (macOS, Windows 10 और बाद के versions, और Linux में शामिल) से हस्ताक्षर जाँचें, फिर अपने डाउनलोड के hash की तुलना हस्ताक्षरित सूची से करें:

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

अगर ssh-keygen Good "ferret-release" signature न दिखाए या hash सूची में न हो, तो आगे न बढ़ें। Ferret का अपडेट जाँचें ऐप में बनी key से यही जाँच करता है और ऐसा कोई version नहीं सुझाता जिसका हस्ताक्षर मेल न खाए। macOS पर आप spctl -a -vv /Applications/Ferret.app से Developer ID हस्ताक्षर और notarization भी जाँच सकते हैं। 0.3.0 तक के releases के लिए releases/<version>/manifest.json में दिए hashes से तुलना करें।

#पुराने macOS versions

0.2.0 build 2 तक के versions के लिए: अगर macOS कहे कि developer की पुष्टि नहीं की जा सकती, तो dialog बंद करें, System Settings → Privacy & Security खोलें, Ferret वाले संदेश के बगल में Open Anyway पर क्लिक करें, और Open से पुष्टि करें। अगर यह कहे कि ऐप "is damaged", तो quarantine attribute हटा दें:

xattr -dr com.apple.quarantine /Applications/Ferret.app

#Source से build करें

इसके लिए Node.js 20+ (CI और local development में 22 इस्तेमाल होता है), pnpm और git चाहिए।

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

Installers पैकेज करने के लिए (output dist/release/ में, config electron-builder.config.cjs में)। Linux build सिर्फ़ Linux पर चलता है।

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

build:<os>:dev scripts सिर्फ़ एक unpacked ऐप (--dir) बनाते हैं, जो local testing के लिए ज़्यादा तेज़ है।

Windows पर pnpm install दोबारा build करने के बजाय node-pty के साथ आने वाली prebuilt binaries इस्तेमाल करता है (दोबारा build करने के लिए Visual Studio C++ build tools चाहिए होते)। ज़बरदस्ती rebuild करने के लिए ADE_FORCE_NATIVE_REBUILD=1 सेट करें।

अगर टर्मिनल बताए कि node-pty load नहीं हो सका, तो pnpm rebuild:native चलाएँ।

#अपडेट

Ferret शुरू होने पर, हर 6 घंटे में, और अपडेट जाँचें पर क्लिक करने पर (footer → अपडेट) नया version जाँचता है। यह डाउनलोड server (R2) से latest.json लेता है और ऐप में बनी release key से उस version की SHA256SUMS का हस्ताक्षर जाँचता है। जिस version का हस्ताक्षर मेल नहीं खाता, वह नहीं दिखाया जाता।

नया version मिलने पर Ferret उसे background में डाउनलोड करता है और प्रगति अपडेट में दिखाता है। डाउनलोड तभी इस्तेमाल होता है जब उसका आकार और SHA-256 हस्ताक्षरित सूची से मेल खाएँ। तैयार होने पर अपडेट में दिखता है कि यह अगली बार Ferret बंद करने पर इंस्टॉल होगा: Ferret को हमेशा की तरह बंद करें, और अगली बार खोलने पर नया version मिलेगा। आपको खुद installer डाउनलोड करने या चलाने की ज़रूरत नहीं है, और Ferret अपने-आप फिर से शुरू नहीं होता, इसलिए जब तक आप उसे बंद नहीं करते, Agent काम करते रहते हैं।

तुरंत इंस्टॉल करने के लिए अपडेट या footer में फिर से शुरू करके अपडेट करें पर क्लिक करें। अगर किसी टर्मिनल में Agent काम कर रहा हो या रिकॉर्डिंग चल रही हो, तो Ferret पहले पूछता है; अब तक की रिकॉर्डिंग फिर से शुरू होने से पहले सहेज ली जाती है।

इंस्टॉल का प्रकारक्या डाउनलोड होता हैकैसे इंस्टॉल होता है
macOSFerret-<version>-mac-<arch>.zip, जो UPDATE-SHA256SUMS में दर्ज है और उसी release key से हस्ताक्षरित हैmacOS के updater (Squirrel.Mac) को दिया जाता है, जो यह भी जाँचता है कि नए ऐप पर वही Developer ID हस्ताक्षर है; Ferret बंद करने पर (या फिर से शुरू करके अपडेट करें से) इंस्टॉल होता है
Windowsinstaller (.exe)Ferret बंद करने के बाद बिना किसी window के चलता है; फिर से शुरू करके अपडेट करें से चलाने पर उसके बाद नया version खुलता है
Linux (AppImage)नया .AppImageFerret बंद करने पर आपके शुरू किए गए AppImage को बदल देता है; फिर से शुरू करके अपडेट करें से चलाने पर उसके बाद नया version खुलता है
Linux (deb).debइंस्टॉलर खोलें उसे आपके Downloads फ़ोल्डर में सहेजकर आपके software installer में खोलता है

सिर्फ़ अपनी मर्ज़ी से अपडेट करने के लिए अपडेट में अपने-आप अपडेट करें बंद करें (या settings.json में "autoUpdate": false सेट करें)। तब Ferret अपने-आप कुछ भी डाउनलोड या इंस्टॉल नहीं करता: नया version दिखने पर डाउनलोड करें पर क्लिक करें, फिर फिर से शुरू करके अपडेट करें पर। Development builds (pnpm dev) background में डाउनलोड नहीं करते; डाउनलोड करें जाँचा हुआ installer आपके Downloads फ़ोल्डर में सहेजता है।
