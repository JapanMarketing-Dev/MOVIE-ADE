Ferret का इस्तेमाल

Editor और प्रीव्यू

प्रोजेक्ट की फ़ाइलें खोलें और संपादित करें, और Markdown व Mermaid का प्रीव्यू देखें। बिल्ट-इन ब्राउज़र में खोला गया प्रीव्यू किसी भी वेब पेज की तरह रिकॉर्ड और review किया जा सकता है।

शॉर्टकट दिखाएँ

#फ़ाइलें खोलें और संपादित करें

  • फ़ाइलें (फ़ाइल ट्री): ⌘⇧E / CtrlShiftE, जिसमें फ़ाइल नाम से फ़िल्टर करें, रिफ़्रेश करें और सब छोटा करें हैं।
  • फ़ाइल पर जाएँ…: ⌘P / CtrlP।
  • किसी फ़ाइल को खोलने के लिए उसे Finder (Windows पर File Explorer, Linux पर आपका file manager) से टैब बार या editor पर drag करें। प्रोजेक्ट की फ़ाइलें editor या viewer में खुलती हैं। प्रोजेक्ट के बाहर की किसी फ़ाइल को अंदर लाने के लिए उसे फ़ाइलें पर drop करें, जो उसे प्रोजेक्ट में कॉपी कर देता है। यहाँ drop किया गया फ़ोल्डर प्रोजेक्ट के रूप में खुलता है। फ़ाइलें से drag की गई फ़ाइलें भी इसी तरह खुलती हैं। किसी खुली Markdown फ़ाइल पर drop की गई इमेज और वीडियो इसके बजाय उसमें embed हो जाते हैं (देखें Markdown में इमेज और वीडियो embed करें)।
  • ⌘S / CtrlS से सेव करें। बदली हुई फ़ाइल बंद करने पर <name> में बदलाव सेव करें? पूछा जाता है, जिसमें सेव करें, सेव न करें और रद्द करें होते हैं।
  • अगर बिना सेव किए बदलावों के दौरान फ़ाइल डिस्क पर बदल जाए, तो डिस्क से रीलोड करें या मेरे बदलाव रखें चुनें।

Editor Monaco है। जो फ़ाइलें टेक्स्ट नहीं हैं, वे इसकी जगह एक viewer में खुलती हैं: इमेज (zoom in और out; SVG को code के रूप में भी दिखाया जा सकता है), seek bar के साथ वीडियो और ऑडियो, PDF, और किसी भी दूसरी binary फ़ाइल के लिए उसका size और शुरुआती bytes का hex view। Viewers सिर्फ़ पढ़ने के लिए हैं, और प्रोजेक्ट फ़ोल्डर के बाहर की फ़ाइलें या फ़ोल्डर से बाहर ले जाने वाले symbolic link से पहुँची फ़ाइलें नहीं दिखाई जातीं।

#फ़ाइल ट्री में फ़ाइलों पर काम करें

VS Code की तरह सीधे फ़ाइलें में फ़ाइलों पर काम करें। किसी आइटम पर right-click करें, या प्रोजेक्ट के सबसे ऊपर के स्तर पर काम करने के लिए ट्री के नीचे की खाली जगह पर। नाम ट्री में ही टाइप किए जाते हैं।

  • नई फ़ाइल / नया फ़ोल्डर: ट्री के ऊपर के बटन, या right-click करें। नया आइटम चुने गए फ़ोल्डर में, चुनी गई फ़ाइल के बगल में, या प्रोजेक्ट के सबसे ऊपर बनता है। रास्ते के फ़ोल्डर भी बनाने के लिए slashes वाला नाम टाइप करें, जैसे src/routes/index.ts। नई फ़ाइल editor में खुलती है। खाली फ़ोल्डर में फ़ाइलें यह फ़ोल्डर खाली है दिखाता है, साथ में नई फ़ाइल और नया फ़ोल्डर बटन।
  • काटें, कॉपी करें और चिपकाएँ: ⌘X / CtrlX, ⌘C / CtrlC, ⌘V / CtrlV, या right-click करें। फ़ोल्डर अपने अंदर की हर चीज़ के साथ कॉपी होते हैं। डुप्लिकेट बनाएँ मूल के बगल में एक कॉपी बनाता है। अगर नाम पहले से लिया गया है, तो कॉपी का नाम name copy, फिर name copy 2 रखा जाता है।
  • आइटम्स को हिलाने के लिए उन्हें किसी फ़ोल्डर पर (या प्रोजेक्ट के सबसे ऊपर के स्तर के लिए खाली जगह पर) drag करें। हिलाने की जगह कॉपी करने के लिए drop करते समय ⌥ / Ctrl दबाए रखें। Finder (Windows पर File Explorer) से drag करके लाई गई फ़ाइलें और फ़ोल्डर प्रोजेक्ट में कॉपी होते हैं; मूल अपनी जगह पर रहते हैं।
  • नाम बदलें: F2 / Enter / F2, या right-click करें।
  • हटाएँ: ⌘⌫ / Delete / Delete, या right-click करें। Ferret पहले पूछता है, फिर आइटम को ट्रैश (Windows पर रीसायकल बिन) में ले जाता है, ताकि आप उसे वापस ला सकें। हटाई गई फ़ाइलों के टैब बंद हो जाते हैं; अगर किसी में बिना सेव किए बदलाव थे, तो पुष्टि वाला संदेश यह बताता है।
  • पूर्ववत करें: ⌘Z / CtrlZ आख़िरी नया आइटम, नाम बदलना, हिलाना, चिपकाना या डुप्लिकेट बनाना उलट देता है। हटाए गए आइटम ट्रैश से वापस लाए जाते हैं।
  • पाथ कॉपी करें (⌥⌘C / ShiftAltC) और रिलेटिव पाथ कॉपी करें (⌥⇧⌘C / CtrlShiftAltC) path को clipboard पर रखते हैं।
  • Finder में दिखाएँ (Windows पर फ़ाइल एक्सप्लोरर में दिखाएँ, Linux पर मूल फ़ोल्डर खोलें): ⌥⌘R / ShiftAltR। टर्मिनल में खोलें उस फ़ोल्डर में (फ़ाइल के लिए, उसके फ़ोल्डर में) एक नया टर्मिनल टैब खोलता है।
  • किसी फ़ाइल के लिए, खोलें उसे editor में खोलता है और डिफ़ॉल्ट ऐप में खोलें उसे उस ऐप में खोलता है जिसे आपका OS उस प्रकार के लिए इस्तेमाल करता है।
  • कई आइटम एक साथ काटने, कॉपी करने, हिलाने या हटाने के लिए उन्हें ⌘ / Ctrl-click या ⇧ / Shift-click से चुनें।
  • Esc टाइप किया जा रहा नाम रद्द करता है।

खुले टैब नाम बदली गई या हिलाई गई फ़ाइल के साथ चलते हैं और बिना सेव किए बदलाव बनाए रखते हैं। Ferret उसी नाम वाली मौजूदा फ़ाइल या फ़ोल्डर को overwrite नहीं करता, और हर चीज़ को प्रोजेक्ट फ़ोल्डर के अंदर रखता है: यह .., absolute paths, बाहर की ओर इशारा करने वाले symbolic links, .git के अंदर की हर चीज़, किसी फ़ोल्डर को उसी के अंदर हिलाना, और ऐसे नाम अस्वीकार करता है जिन्हें कोई OS इस्तेमाल नहीं कर सकता: / \ < > : " | ? *, control characters, आख़िर में space या dot, और Windows के आरक्षित नाम जैसे CON या NUL। एक कॉपी या drop में 10,000 आइटम और 1 GB तक हो सकते हैं।

#Markdown और Mermaid प्रीव्यू

प्रीव्यू .md, .markdown, .mdx, .mmd और .mermaid के लिए काम करता है। Mermaid ऐप के साथ ही आता है, इसलिए diagrams offline render होते हैं।

Markdown फ़ाइल में editor के ऊपर दो views होते हैं: सोर्स और प्रीव्यू। प्रीव्यू हमेशा संपादित किया जा सकता है, इसलिए आप उसमें सीधे टाइप कर सकते हैं; text पर वापस जाने के लिए सोर्स पर क्लिक करें। दोनों एक ही content दिखाते हैं, और सेव करना, बिना सेव किए बदलाव का निशान और बंद करते समय की पुष्टि एक ही तरह काम करते हैं।

  • Headings, paragraphs, lists, checkboxes, tables, links और bold, italic या inline code में सीधे टाइप करें। किसी लाइन की शुरुआत में #, -, 1. या > और एक space टाइप करने से heading, list या quote शुरू होता है।
  • पंक्ति की शुरुआत में (या स्पेस के बाद) / टाइप करें और सूची से ब्लॉक चुनें: शीर्षक, बुलेट, क्रमांकित या चेकलिस्ट सूचियाँ, तालिका, कोड ब्लॉक, उद्धरण या विभाजक। हर विकल्प बताता है कि वह क्या बनाता है और Markdown में उसे कैसे लिखते हैं। छाँटने के लिए टाइप करते रहें, चुनने के लिए ↑ ↓ और Enter इस्तेमाल करें, या / को टेक्स्ट के रूप में रखने के लिए Esc दबाएँ। तालिका हेडर पंक्ति के साथ 3 × 3 से शुरू होती है; Tab अगले सेल पर ले जाता है और अंत में एक पंक्ति जोड़ता है। तालिका के अंदर / टाइप करने पर पंक्तियाँ और कॉलम जोड़े या हटाए जा सकते हैं, या पूरी तालिका हटाई जा सकती है।
  • कोड ब्लॉक source के रूप में संपादित होते हैं, कोने में भाषा दिखती है। Mermaid कोड ब्लॉक (mermaid या mmd) डिफ़ॉल्ट रूप से डायग्राम दिखाता है। source संपादित करने के लिए ऊपर दाईं ओर कोड पर क्लिक करें या डायग्राम पर डबल-क्लिक करें; कर्सर ब्लॉक से बाहर जाते ही डायग्राम फिर दिखता है। source में गलती हो तो संदेश और कोड ठीक करें दिखता है। डायग्राम एक sandbox फ़्रेम के अंदर बनते हैं, और सेव किया गया Markdown वैसा ही रहता है जैसा लिखा गया।
  • Front matter (सबसे ऊपर का --- block) document के ऊपर text के रूप में दिखता है और वहीं संपादित किया जा सकता है।
  • जिन हिस्सों को आप नहीं बदलते, वे ठीक वैसे ही सेव होते हैं जैसे लिखे गए थे, जिसमें heading style, list markers, खाली लाइनें, table alignment और line endings शामिल हैं। आप जिस block को संपादित करते हैं, उसका style जहाँ तक हो सके बना रहता है; नहीं तो वह block मानक Markdown रूप में लिखा जाता है, lists के लिए - और headings के लिए # के साथ।
  • प्रोजेक्ट की इमेज और वीडियो दिखाए जाते हैं। दूसरी sites की इमेज load नहीं होतीं; उनकी जगह उनका host name दिखता है। फ़ाइल में मौजूद बाकी HTML text के रूप में दिखता है।

.mdx फ़ाइलों (जो सिर्फ़ source के रूप में संपादित होती हैं), .mmd और .mermaid फ़ाइलों में इसके बजाय सिर्फ़ पढ़ने वाला प्रीव्यू होता है:

  • प्रीव्यू बगल में खोलें: editor के बगल में
  • प्रीव्यू खोलें: बिल्ट-इन ब्राउज़र (ade-preview://) में, ताकि आप उसे रिकॉर्ड और review कर सकें

#Markdown में इमेज और वीडियो embed करें

इमेज (PNG, JPEG, GIF, WebP, SVG, AVIF) या वीडियो (MP4, WebM, MOV) को किसी Markdown फ़ाइल पर, सोर्स या प्रीव्यू में, drag करें, ताकि वे वहीं embed हो जाएँ जहाँ आप उन्हें drop करते हैं।

  • जो फ़ाइलें पहले से प्रोजेक्ट में हैं, जिनमें फ़ाइलें से drag की गई फ़ाइलें भी शामिल हैं, वे Markdown फ़ाइल के सापेक्ष path से link होती हैं। कुछ भी कॉपी नहीं होता।
  • प्रोजेक्ट के बाहर की फ़ाइलें (Finder, desktop, Windows पर File Explorer) पहले Markdown फ़ाइल के बगल के एक फ़ोल्डर में कॉपी होती हैं: assets, images, media या img, अगर इनमें से कोई पहले से मौजूद हो, नहीं तो एक नया assets फ़ोल्डर। नाम में spaces - बन जाते हैं, और अगर नाम पहले से लिया हुआ हो तो कॉपी का नाम name-2 होता है। मूल फ़ाइलें जहाँ थीं वहीं रहती हैं।
  • इमेज ![name](assets/name.png) के रूप में और वीडियो <video src="assets/name.mp4" controls></video> के रूप में लिखे जाते हैं, जिसे GitHub भी चलाता है। दोनों प्रीव्यू में दिखते हैं।
  • एक इमेज 50 MB तक और एक वीडियो 500 MB तक हो सकता है, और एक drop में ज़्यादा से ज़्यादा 50 फ़ाइलें और 1 GB कॉपी होते हैं। उनके साथ drop की गई दूसरी फ़ाइलें हमेशा की तरह editor में खुलती हैं।

#रिकॉर्ड करके दस्तावेज़ों का review करें

  1. Review targets पैनल में, फ़ाइलें से Markdown फ़ाइल खोलें। यह बिल्ट-इन ब्राउज़र में प्रीव्यू के रूप में खुलती है।
  2. हमेशा की तरह रिकॉर्ड करें। spec या design doc पर बोलते जाएँ और जो गलत है उसे घेरें।
  3. रोकें। Findings में URL की जगह फ़ाइल का प्रोजेक्ट-सापेक्ष path होता है।
  4. दस्तावेज़ ठीक करवाने के लिए Agent को भेजें।
