Utiliser Ferret

Envoyer aux agents

Lancez votre agent de code dans le terminal intégré et confiez-lui une relecture en un clic. Claude Code et Codex sont les exemples habituels, mais tout agent de la liste ci-dessous fonctionne, de même qu'une CLI que vous ajoutez vous-même. Vous pouvez aussi copier l'instruction pour un agent qui tourne ailleurs, ou publier la relecture sur GitHub.

Raccourcis pour

#Relire les remarques

Chaque carte de l'onglet Remarques permet :

  • de modifier directement le titre et la demande
  • de basculer entre Envoyer et Ne pas envoyer
  • Voir l'enregistrement (se place à ce moment-là) et Remplacer l'image (choisir une autre image de la vidéo)
  • Valider / Marquer « À vérifier », Fusionner avec la suivante, Supprimer

Filtrer par avancement affiche ou masque les remarques selon leur statut (par exemple Seulement celles qui attendent votre relecture) ; Tout afficher retire le filtre.

L'en-tête contient Annuler, Ouvrir le dossier, Copier pour l'agent, Envoyer vers GitHub / GitLab, Organiser et Envoyer à l'agent. Les paroles qui ne sont pas devenues des remarques sont listées sous Paroles exclues, où Restaurer en remarque les récupère.

#Lancer des agents dans le terminal intégré

À l'ouverture d'un projet, Ferret ouvre un onglet de terminal par agent choisi dans Réglages → Agents → Démarrer à l'ouverture d'un projet, dans le dossier du projet. Par défaut, ce sont Claude Code et Codex, démarrés sans demandes d'autorisation et avec Claude in Chrome activé :

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

Vous pouvez choisir à la place n'importe quels agents de la liste des agents pris en charge (ils démarrent dans l'ordre où vous les choisissez), ou aucun.

Les agents que vous ouvrez vous-même démarrent de la même façon. Ferret marque aussi le dossier du projet comme fiable pour Claude Code et Codex, qui ne posent donc pas de question sur le dossier. Pour les démarrer dans leur mode normal, où ils demandent avant de faire confiance à un dossier, de modifier des fichiers ou d'exécuter des commandes, désactivez Réglages → Agents → Démarrer les agents sans demandes d'autorisation. La commande et les arguments de chaque agent se trouvent sous Réglages → Agents (Commande) et dans settings.json (agents.launch), et sont utilisés tels que vous les écrivez. Retirez-y --chrome pour démarrer Claude Code sans Claude in Chrome. Si les arguments choisissent déjà un mode d'autorisation (par exemple --permission-mode plan, ou --sandbox workspace-write pour Codex), l'option d'ignorance n'est pas ajoutée.

Si aucun agent n'est sélectionné, un shell simple s'ouvre. Le menu + ouvre un Nouveau terminal, lance l'un de vos agents dans un nouvel onglet ou mène à Réglages des agents…. Son champ de recherche trouve aussi les onglets, les URL enregistrées et les fichiers.

Déposer des fichiers dans le terminal. Faites glisser des fichiers, des dossiers ou des images depuis le Finder (l'Explorateur de fichiers sous Windows, votre gestionnaire de fichiers sous Linux) sur un panneau de terminal : leurs chemins y sont saisis, séparés par des espaces, sans appuyer sur Entrée. Cela fonctionne de la même façon pendant qu'un agent tourne : Claude Code lit le chemin d'une image déposée comme une image. Les lignes glissées depuis Fichiers (plusieurs à la fois si vous les sélectionnez) fonctionnent de la même façon : le chemin est relatif au dossier du projet tant que le terminal s'y trouve, et absolu après un cd ailleurs. Les chemins contenant des espaces ou d'autres caractères spéciaux sont mis entre guillemets pour le shell : '…' dans zsh et bash, "…" dans l'invite de commandes et '…' dans PowerShell.

Les onglets affichent l'état de l'agent : En cours, En attente d'une saisie, Terminé (non lu), Inactif. Terminé (non lu) signifie que l'agent a terminé pendant que vous regardiez un autre onglet ; l'état passe à Inactif dès que vous ouvrez cet onglet. La barre latérale signale chaque projet de la même façon, pour que vous le voyiez sans changer de projet : des barres animées pendant qu'un agent tourne, un point d'interrogation quand l'un d'eux vous attend, et une coche quand les agents du projet ont terminé et que vous n'avez pas encore ouvert l'onglet.

Notifications. Activez Réglages → Agents → Me prévenir quand les agents terminent ou ont besoin de moi pour recevoir une notification système quand tous les agents d'un projet ont terminé, ou quand un agent attend une autorisation ou une réponse. Rien ne s'affiche pour l'onglet que vous regardez. Cliquez sur la notification pour passer à ce projet et ouvrir l'onglet.

Faire glisser pour diviser. Faites glisser un onglet, ou un panneau par sa poignée (affichée dès qu'un onglet est divisé), et déposez-le :

  • sur le quart extérieur d'un bord de panneau : Diviser à gauche / Diviser à droite / Diviser en haut / Diviser en bas
  • au centre d'un panneau : Ouvrir dans un onglet (un panneau quitte sa division et devient son propre onglet)
  • sur la fine bande qui entoure toute la zone du terminal : Diviser toute la zone à gauche, etc. (lorsqu'il y a au moins 2 panneaux)
  • sur la barre d'onglets : Placer ici comme onglet

Les processus continuent de tourner pendant le déplacement, et un onglet laissé vide se ferme. Divisions au clavier :

ActionmacOSWindows / Linux
Nouveau terminal⌘TCtrlT
Diviser à droite⌘DCtrlShiftD
Diviser en bas⌘⇧DAltShiftD
Fermer le panneau / l'onglet⌘WCtrlW

#Envoyer à l'agent / Copier pour l'agent

  1. Cliquez sur Envoyer à l'agent. Par défaut (Auto (onglet actuel ou agent en cours)), l'envoi part vers l'agent de l'onglet de terminal actuel, ou vers un agent en cours d'exécution. Utilisez la flèche à côté du bouton (Choisir l'agent destinataire) pour choisir un agent ou un onglet précis.
  2. Ferret écrit l'instruction dans la saisie de l'agent et la valide. Suivez l'avancement dans le terminal.

Si aucun agent ne tourne, Ferret en démarre un d'abord et envoie dès qu'il est prêt. Rien n'est envoyé tant que l'agent attend une réponse à une demande d'autorisation : répondez d'abord dans le terminal.

Copier pour l'agent place la même instruction dans le presse-papiers pour un agent qui tourne ailleurs (un autre terminal, un IDE ou une application). Seules les remarques réglées sur Envoyer sont concernées. La vidéo n'est jamais incluse.

#Vérification d'acceptation avec un modèle de décision

Activez cette option et votre agent de code vérifie son propre travail par rapport à chaque remarque avant d'annoncer Terminé. Ferret ne juge rien lui-même : il fournit à l'agent un modèle de décision (n'importe quelle API compatible System One) et lui demande, dans feedback.md, de boucler jusqu'à ce que chaque remarque passe.

  1. L'agent implémente les remarques.
  2. Pour chaque remarque, il prend une capture d'écran APRÈS (même viewport et même état de la page que l'image AVANT) et envoie au modèle de décision une requête avec le texte de la remarque, sa ligne « Terminé quand » et les images AVANT/APRÈS.
  3. Une remarque passe lorsque P(done) atteint au moins le seuil (0,7 par défaut) et que le choix est done. L'agent corrige le reste et rejuge toutes les remarques à chaque tour, et ne s'arrête que lorsque toutes passent dans le même tour, ou pour une raison légitime qu'il doit indiquer : l'API est injoignable, une remarque est hors périmètre, ou une remarque reste bloquée avec des scores inchangés.
  4. La liste finale Terminé / Non terminé indique les scores de chaque remarque et le nombre de tours.

Configurez-le dans Réglages → Modèle de décision et activez Ajouter la vérification par modèle de décision aux instructions de l'agent. Les préréglages ne font que remplir les champs ; chaque champ reste modifiable, et Personnalisé fonctionne avec n'importe quelle API compatible.

Pour Ollama, installez-le (0.35.1 ou ultérieur pour Clef / Clef Flash) et téléchargez le modèle dans un terminal. Ferret n'exécute pas d'installeur :

ollama pull clef-flash

Les clés proviennent du champ de clé (enregistré avec vos autres clés d'API), d'une variable d'environnement que vous nommez (l'environnement de l'application, le .env du projet ou ~/.ferret/.env), ou de apiKey dans settings.json. Les en-têtes supplémentaires peuvent lire des valeurs dans des variables d'environnement avec ${VAR}.

Comment la clé reste hors des prompts

Les agents ne voient jamais votre clé. Ferret exécute un relais local sur 127.0.0.1 et fournit à chaque terminal FERRET_DECISION_URL (le relais, avec un jeton propre à chaque terminal), FERRET_DECISION_MODEL et FERRET_DECISION_IMAGES (pendant une version, les anciens noms MOVIE_ADE_DECISION_* sont aussi définis). Le relais ajoute la clé et les en-têtes et transmet la requête sans la modifier : les prompts, feedback.md et les transcriptions des agents ne contiennent donc aucun secret. Les terminaux ouverts après une modification des réglages en tiennent compte.

Cloudflare diffère de la documentation System One sur deux points (vérifiés sur l'API réelle) : les images doivent être des data URI (data:image/jpeg;base64,…, sinon erreur 422 « image must be an embedded base64 data URI »), et la réponse est enveloppée sous la forme { "result": { … }, "success": true } (les erreurs reviennent sous la forme { "success": false, "errors": [ … ] }). Le préréglage Cloudflare règle Encodage des images sur data URI, les agents le reçoivent via FERRET_DECISION_IMAGE_FORMAT, et les instructions leur demandent de lire .result lorsqu'il est présent. Le relais transmet les deux sens sans modification. Pour utiliser une Global API Key au lieu d'un jeton d'API, réglez Authentification sur Sans clé et ajoutez les en-têtes X-Auth-Email: ${CLOUDFLARE_EMAIL} et X-Auth-Key: ${CLOUDFLARE_API_KEY}.

Seuls Clef et Clef Flash lisent les images. Avec un modèle texte uniquement, désactivez Envoyer les images AVANT/APRÈS ; l'agent juge alors à partir du texte seul, ce qui est moins fiable.

Ollama et les images volumineuses

Ollama 0.35.0 limite les requêtes /v1/systemone à 64 Kio : les requêtes avec des captures d'écran échouent donc avec une erreur HTTP 413. Les instructions demandent à l'agent de réduire les deux images à 1024 px de large au maximum, en JPEG (qualité d'environ 70). S'il obtient encore une erreur 413, mettez Ollama à jour en 0.35.1 ou ultérieur, ou passez à Cloudflare Workers AI.

#Utilisation de l'API dans le pied de page

Les appels au modèle de décision passent par le relais, ce qui permet à Ferret de les compter. L'élément du pied de page situé à côté de l'indicateur d'utilisation de l'agent affiche le modèle de décision ainsi que les appels, les jetons et le coût du jour (par exemple clef-flash · 42 calls · 18.3k tok). Cliquez dessus pour voir le jour, le mois, le détail par projet, par modèle et par type (décision / transcription / organisation), ainsi que les 50 derniers appels.

Le coût n'apparaît que si l'API le communique (c'est le cas de Vercel AI Gateway) ou si vous définissez des prix par million de jetons dans Réglages → Modèle de décision ; sinon « — » s'affiche. Seules les métadonnées sont journalisées (heure, projet, modèle, statut, latence, taille, nombre d'images, jetons, coût), jamais les images, le texte ni les clés, dans ~/.ferret/usage/decision-YYYY-MM.jsonl, un fichier par mois.

#Personnaliser l'instruction

Modifiez Réglages → Agents → Instructions pour l'agent. Deux variables sont remplacées :

VariableRemplacée par
{{path}}Chemin absolu de feedback.md
{{relpath}}Chemin relatif au projet : .ferret/reviews/<id>/feedback.md

Laissez le champ vide pour utiliser l'instruction par défaut. La longueur maximale est de 2000 caractères, et Réinitialiser les instructions rétablit l'instruction par défaut. Exemple :

Read {{relpath}} and the PNGs next to it. Fix only findings marked to send, one commit per finding, then run the tests.

Le réglage est stocké sous agentPrompt dans settings.json.

#Envoyer vers GitHub ou GitLab (Issue / commentaire de PR ou de MR)

Envoyer sur GitHub publie la relecture sous forme de nouvelle Issue ou de commentaire sur l'une de vos pull requests ouvertes. L'authentification est déléguée à la GitHub CLI (s'ouvre dans un nouvel onglet). Ferret ne lit ni ne stocke jamais de jeton.

  1. Installez gh : brew install gh (macOS), winget install --id GitHub.cli (Windows), ou consultez cli/cli (s'ouvre dans un nouvel onglet).
  2. Réglages → GitHub / GitLab → Se connecter dans le terminal exécute gh auth login --web -h github.com dans le terminal intégré.
  3. Cliquez sur Envoyer sur GitHub, choisissez Créer une nouvelle Issue ou une PR, et relisez le Titre et le Corps (modifiables).
  4. Cochez la case de confirmation, puis Créer l'Issue ou Publier le commentaire.

Détails :

  • Le dépôt est déterminé par git remote get-url origin.
  • Ferret exécute gh issue create --repo … --title … --body-file - ou gh pr comment <n> --repo … --body-file -.
  • Le corps est le feedback.md sans les lignes d'image (les images ne sont pas envoyées), jusqu'à 60 000 caractères.
  • Les PR proposées sont vos propres PR ouvertes (jusqu'à 30).

Si GH_TOKEN ou GITHUB_TOKEN est défini, gh l'utilise en priorité, et le panneau des réglages vous en avertit.

GitLab. Lorsque origin est un projet GitLab (gitlab.com ou une instance GitLab autogérée), le même bouton envoie vers GitLab via la GitLab CLI (s'ouvre dans un nouvel onglet) (glab) : une nouvelle Issue, ou un commentaire sur l'une de vos merge requests ouvertes. Connectez-vous depuis Réglages → GitHub / GitLab, qui exécute glab auth login (avec --hostname pour une instance GitLab autogérée) dans le terminal intégré. Ferret ne lit ni ne stocke jamais le jeton, et vous avertit lorsque GITLAB_TOKEN est défini.

Demande d'étoile. Après votre premier Envoyer à l'agent, puis lorsque vous atteignez 3, 10 et 30 relectures terminées, Ferret peut vous proposer de lui mettre une étoile sur GitHub. Il le demande au maximum 3 fois, à au moins 3 jours d'intervalle, et jamais pendant un enregistrement. Mettre une étoile sur GitHub ajoute l'étoile via votre propre connexion gh (ou ouvre GitHub si gh n'est pas disponible), et Ne plus demander arrête ces demandes. Vous pouvez aussi mettre une étoile depuis Aide → Mettre une étoile à Ferret sur GitHub.

#Installer les outils CLI et s'y connecter

Réglages → Outils CLI liste les outils en ligne de commande dont vos agents ont souvent besoin, indique ceux qui sont installés et leur version, et exécute dans un nouvel onglet de terminal la commande officielle d'installation ou de connexion pour votre OS :

  • Hébergement Git : gh, glab
  • IA et modèles : Ollama, Cloudflare wrangler
  • Déploiement : Vercel, Netlify, Fly.io, Railway, Heroku
  • Cloud et services : Supabase, Firebase, Stripe, Google Cloud (gcloud), AWS, Azure, Docker

Lorsqu'un outil n'a pas d'installeur officiel en une ligne pour votre OS, Documentation ouvre sa page d'installation à la place. La liste refait sa vérification d'elle-même une fois l'installation terminée.
