Éditeur et aperçu

Ouvrez et modifiez les fichiers du projet, et prévisualisez le Markdown et Mermaid. Un aperçu ouvert dans le navigateur intégré peut être enregistré et relu comme n'importe quelle page web.

Raccourcis pour

#Ouvrir et modifier des fichiers

  • Fichiers (l'arborescence) : ⌘⇧E / CtrlShiftE, avec Filtrer par nom de fichier, Actualiser et Tout réduire.
  • Aller au fichier… : ⌘P / CtrlP.
  • Faites glisser un fichier depuis le Finder (l'Explorateur de fichiers sous Windows, votre gestionnaire de fichiers sous Linux) sur la barre d'onglets ou sur l'éditeur pour l'ouvrir. Les fichiers du projet s'ouvrent dans l'éditeur ou dans une visionneuse. Pour faire entrer dans le projet un fichier situé ailleurs, déposez-le sur Fichiers : il y est copié. Un dossier déposé ici s'ouvre comme projet. Les fichiers glissés depuis Fichiers s'ouvrent de la même façon. Les images et vidéos déposées sur un fichier Markdown ouvert y sont en revanche intégrées (voir Intégrer des images et des vidéos dans Markdown).
  • Enregistrez avec ⌘S / CtrlS. Fermer un fichier modifié demande Enregistrer les modifications de <name> ? avec Enregistrer, Ne pas enregistrer et Annuler.
  • Si le fichier change sur le disque alors que vous avez des modifications non enregistrées, choisissez Recharger depuis le disque ou Garder mes modifications.

L'éditeur est Monaco. Les fichiers qui ne sont pas du texte s'ouvrent dans une visionneuse : images (zoom avant et arrière ; un SVG peut aussi s'afficher sous forme de code), vidéo et audio avec une barre de lecture, PDF et, pour tout autre fichier binaire, sa taille et une vue hexadécimale des premiers octets. Les visionneuses sont en lecture seule, et les fichiers situés hors du dossier du projet, ou atteints par un lien symbolique qui en sort, ne sont pas affichés.

#Travailler sur les fichiers dans l'arborescence

Travaillez sur les fichiers directement dans Fichiers, comme dans VS Code. Faites un clic droit sur un élément, ou sur l'espace vide sous l'arborescence pour agir à la racine du projet. Les noms se saisissent sur place, dans l'arborescence.

  • Nouveau fichier / Nouveau dossier : les boutons au-dessus de l'arborescence, ou clic droit. Le nouvel élément est créé dans le dossier sélectionné, à côté du fichier sélectionné, ou à la racine du projet. Saisissez un nom avec des barres obliques, comme src/routes/index.ts, pour créer au passage les dossiers intermédiaires. Un nouveau fichier s'ouvre dans l'éditeur. Dans un dossier vide, Fichiers affiche Ce dossier est vide avec les boutons Nouveau fichier et Nouveau dossier.
  • Couper, Copier et Coller : ⌘X / CtrlX, ⌘C / CtrlC, ⌘V / CtrlV, ou clic droit. Les dossiers sont copiés avec tout leur contenu. Dupliquer crée une copie à côté de l'original. Si le nom est déjà pris, la copie s'appelle name copy, puis name copy 2.
  • Faites glisser des éléments sur un dossier (ou sur l'espace vide pour la racine du projet) pour les déplacer. Maintenez ⌥ / Ctrl en déposant pour copier à la place. Les fichiers et dossiers glissés depuis le Finder (l'Explorateur de fichiers sous Windows) sont copiés dans le projet ; les originaux restent où ils étaient.
  • Renommer : F2 / Enter / F2, ou clic droit.
  • Supprimer : ⌘⌫ / Delete / Delete, ou clic droit. Ferret demande d'abord confirmation, puis place l'élément dans la Corbeille, d'où vous pouvez le restaurer. Les onglets des fichiers supprimés se ferment ; si certains avaient des modifications non enregistrées, la confirmation le signale.
  • Annuler : ⌘Z / CtrlZ annule la dernière création, le dernier renommage, déplacement, collage ou la dernière duplication. Les éléments supprimés sont restaurés depuis la Corbeille.
  • Copier le chemin (⌥⌘C / ShiftAltC) et Copier le chemin relatif (⌥⇧⌘C / CtrlShiftAltC) placent le chemin dans le presse-papiers.
  • Afficher dans le Finder (Afficher dans l’Explorateur de fichiers sous Windows, Ouvrir le dossier parent sous Linux) : ⌥⌘R / ShiftAltR. Ouvrir dans le terminal ouvre un nouvel onglet de terminal dans ce dossier (pour un fichier, dans son dossier).
  • Pour un fichier, Ouvrir l'ouvre dans l'éditeur et Ouvrir avec l’app par défaut l'ouvre dans l'application que votre OS utilise pour ce type.
  • Sélectionnez plusieurs éléments avec ⌘ / Ctrl-clic ou ⇧ / Shift-clic pour les couper, copier, déplacer ou supprimer ensemble.
  • Esc annule le nom en cours de saisie.

Les onglets ouverts suivent un fichier renommé ou déplacé et gardent les modifications non enregistrées. Ferret n'écrase pas un fichier ou un dossier existant du même nom, et garde tout à l'intérieur du dossier du projet : il refuse .., les chemins absolus, les liens symboliques qui pointent à l'extérieur, tout ce qui se trouve dans .git, le déplacement d'un dossier dans lui-même, et les noms qu'un OS ne peut pas utiliser : / \ < > : " | ? *, caractères de contrôle, espace ou point final, et noms réservés de Windows comme CON ou NUL. Une copie ou un dépôt peut contenir jusqu'à 10 000 éléments et 1 Go.

#Aperçu Markdown et Mermaid

L'aperçu fonctionne pour .md, .markdown, .mdx, .mmd et .mermaid. Mermaid est intégré à l'application : les diagrammes s'affichent donc hors ligne.

Un fichier Markdown a deux vues en haut de l'éditeur : Source et Aperçu. L'aperçu est toujours modifiable, vous pouvez donc saisir directement dedans ; cliquez sur Source pour revenir au texte. Les deux affichent le même contenu, et l'enregistrement, la marque de modifications non enregistrées et la confirmation à la fermeture fonctionnent de la même façon.

  • Saisissez directement dans les titres, paragraphes, listes, cases à cocher, tableaux, liens, et le texte en gras, en italique ou en code en ligne. Taper #, -, 1. ou > suivi d'une espace en début de ligne commence un titre, une liste ou une citation.
  • Tapez / en début de ligne (ou après un espace) pour choisir un bloc dans une liste : titres, listes à puces, numérotées ou de tâches, tableau, bloc de code, citation ou séparateur. Chaque entrée indique ce qu’elle crée et comment elle s’écrit en Markdown. Continuez à taper pour filtrer, utilisez ↑ ↓ et Enter pour choisir, ou Esc pour garder le / comme texte. Un tableau commence en 3 × 3 avec une ligne d’en-tête ; Tab passe à la cellule suivante et ajoute une ligne à la fin. Taper / dans un tableau permet d’ajouter ou de supprimer des lignes et des colonnes, ou de supprimer le tableau.
  • Les blocs de code se modifient en source, avec le langage affiché dans un coin. Un bloc de code Mermaid (mermaid ou mmd) affiche le diagramme par défaut. Cliquez sur Code en haut à droite, ou double-cliquez sur le diagramme, pour modifier la source ; quand le curseur sort du bloc, le diagramme réapparaît. Si la source contient une erreur, le message s'affiche avec Corriger le code. Les diagrammes sont dessinés dans un cadre isolé (sandbox), et le Markdown enregistré reste tel qu'écrit.
  • Le front matter (le bloc --- en haut) s'affiche sous forme de texte au-dessus du document et peut y être modifié.
  • Les parties que vous ne modifiez pas sont enregistrées exactement telles qu'elles sont écrites, y compris le style des titres, les marqueurs de liste, les lignes vides, l'alignement des tableaux et les fins de ligne. Un bloc modifié garde son style si possible ; sinon, ce bloc est écrit sous une forme Markdown standard, avec - pour les listes et # pour les titres.
  • Les images et vidéos du projet sont affichées. Les images d'autres sites ne sont pas chargées ; leur nom d'hôte s'affiche à la place. Le reste du HTML du fichier s'affiche sous forme de texte.

Les fichiers .mdx (modifiés uniquement sous forme de source), .mmd et .mermaid ont à la place un aperçu en lecture seule :

  • Ouvrir l'aperçu sur le côté : à côté de l'éditeur
  • Ouvrir l'aperçu : dans le navigateur intégré (ade-preview://), pour pouvoir l'enregistrer et le relire

#Intégrer des images et des vidéos dans Markdown

Faites glisser des images (PNG, JPEG, GIF, WebP, SVG, AVIF) ou des vidéos (MP4, WebM, MOV) sur un fichier Markdown, en Source ou en Aperçu, pour les intégrer à l'endroit où vous les déposez.

  • Les fichiers déjà présents dans le projet, y compris ceux glissés depuis Fichiers, sont liés avec un chemin relatif au fichier Markdown. Rien n'est copié.
  • Les fichiers extérieurs au projet (Finder, le bureau, l'Explorateur de fichiers sous Windows) sont d'abord copiés dans un dossier à côté du fichier Markdown : assets, images, media ou img s'il en existe déjà un, sinon un nouveau dossier assets. Les espaces du nom deviennent -, et si le nom est déjà pris, la copie s'appelle name-2. Les originaux restent où ils étaient.
  • Les images sont écrites sous la forme ![name](assets/name.png) et les vidéos sous la forme <video src="assets/name.mp4" controls></video>, que GitHub lit aussi. Les deux s'affichent dans Aperçu.
  • Une image peut faire jusqu'à 50 Mo et une vidéo jusqu'à 500 Mo, et un dépôt copie au plus 50 fichiers et 1 Go. Les autres fichiers déposés en même temps s'ouvrent dans l'éditeur comme d'habitude.

#Relire de la documentation en l'enregistrant

  1. Dans le panneau Cibles de relecture, ouvrez le fichier Markdown depuis Fichiers. Il s'ouvre en aperçu dans le navigateur intégré.
  2. Enregistrez comme d'habitude. Commentez la spécification ou le document de conception à voix haute et entourez ce qui ne va pas.
  3. Arrêtez. Les remarques font référence au chemin du fichier relatif au projet au lieu d'une URL.
  4. Envoyer à l'agent pour faire corriger le document.
