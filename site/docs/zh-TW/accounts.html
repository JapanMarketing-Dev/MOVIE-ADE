設定

帳號與用量

在多個 Claude Code 或 Codex 登入之間切換，並在頁尾查看速率限制時段的用量。這兩項功能目前只支援 Claude Code 與 Codex；其他 Agent 照常使用各自的登入。

#多個帳號

帳號是選用的。只有在需要於多個帳號之間切換時才需要新增。

  1. 開啟 設定 → 帳號，或從頁尾的用量選單開啟 管理帳號…。
  2. 新增帳號 會在內建的終端機分頁中啟動該 Agent 的登入流程。
  3. 選擇要使用的帳號。執行中的分頁會維持原本的帳號，新分頁則使用所選的帳號。

運作方式：每個新增的帳號都有自己的設定目錄 <userData>/accounts/<agent>/<id>/。Ferret 啟動 Agent 時，會將 CLAUDE_CONFIG_DIR（Claude Code）或 CODEX_HOME（Codex）指向該目錄。系統預設 則直接使用你平常的 ~/.claude / ~/.codex。

移除帳號會刪除它的設定目錄，但不會在伺服器端將你登出。

#頁尾的用量

頁尾會顯示各個速率限制時段已使用的比例：5 小時時段與每週時段，Claude 另外還有各模型的每週時段。用量達 60% 時會變成黃色，達 80% 時變成紅色。數值每 15 分鐘更新一次，也可以按 重新整理用量 立即更新。

顯示多少內容取決於頁尾的空間。空間足夠時，會顯示長條、時段名稱與百分比。頁尾越窄，就會先省略較不重要的部分，最少只顯示每個 Agent 一個百分比。按一下用量，即可在彈出視窗中查看所有內容。

用量是以已登入帳號本身的憑證，直接向 Anthropic（api.anthropic.com/api/oauth/usage）與 ChatGPT（chatgpt.com/backend-api/wham/usage）取得。

#達到用量上限時繼續工作

當 Agent 達到用量上限時，Ferret 會在同一個專案資料夾中繼續同一項工作，因此長時間的工作不會因上限而停下。此功能預設開啟，可在 設定 → 帳號 → 達到用量上限時自動切換 中設定。

工作會透過專案中的一個檔案 .ferret/handoff.md 交接，因此在帳號之間與不同 Agent 之間都同樣適用。傳送給 Agent 的指示會要求 Agent 在每個階段以及接近用量上限時更新這個檔案：目標、已完成的部分、以檢查清單列出的剩餘工作、變更過的檔案、下一步、相關的 feedback.md 與審查路徑，以及需要注意的事項。.ferret/ 不會進入 git（它會加入 .git/info/exclude，而不是 .gitignore）。

  1. Ferret 會根據終端機中 Agent 本身的訊息（例如 Claude Code 的 5-hour limit reached ∙ resets 3pm、Codex 的 You've hit your usage limit），或頁尾的用量達到門檻（預設 95%；取 5 小時、每週與各模型額度中最高者）來判斷已達上限。
  2. 切換之前，Ferret 會請目前的 Agent 更新 .ferret/handoff.md。如果 Agent 沒有開始處理（例如它已經達到上限），Ferret 會把它知道的資訊加入該檔案：最後的要求、feedback.md 的位置，以及 git status 中顯示的變更檔案。
  3. 接著 Ferret 會切換到同一個 Agent 已登入的其他帳號中用量最低的那個。當該 Agent 的所有帳號都達到上限時，工作會移到 Agent 順序（預設：Claude Code → Codex → Gemini CLI）中的下一個 Agent。
  4. 新的 Agent 會在同一個專案的新分頁中開啟，並以 App 顯示語言收到提示：先閱讀 .ferret/handoff.md，再繼續剩餘的工作。
  5. 頁尾會顯示 目前使用 <agent>，並有通知說明有什麼改變（例如 Codex 已達到用量上限，已切換到 Claude Code。）。達到上限的分頁會被關閉，因此在其上限恢復時不會再次接手同一項工作。
設定預設值
達到用量上限時自動切換開啟
帳號用量達到此值即視為上限95%
先切換到同一個 Agent 的其他帳號開啟
Agent 順序Claude Code、Codex、Gemini CLI。不在清單中的 Agent 不會被使用。
上限恢復後切回順序較前的 Agent關閉（繼續使用目前的 Agent 工作）。開啟時，會在分頁等待輸入時把工作切回去。

切換只會在專案內進行，每小時最多 6 次，且間隔至少 1 分鐘。憑證保留在各帳號自己的設定目錄中，絕不會被複製。在 settings.json 中，這些設定位於 limitFailover 底下。
