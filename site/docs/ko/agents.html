에이전트로 보내기

코딩 에이전트를 내장 터미널에서 실행하고, 클릭 한 번으로 리뷰를 넘깁니다. Claude Code와 Codex가 대표적인 예이지만, 아래 목록에 있는 에이전트라면 무엇이든 사용할 수 있고 직접 추가한 CLI도 사용할 수 있습니다. 다른 곳에서 실행 중인 에이전트를 위해 지시를 복사할 수도 있습니다.

단축키 표시

#지적 사항 검토

지적 사항 탭의 각 카드에서는 다음을 할 수 있습니다.

  • 제목과 요청을 그 자리에서 편집
  • 보내기 / 보내지 않음 전환
  • 녹화 보기(해당 시점으로 이동)와 이미지 교체(다른 프레임 선택)
  • 확인 완료, 삭제

진행 상태로 필터는 상태별로 지적 사항을 표시하거나 숨깁니다(예: 내 검토를 기다리는 것만 표시). 모두 표시를 누르면 필터가 해제됩니다.

지적 사항의 순서를 바꾸려면 카드 제목 왼쪽의 핸들을 끌거나, 핸들을 선택하고 ↑ / ↓를 누릅니다. 번호, feedback.md, 에이전트에게 보내는 내용이 새 순서를 따릅니다. 필터가 켜져 있으면 보이는 지적 사항 사이에서만 순서가 바뀌고, 숨겨진 지적 사항은 제자리에 남습니다. 하나의 리뷰가 여러 페이지나 파일에 걸쳐 있으면 지적 사항은 같은 그룹 안에서만 움직입니다. 헤더의 지적 사항 정렬에서 수동(끌어 놓은 순서), 녹화 시각 순, 진행 상태 순(미대응이 먼저, 완료가 마지막)을 바꿀 수 있으며, 진행 상태 순으로 정렬하면 그 순서가 수동 순서로 저장됩니다.

헤더에는 실행 취소, 폴더 열기, 에이전트용으로 복사, 정리, 에이전트에게 보내기가 있습니다. 지적 사항이 되지 않은 발화는 제외된 발화에 나열되며, 지적 사항으로 복원으로 되돌릴 수 있습니다. 의미 있는 말이 없는 발화도 지적 사항이 되지 않고 여기에 표시됩니다. 음성 인식이 무음에서 지어내는 “Shh.”나 “시청해 주셔서 감사합니다” 같은 문장, “음” 같은 군말뿐인 발화, 펜 표시 없이 “네”나 “OK”만 말한 발화입니다.

#내장 터미널에서 에이전트 실행

프로젝트를 열면 Ferret은 설정 → 에이전트 → 프로젝트를 열 때 시작에 있는 에이전트마다 터미널 탭을 하나씩 프로젝트 폴더에서 시작합니다. 기본값은 Claude Code와 Codex이며, 권한 확인 없이 Claude in Chrome을 켠 상태로 시작합니다.

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

대신 지원 목록에서 원하는 에이전트를 고를 수 있으며(고른 순서대로 시작됩니다), 아무것도 고르지 않아도 됩니다.

직접 여는 에이전트도 같은 방식으로 시작됩니다. 또한 Ferret은 Claude Code와 Codex에 대해 프로젝트 폴더를 신뢰하는 폴더로 표시하므로, 폴더에 대해 묻지 않습니다. 폴더를 신뢰하기 전, 파일을 편집하기 전, 명령을 실행하기 전에 확인하는 일반 모드로 시작하려면 설정 → 에이전트 → 권한 확인 없이 에이전트 시작을 끄세요. 각 에이전트의 명령과 인수는 설정 → 에이전트(명령)와 settings.json(agents.launch)에 있으며, 적은 그대로 사용됩니다. Claude in Chrome 없이 Claude Code를 시작하려면 그곳에서 --chrome을 지우세요. 인수에서 이미 권한 모드를 고른 경우(예: --permission-mode plan, Codex라면 --sandbox workspace-write)에는 건너뛰기 플래그를 추가하지 않습니다.

선택된 에이전트가 없으면 일반 셸이 열립니다. + 메뉴에서는 새 터미널을 열거나, 에이전트를 새 탭에서 실행하거나, 에이전트 설정…으로 이동할 수 있습니다. 이 메뉴의 검색 상자로 탭, 저장된 URL, 파일도 찾을 수 있습니다.

터미널에 파일 놓기. Finder(Windows에서는 파일 탐색기, Linux에서는 파일 관리자)에서 파일, 폴더, 이미지를 터미널 창으로 드래그하면 그 경로가 공백으로 구분되어 해당 창에 입력되며, Enter는 누르지 않습니다. 에이전트가 실행 중일 때도 마찬가지이며, Claude Code는 놓은 이미지 경로를 이미지로 읽습니다. 파일에서 드래그한 행(선택하면 여러 개를 한 번에)도 같은 방식으로 작동합니다. 터미널이 프로젝트 폴더에 있는 동안에는 프로젝트 폴더 기준의 상대 경로가, cd로 다른 곳으로 이동한 뒤에는 절대 경로가 입력됩니다. 공백이나 그 밖의 특수 문자가 들어간 경로는 셸에 맞게 따옴표로 감쌉니다. zsh와 bash에서는 '…', 명령 프롬프트에서는 "…", PowerShell에서는 '…'입니다.

탭에는 에이전트 상태가 표시됩니다: 실행 중, 입력 대기 중, 완료(읽지 않음), 대기. 완료(읽지 않음)는 다른 탭을 보고 있는 동안 에이전트가 끝났다는 뜻이며, 그 탭을 열면 대기로 바뀝니다. 사이드바도 각 프로젝트에 같은 방식으로 표시하므로 프로젝트를 전환하지 않아도 알 수 있습니다. 에이전트가 실행 중이면 움직이는 막대, 에이전트가 사용자를 기다리고 있으면 물음표, 그곳의 에이전트가 끝났는데 아직 탭을 열지 않았으면 체크 표시가 나타납니다.

알림. 설정 → 에이전트 → 에이전트 작업이 끝나거나 확인이 필요할 때 알림 받기를 켜면, 프로젝트의 모든 에이전트가 끝났을 때 또는 에이전트가 권한이나 답변을 기다릴 때 시스템 알림을 받습니다. 보고 있는 탭에 대해서는 아무것도 표시되지 않습니다. 알림을 클릭하면 그 프로젝트로 전환되고 탭이 열립니다.

드래그로 분할. 탭을 드래그하거나, 창을 핸들(탭이 분할되면 표시됨)로 드래그해서 다음 위치에 놓습니다.

  • 창 가장자리의 바깥쪽 4분의 1: 왼쪽으로 분할 / 오른쪽으로 분할 / 위로 분할 / 아래로 분할
  • 창의 가운데: 탭으로 열기(창이 분할에서 빠져 독립된 탭이 됩니다)
  • 터미널 영역 전체를 둘러싼 얇은 띠: 전체 영역을 왼쪽으로 분할 등(창이 2개 이상일 때)
  • 탭 표시줄: 여기에 탭으로 배치

옮기는 동안에도 프로세스는 계속 실행되며, 비어 있게 된 탭은 닫힙니다. 키보드로 분할하기:

동작macOSWindows / Linux
새 터미널⌘TCtrlT
오른쪽으로 분할⌘DCtrlShiftD
아래로 분할⌘⇧DAltShiftD
창 / 탭 닫기⌘WCtrlW

#다시 시작한 뒤 터미널 되돌리기

Ferret을 종료할 때 모든 프로젝트의 터미널 탭을 기억합니다. 순서와 분할, 각 탭을 연 폴더, 실행하던 에이전트와 계정, 그리고 화면마다 최대 2,000줄의 글자입니다. 다음에 Ferret을 시작하면 탭이 같은 순서로 돌아옵니다. 이전 글자가 먼저 표시되고, — 지난번에 이어서 (2026-10-05 14:30) — 같은 흐린 줄 뒤에 같은 폴더에서 새 셸이 시작됩니다.

에이전트 탭은 대화를 이어서 시작합니다. Claude Code는 --continue, Codex는 resume --last로 그 폴더의 가장 최근 대화를 이어갑니다. 같은 폴더에서 같은 계정으로 같은 에이전트를 실행하는 탭이 여러 개면 첫 번째 탭만 대화를 잇고 나머지는 새로 시작하므로, 두 탭이 같은 대화를 잇는 일은 없습니다. 그 폴더에 Claude Code 대화가 없거나 프로젝트가 SSH 호스트에 있으면 평소처럼 시작합니다.

닫은 터미널 다시 열기. 터미널 → 닫은 터미널 다시 열기(터미널에 포커스가 있을 때 ⌘⇧T / CtrlShiftT)는 이 프로젝트에서 마지막으로 닫은 탭이나 창을 글자와 함께 되돌리고, 에이전트도 같은 방식으로 대화를 이어서 시작합니다. 닫은 터미널은 최근 10개까지 다시 시작한 뒤에도 기억합니다.

기록은 색이 없는 일반 텍스트로 Ferret의 데이터 폴더(terminal-restore.json, 본인만 읽을 수 있음)에 저장하며 프로젝트에는 쓰지 않습니다. 계정 추가에서 연 로그인 탭과 한 번만 실행하는 명령은 기억하지 않습니다. 저장을 멈추려면 설정 → 에이전트 → 터미널 기록을 저장하고 복원을 끄세요. 저장한 내용도 삭제됩니다. 옆의 저장한 기록 삭제로 언제든지 삭제할 수 있습니다.

#에이전트에게 보내기 / 에이전트용으로 복사

  1. 에이전트에게 보내기를 클릭합니다. 기본값(자동(현재 탭 또는 실행 중인 에이전트))에서는 현재 터미널 탭의 에이전트나 실행 중인 에이전트로 보냅니다. 버튼 옆의 화살표(보낼 에이전트 선택)로 특정 에이전트나 탭을 고를 수 있습니다.
  2. Ferret이 에이전트의 입력란에 지시를 써 넣고 제출합니다. 진행 상황은 터미널에서 확인하세요.

실행 중인 에이전트가 없으면 Ferret이 먼저 하나를 시작하고, 준비되는 대로 보냅니다. 에이전트가 권한 확인에 대한 응답을 기다리는 동안에는 아무것도 보내지 않습니다. 먼저 터미널에서 응답하세요.

에이전트용으로 복사는 다른 곳(다른 터미널, IDE, 앱)에서 실행 중인 에이전트를 위해 같은 지시를 클립보드에 넣습니다. 보내기로 설정된 지적 사항만 대상이 됩니다. 동영상은 절대 포함되지 않습니다.

#판정 모델로 완료 검사

이 기능을 켜면 코딩 에이전트가 사용자가 보기 전에 지적 사항마다 자신의 작업을 한 번 스스로 확인합니다. Ferret 자체는 아무것도 판정하지 않습니다. 에이전트에게 판정 모델(System One 호환 API라면 무엇이든)을 제공하고, feedback.md에서 사용 방법을 알려 줍니다. 판정 모델은 에이전트 자신의 확인이며, 사용자에게 하는 질문이 아닙니다. 에이전트는 사용자에게 아무것도 묻지 않습니다. 사용자는 BEFORE와 AFTER를 비교하고 OK 또는 NG를 누르기만 하면 됩니다.

  1. 에이전트가 지적 사항을 구현합니다.
  2. 지적 사항마다 AFTER 스크린샷(BEFORE 정지 화면과 같은 뷰포트, 같은 페이지 상태)을 찍고, 지적 사항의 텍스트, "완료 조건" 줄, BEFORE/AFTER 이미지를 담은 요청 하나를 판정 모델에 보냅니다.
  3. 판정 모델은 지적 사항을 에이전트에게 보낼 때마다 지적 사항 하나당 최대 한 번 호출됩니다. 두 번째 판정도 반복도 없으므로, "done"이라고 하지 않는 모델이 에이전트를 계속 붙잡아 둘 수 없습니다.
  4. 에이전트는 그 한 번의 결과를 읽습니다. P(done)이 임계값(기본값 0.7) 이상이고 choice가 done이면 그 지적 사항은 통과이며 그대로 사용자에게 넘어갑니다. 그렇지 않고 결과가 에이전트가 고칠 수 있는 분명한 차이를 보이면, 에이전트는 수정을 한 번 더 개선하고 다시 판정하지 않은 채 AFTER를 다시 캡처할 수 있습니다.
  5. 어느 경우든 에이전트는 지적 사항을 확인 대기로 설정하고, AFTER와 그 한 번의 점수, 최대 한 줄의 메모를 붙입니다. 범위를 벗어난 지적 사항이나 연결할 수 없는 판정 API는 작업을 멈추게 하지 않습니다. 그 지적 사항은 점수 없이 확인 대기로 넘어갑니다.
  6. 지적 사항에서는 사용자를 기다리는 각 지적 사항이 BEFORE, AFTER와 점수를 판단 자료로 보여 줍니다. OK를 누르면 완료로 표시되고, 코멘트와 함께 NG를 누르면 새 요청으로 에이전트에게 다시 보내지며, 거기서 다시 한 번 판정됩니다. 터미널에 나오는 에이전트의 최종 완료 / 미완료 목록에는 각 지적 사항의 점수와 수정을 한 번 더 개선했는지가 포함됩니다.

설정 → 판정 모델에서 설정하고 에이전트 지시에 판정 모델 검사 추가를 켜세요. 프리셋은 필드를 채울 뿐이며 모든 필드는 계속 편집할 수 있고, 사용자 지정은 호환되는 어떤 API와도 동작합니다.

Ollama를 쓰려면 설치하고(Clef / Clef Flash에는 0.35.1 이상) 터미널에서 모델을 내려받으세요. Ferret은 설치 프로그램을 실행하지 않습니다.

ollama pull clef-flash

키는 키 필드(다른 API 키와 함께 저장됨), 지정한 이름의 환경 변수(앱의 환경, 프로젝트의 .env, 또는 ~/.ferret/.env), 또는 settings.json의 apiKey에서 가져옵니다. 추가 헤더는 ${VAR}로 환경 변수의 값을 읽을 수 있습니다.

키가 프롬프트에 들어가지 않는 방식

에이전트는 키를 절대 보지 못합니다. Ferret은 127.0.0.1에서 로컬 릴레이를 실행하고, 각 터미널에 FERRET_DECISION_URL(터미널별 토큰이 붙은 릴레이), FERRET_DECISION_MODEL, FERRET_DECISION_IMAGES를 전달합니다(한 릴리스 동안은 예전 이름인 MOVIE_ADE_DECISION_*도 함께 설정됩니다). 릴레이는 키와 헤더를 붙여 요청을 그대로 전달하므로 프롬프트, feedback.md, 에이전트의 대화 기록에는 비밀 정보가 남지 않습니다. 터미널마다 받는 토큰으로는 500회, 분당 30회, 2,000만 토큰, 5달러(비용을 알 수 있을 때)까지, 프로젝트마다 하루 2,000회와 20달러까지 쓸 수 있습니다. 한도에 닿으면 릴레이가 이유와 함께 429를 돌려주고, 새 터미널 탭은 새 토큰을 받습니다. 판정 모델 설정을 바꾸면 열려 있는 터미널의 토큰은 더 이상 쓸 수 없고, 그 뒤에 연 터미널부터 새 설정이 적용됩니다.

Cloudflare는 System One 문서와 두 가지 점에서 다릅니다(실제 API로 확인함). 이미지는 data URI(data:image/jpeg;base64,…)여야 하며, 그렇지 않으면 422 "image must be an embedded base64 data URI"가 반환됩니다. 또한 응답이 { "result": { … }, "success": true }로 감싸여 옵니다(오류는 { "success": false, "errors": [ … ] }로 옵니다). Cloudflare 프리셋은 이미지 인코딩을 data URI로 설정하고, 에이전트는 이를 FERRET_DECISION_IMAGE_FORMAT으로 받으며, 지시에는 .result가 있으면 그것을 읽으라고 적혀 있습니다. 릴레이는 양방향 모두 그대로 전달합니다. API 토큰 대신 Global API Key를 쓰려면 인증을 키 없음으로 설정하고 X-Auth-Email: ${CLOUDFLARE_EMAIL}과 X-Auth-Key: ${CLOUDFLARE_API_KEY} 헤더를 추가하세요.

이미지를 읽을 수 있는 것은 Clef와 Clef Flash뿐입니다. 텍스트 전용 모델을 쓸 때는 BEFORE/AFTER 이미지 전송을 끄세요. 그러면 에이전트는 텍스트만으로 판정하므로 신뢰도가 떨어집니다.

Ollama와 큰 이미지

Ollama 0.35.0은 /v1/systemone 요청을 64 KiB로 제한하므로, 스크린샷이 포함된 요청은 HTTP 413으로 실패합니다. 지시에는 두 이미지를 너비 최대 1024px의 JPEG(품질 약 70)로 줄이라고 적혀 있습니다. 그래도 413이 나오면 Ollama를 0.35.1 이상으로 업데이트하거나 Cloudflare Workers AI로 바꾸세요.

#푸터의 API 사용량

판정 호출은 릴레이를 거치므로 Ferret이 횟수를 셀 수 있습니다. 푸터에서 에이전트 사용량 미터 옆 항목에 판정 모델과 오늘의 호출 수, 토큰, 비용이 표시됩니다(예: clef-flash · 42 calls · 18.3k tok). 클릭하면 오늘, 이번 달, 프로젝트별, 모델별, 종류별(판정 / 음성 인식 / 정리) 집계와 최근 50건의 호출을 볼 수 있습니다.

비용은 API가 보고하는 경우(Vercel AI Gateway는 보고합니다)나 설정 → 판정 모델에서 100만 토큰당 가격을 설정한 경우에만 표시되며, 그 외에는 "—"로 표시됩니다. 기록되는 것은 메타데이터(시각, 프로젝트, 모델, 상태, 지연 시간, 크기, 이미지 수, 토큰, 비용)뿐이며 이미지, 텍스트, 키는 절대 기록되지 않습니다. 기록은 ~/.ferret/usage/decision-YYYY-MM.jsonl에 한 달에 한 파일씩 저장됩니다.

#지시 바꾸기

설정 → 에이전트 → 에이전트에게 보낼 지시를 편집하세요. 변수 두 개가 치환됩니다.

변수치환 결과
{{path}}feedback.md의 절대 경로
{{relpath}}프로젝트 기준 상대 경로: .ferret/reviews/<id>/feedback.md

비워 두면 기본값을 사용합니다. 최대 길이는 2000자이며, 지시 초기화로 기본값을 복원할 수 있습니다. 예:

Read {{relpath}} and the PNGs next to it. Fix only findings marked to send, one commit per finding, then run the tests.

이 설정은 settings.json에 agentPrompt로 저장됩니다.

#GitHub에서 Ferret에 스타 주기

처음 에이전트에게 보내기를 한 뒤, 그리고 완료한 리뷰가 3, 10, 30개가 되었을 때 Ferret이 GitHub에서 스타를 달라고 요청할 수 있습니다. 요청은 최대 3번, 최소 3일 간격으로 하며, 녹화 중에는 절대 하지 않습니다. GitHub에서 스타는 내 gh 로그인으로 스타를 주고(gh를 쓸 수 없으면 GitHub를 엽니다), 다시 묻지 않기를 누르면 요청이 멈춥니다. 도움말 → GitHub에서 Ferret에 스타 주기에서도 스타를 줄 수 있습니다.

#자주 쓰는 서비스 CLI

설정 → 자주 쓰는 서비스 CLI에는 자주 쓰는 서비스의 명령줄 도구가 나열됩니다. 설치해 두면 에이전트가 해당 서비스를 다룰 수 있습니다. 설치는 선택 사항이므로 필요한 것만 설치하세요. 하나도 설치하지 않아도 Ferret은 사용할 수 있습니다. 각 행에는 설치 여부와 버전, 서비스 웹사이트 링크, 그리고 OS에 맞는 공식 설치·로그인 명령을 새 터미널 탭에서 실행하는 버튼이 있습니다:

  • Git 호스팅: GitHub(gh), GitLab(glab)
  • 호스팅·배포: Vercel, Netlify, Cloudflare(wrangler), Firebase, Fly.io, Railway, Heroku
  • 클라우드: AWS, Google Cloud(gcloud), Azure(az)
  • 데이터베이스·백엔드: Supabase, Neon, PlanetScale, Turso
  • 오류·모니터링: Sentry(sentry-cli), Datadog(datadog-ci)
  • 결제: Stripe
  • 컨테이너: Docker, kubectl
  • 모바일: Xcode Command Line Tools(macOS 전용), Android Platform Tools(adb), Expo EAS, fastlane
  • 가상 머신: UTM(macOS 전용), Lima, Multipass
  • AI·모델: Ollama

내 OS용 한 줄 공식 설치 프로그램이 없는 도구는 대신 문서가 설치 페이지를 엽니다. 설치가 끝나면 목록이 자동으로 다시 확인합니다.
