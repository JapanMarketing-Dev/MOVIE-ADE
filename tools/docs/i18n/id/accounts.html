Akun dan penggunaan Berpindah antara beberapa login Claude Code atau Codex, dan pantau jendela batas rate Anda di footer. Untuk saat ini kedua fitur hanya berfungsi dengan Claude Code dan Codex; agent lain tetap memakai login masing-masing seperti biasa. ## Beberapa akun

Akun bersifat opsional. Tambahkan hanya jika Anda berpindah-pindah di antara beberapa akun.

  1. Buka Pengaturan → Akun, atau Kelola Akun… dari menu penggunaan di footer.
  2. Tambah Akun memulai login agent di tab terminal bawaan.
  3. Pilih akun yang akan dipakai. Tab yang sedang berjalan tetap memakai akunnya. Tab baru memakai akun yang dipilih.

Cara kerjanya: setiap akun yang ditambahkan mendapat direktori konfigurasi sendiri, <userData>/accounts/<agent>/<id>/. Ferret menjalankan agent dengan CLAUDE_CONFIG_DIR (Claude Code) atau CODEX_HOME (Codex) yang menunjuk ke sana. Default Sistem memakai ~/.claude / ~/.codex Anda yang biasa tanpa perubahan.

Menghapus akun akan menghapus direktori konfigurasinya. Tindakan ini tidak mengeluarkan Anda (sign out) di sisi server.

## Penggunaan di footer

Footer menampilkan seberapa banyak setiap jendela batas rate sudah terpakai: jendela 5 jam dan jendela mingguan, ditambah jendela mingguan per model untuk Claude. Warna berubah menjadi kuning di 60% dan merah di 80%. Nilai diperbarui setiap 15 menit, atau saat Anda mengklik Segarkan penggunaan.

Seberapa banyak yang ditampilkan bergantung pada ruang di footer. Jika ruangnya cukup, footer menampilkan bar, nama jendela, dan persentase. Saat footer makin sempit, bagian yang kurang berguna dihilangkan lebih dulu, hingga tersisa satu persentase per agent. Klik penggunaan untuk melihat semuanya di popover.

Data penggunaan diambil langsung dari Anthropic (api.anthropic.com/api/oauth/usage) dan ChatGPT (chatgpt.com/backend-api/wham/usage) dengan kredensial milik akun yang sedang masuk.

{{shot:usage|Penggunaan di footer}} ## Tetap bekerja saat mencapai batas penggunaan

Saat agent mencapai batas penggunaannya, Ferret melanjutkan pekerjaan yang sama di folder proyek yang sama, sehingga tugas panjang tidak berhenti di batas tersebut. Fitur ini aktif secara bawaan dan diatur di Pengaturan → Akun → Beralih saat batas penggunaan.

Pekerjaan diserahterimakan melalui satu file di proyek, .ferret/handoff.md, sehingga cara ini berfungsi sama baiknya antar-akun maupun antar-agent yang berbeda. Instruksi Kirim ke Agent meminta agent untuk terus memperbarui file tersebut di setiap tahap penting dan saat mendekati batas penggunaan: tujuan, apa yang sudah selesai, sisa pekerjaan sebagai checklist, file yang diubahnya, langkah berikutnya, path feedback.md dan tinjauan yang terkait, serta hal-hal yang perlu diperhatikan. .ferret/ tetap di luar git (ditambahkan ke .git/info/exclude, bukan ke .gitignore).

  1. Ferret mendeteksi batas dari pesan agent itu sendiri di terminal (misalnya 5-hour limit reached ∙ resets 3pm di Claude Code, You've hit your usage limit di Codex) atau dari penggunaan di footer yang mencapai ambang (95% secara bawaan; nilai tertinggi dari jendela 5 jam, mingguan, dan per model).
  2. Sebelum beralih, Ferret meminta agent saat ini untuk memperbarui .ferret/handoff.md. Jika agent tidak mulai mengerjakannya (misalnya karena sudah mencapai batas), Ferret menambahkan apa yang diketahuinya ke file tersebut: permintaan terakhir, lokasi feedback.md, dan file yang berubah menurut git status.
  3. Ferret lalu beralih ke akun lain yang sudah masuk untuk agent yang sama, yaitu yang penggunaannya paling rendah. Jika semua akun agent tersebut sudah mencapai batas, pekerjaan berpindah ke agent berikutnya dalam Urutan agen (bawaan: Claude Code → Codex → Gemini CLI).
  4. Agent baru terbuka di tab baru di proyek yang sama dan diberi tahu, dalam bahasa aplikasi, untuk membaca .ferret/handoff.md lebih dulu lalu melanjutkan sisa pekerjaan.
  5. Footer menampilkan Sekarang dengan <agent> dan sebuah pemberitahuan menjelaskan apa yang berubah, misalnya Codex mencapai batas penggunaannya, jadi Claude Code mengambil alih pekerjaan. Tab yang mencapai batas ditutup, sehingga tidak mengerjakan tugas yang sama lagi saat batasnya pulih.
