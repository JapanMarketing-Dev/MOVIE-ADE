Instalación Ferret es una app de escritorio para macOS, Windows y Linux. La versión de macOS está firmada con un Developer ID y notarizada por Apple. Las versiones de Windows y Linux aún no tienen firma de código, así que esos sistemas te piden que confirmes el primer inicio. ## Descarga

Descarga el archivo para tu sistema operativo y CPU desde la página de descarga. Los archivos se sirven desde Cloudflare R2, no desde GitHub Releases, y solo se conservan las 10 versiones más recientes.

## Verificar la descarga (SHA256SUMS firmado)

Cada versión incluye un archivo SHA256SUMS y su firma SHA256SUMS.sig. La firma se hace con la clave de publicación de Ferret, que se guarda aparte del servidor de descarga, así que un instalador modificado en el servidor de descarga no puede venir con una firma válida. La clave pública no se obtiene del servidor de descarga: tómala del repositorio (build/release-signing/allowed_signers) o cópiala de aquí:

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

Su huella digital es SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ. Los mismos archivos se adjuntan a cada versión en GitHub. Comprueba la firma con ssh-keygen (incluido en macOS, Windows 10 y posteriores, y Linux) y luego compara el hash de tu descarga con la lista firmada:

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

No sigas si ssh-keygen no muestra Good "ferret-release" signature o si el hash no está en la lista. Buscar actualizaciones de Ferret hace la misma comprobación con la clave integrada en la app y no ofrece ninguna versión cuya firma no coincida. En macOS también puedes comprobar la firma Developer ID y la notarización con spctl -a -vv /Applications/Ferret.app. Los instaladores de Windows y Linux aún no tienen firma de código de Microsoft ni de ninguna distribución de Linux. Las versiones hasta la 0.3.0 se publicaron antes de que empezara la firma y solo tienen los hashes sin firmar en releases/<version>/manifest.json.

## macOS
  1. Abre el .dmg y arrastra Ferret.app a /Applications.
  2. Ábrela. La app está firmada con un Developer ID y notarizada por Apple (con el ticket grapado), así que se abre sin ninguna advertencia.

Para comprobar la firma tú mismo:

spctl -a -vv /Applications/Ferret.app
# accepted
# source=Notarized Developer ID

Solo las versiones antiguas (0.2.0 build 2 y anteriores) no estaban firmadas. Con ellas, macOS indica que no se puede verificar el desarrollador: cierra el diálogo, abre Ajustes del Sistema → Privacidad y seguridad, haz clic en Abrir igualmente junto al mensaje sobre Ferret y confirma con Abrir. Si dice que la app «está dañada», elimina el atributo de cuarentena:

xattr -dr com.apple.quarantine /Applications/Ferret.app
## Windows
  1. Ejecuta Ferret-<version>-win-<arch>.exe.
  2. Cuando SmartScreen muestre «Windows protegió tu PC», haz clic en Más información y luego en Ejecutar de todas formas.
  3. Elige la carpeta de instalación. El instalador crea un acceso directo en el escritorio.
## Linux

AppImage:

chmod +x Ferret-<version>-linux-x86_64.AppImage
./Ferret-<version>-linux-x86_64.AppImage

Debian / Ubuntu:

sudo apt install ./Ferret-<version>-linux-amd64.deb

El deb instala el paquete y el comando ferret.

En Ubuntu 23.10 y posteriores, el AppImage puede detenerse al iniciarse con un error de sandbox, porque AppArmor restringe los espacios de nombres de usuario que usa el sandbox de Electron. Instala el .deb en su lugar; configura el asistente del sandbox.

## Compilar desde el código fuente

Requiere Node.js 20+ (la CI y el desarrollo local usan la 22), pnpm y git.

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

Para empaquetar los instaladores (salida en dist/release/, configuración en electron-builder.config.cjs). La compilación de Linux solo se ejecuta en Linux.

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

Los scripts build:<os>:dev solo generan la app sin empaquetar (--dir), lo que es más rápido para probar en local.

En Windows, pnpm install usa los binarios precompilados que incluye node-pty en lugar de recompilar (eso requeriría las herramientas de compilación de C++ de Visual Studio). Define ADE_FORCE_NATIVE_REBUILD=1 para forzar la recompilación.

Si la terminal indica que no se pudo cargar node-pty, ejecuta pnpm rebuild:native.

## Actualizaciones

Ferret no se actualiza automáticamente. En el pie de la ventana, abre Actualizaciones y haz clic en Buscar actualizaciones. Descarga latest.json del servidor de descarga (R2), compara las versiones y enlaza a la página de descarga. Desde la 0.4.0 también comprueba la firma del SHA256SUMS de esa versión con la clave de publicación integrada en la app, y no ofrece ninguna versión cuya firma no se pueda verificar. No se comprueba nada hasta que haces clic, y nada se instala automáticamente.
