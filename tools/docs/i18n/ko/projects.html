프로젝트와 URL 프로젝트는 폴더(보통 저장소의 루트)입니다. 프로젝트마다 저장한 URL을 따로 가지므로 local, dev, 프로덕션을 한 번의 클릭으로 오갈 수 있습니다. ## 프로젝트 추가하기
  1. 파일 → 프로젝트 폴더 열기…({{keys:Mod+O}}), 사이드바의 프로젝트 추가, 또는 제목 표시줄 프로젝트 메뉴의 프로젝트 추가…를 사용합니다.
  2. 프로젝트를 가져올 곳을 고릅니다.
    • 이 컴퓨터에서: 폴더를 선택합니다.
    • GitHub / GitLab에서 클론: 내 저장소 중 하나(gh 또는 glab 로그인으로 목록을 가져옴)를 고르거나 URL을 붙여 넣고 상위 폴더를 선택하면, Ferret이 클론한 뒤 엽니다.
    • SSH로 열기: ~/.ssh/config에서 호스트를 고릅니다. 터미널과 에이전트는 원격 머신에서 실행되고, 리뷰는 이 컴퓨터에 남습니다.

Finder(Windows에서는 파일 탐색기, Linux에서는 파일 관리자)에서 폴더를 드래그해 사이드바의 프로젝트 목록에 놓아도 됩니다. 드래그하는 동안 목록이 강조 표시됩니다. 파일이 아니라 폴더를 놓으세요. 여러 폴더를 놓으면 각각을 추가하고 마지막 폴더를 엽니다.

이름의 기본값은 폴더 이름입니다. 이미 등록된 폴더를 추가하면 대신 그 프로젝트가 열립니다(macOS와 Windows에서는 경로를 대소문자 구분 없이 비교합니다). 사이드바 메뉴에서 프로젝트를 이름 변경하거나 목록에서 제거할 수 있습니다. 제거해도 폴더는 삭제되지 않습니다.

목록의 순서를 바꾸려면 프로젝트를 위아래로 끌어 놓습니다(놓일 위치에 선이 표시됩니다). 선택한 프로젝트에서 {{keys:Alt+Up}} / {{keys:Alt+Down}}를 누르거나, 메뉴의 위로 이동 / 아래로 이동을 사용해도 됩니다. 순서는 저장되어 다시 시작한 뒤에도 유지됩니다.

리뷰 검색창 옆의 필터 버튼에서 프로젝트 정렬도 정할 수 있습니다: 수동(끌어 놓은 순서), 활동 중 먼저(에이전트가 나를 기다리거나, 작업 중이거나, 방금 작업을 마친 프로젝트가 위), 최근 사용 순, 이름 순, 추가한 순. 수동이 아닌 정렬에서 프로젝트를 끌면 지금 보이는 순서가 수동 순서가 되고 정렬은 수동(끌어 놓은 순서)으로 바뀝니다. 프로젝트 행의 별표나 메뉴의 별표 달기로 별표를 달면 어떤 정렬에서도 목록 맨 위에 놓입니다. 별표만 표시을 켜면 나머지 프로젝트는 숨겨집니다. 별표와 정렬은 다시 시작한 뒤에도 유지됩니다.

터미널은 프로젝트 폴더에서 열리고, 리뷰는 <project>/.ferret/ 아래에 저장됩니다.

## GitHub에 비공개 저장소 만들기

아직 GitHub에 없는 프로젝트를 비공개 저장소로 만들려면, 사이드바에서 프로젝트를 오른쪽 클릭하고 GitHub에 비공개 저장소 만들기를 고릅니다. 자신의 gh 로그인을 쓰므로 gh를 설치하고 로그인해 두어야 합니다. GitHub만 지원하며 GitLab은 지원하지 않습니다.

  1. 소유자(자신의 계정이나 소속 조직)와 저장소 이름(폴더 이름에서 제안. 영문자, 숫자, ., _, -)을 고릅니다. 설명(선택)도 붙일 수 있습니다.
  2. 폴더에 아직 커밋이 없으면 첫 커밋을 만들고 push로 첫 커밋을 만듭니다. .gitignore 대상과 비밀을 담을 수 있는 파일은 넣지 않습니다: .env 파일(.env.example 같은 템플릿은 넣음), *.pem이나 id_rsa 같은 키, .npmrc, .netrc, credentials.json, *.tfstate 등. 빠진 파일은 대화 상자에 목록으로 나옵니다. 그 경로는 .git/info/exclude에 적으므로 이후 커밋에도 들어가지 않습니다. 프로젝트의 파일과 .gitignore는 바꾸지 않습니다. 아직 git 저장소가 아닌 폴더는 브랜치 main으로 초기화합니다.
  3. 다음을 누르고 저장소, 공개 범위, push를 확인한 뒤 만들기를 누릅니다. 저장소는 항상 비공개입니다. 폴더의 origin이 되고, 폴더의 커밋을 push합니다.

폴더에 이미 origin이 있을 때, 다른 git 저장소 안에 있을 때(모노레포 안의 폴더 등), 같은 이름의 저장소가 이미 있을 때, 첫 커밋의 파일이 20,000개를 넘을 때, git에 사용자 이름과 이메일이 없을 때, SSH로 연 프로젝트일 때는 만들지 않고 거절합니다.

처음 선택되는 소유자는 자신의 계정입니다. 조직으로 하려면 설정 → 자주 쓰는 서비스 CLI에서 새 저장소의 소유자(GitHub)(settings.json의 github.defaultOwner)를 정합니다.

## URL 저장하기
  1. 내장 브라우저에서 페이지를 엽니다.
  2. 브라우저 도구 모음의 +(현재 URL 저장)를 클릭합니다. 현재 URL이 미리 입력되어 있습니다.
  3. 이름을 입력하고 저장을 클릭합니다.

저장한 URL마다 검토 대상에서 종류를 정합니다. 앱(만들고 있는 앱), 디자인(Figma, Penpot, Canva, 프로토타입), 문서 / 사양(Google Docs, Notion, Confluence, GitHub의 Markdown 사양, PDF), 참고(경쟁사 사이트 등 고칠 수 없는 외부 사이트) 중 하나입니다. 종류는 URL과 이름에서 추측하며 바꿀 수 있습니다. 코드뿐 아니라 디자인과 문서도 리뷰하기와 다른 사이트를 참고로 쓰기를 참고하세요.

http://와 https:// URL만 사용할 수 있습니다. 앱 URL은 제안된 이름을 그대로 두면 호스트에서 이름을 추측합니다.

dev, develop, development 포함dev
stg, stage, staging 포함stg

피드백 모드에서는 오른쪽의 리뷰 대상 패널에 현재 프로젝트에서 리뷰할 수 있는 모든 것이 나열됩니다. 대상을 전환해도 녹화는 멈추지 않습니다. 패널은 보기 → 리뷰 대상 표시/숨기기({{keys:Mod+Shift+K}}) 또는 패널 숨기기로 표시하거나 숨깁니다.

  • 대상: 프로젝트에 저장된 URL입니다. 각 URL 아래에는 그 사이트에서 방문한 페이지가 트리로 표시됩니다. 저장하지 않았지만 방문한 사이트는 별도의 그룹으로 표시됩니다.
  • 파일: 프로젝트 폴더입니다. 파일은 미리 보기로 열리므로(Markdown과 Mermaid는 렌더링되고, 그 밖의 텍스트는 읽기 전용) 문서도 리뷰할 수 있습니다. 연필(에디터에서 열기)을 누르면 에디터에서 열립니다.

대상 필터는 대상, 페이지, 파일을 한꺼번에 걸러 내며, 파일로 이동…과 같은 퍼지 매칭을 사용합니다. 목록에서는 ↑ ↓ Enter 또는 1–9로 대상을 전환합니다. URL 열기…는 일회성 URL을 열고, 프로젝트 URL에 저장은 그 URL을 저장합니다.

대상은 settings.json의 projects[].urls에서 가져옵니다(예시 참고). 각 항목에는 url, launchCommand(터미널에서 실행. 예: 데스크톱 앱 시작), windowMatch(녹화할 창) 중 하나가 필요하고, purpose(app, design, doc, reference)를 지정할 수 있습니다. 녹화 전에 창 대상을 고르면 그 창이 녹화 소스로 설정되고, 녹화 중에 고르면 그 창을 녹화에 추가해 보여 줍니다(여러 창을 동시에 녹화 참고). 방문한 페이지는 프로젝트별로 이 컴퓨터에만 기억됩니다(최대 200개).

## 환경 열기와 전환

저장한 URL을 클릭하면 열립니다. 현재 페이지가 다른 저장된 URL 아래에 있으면, Ferret은 경로, 쿼리, 해시를 유지하고 origin만 바꿉니다. 예를 들어 http://localhost:3000/pricing?plan=pro에서 prd를 클릭하면 https://example.com/pricing?plan=pro가 열립니다.

현재 페이지와 일치하는 칩(가장 긴 접두사)이 강조 표시됩니다. 칩을 마우스 오른쪽 버튼으로 클릭하거나 연필 아이콘을 사용해 편집하거나 삭제할 수 있습니다. 프로젝트를 열 때 이전 URL이 없으면 첫 번째 저장된 URL이 로드됩니다.

칩은 종류별로 묶입니다. 앱 URL이 먼저, 그다음 디자인, 문서, 참고 순이며, 종류마다 구분선과 아이콘이 붙습니다. 디자인, 문서, 참고로 전환하거나 거기서 다른 곳으로 전환할 때는 경로를 이어 가지 않고 저장된 URL을 그대로 엽니다.

## 코드뿐 아니라 디자인과 문서도 리뷰하기

피드백이 꼭 코드에 관한 것일 필요는 없습니다. 내장 브라우저에서 열리는 것이라면 무엇이든 같은 방식으로 녹화하고 펜으로 표시할 수 있습니다. Figma나 Penpot 디자인, 프로토타입, Google Docs나 Notion의 사양, GitHub의 설계 문서, PDF 등입니다. 리뷰 전에 이런 URL을 local, dev와 나란히 프로젝트에 저장해 두세요.

  1. 사이드바 메뉴에서 프로젝트 편집…을 열고(또는 브라우저 도구 모음의 +를 클릭하고) 대상 추가를 클릭합니다.
  2. URL을 붙여 넣습니다. figma.com 링크는 디자인이 되고 docs.google.com이나 notion.so 링크는 문서 / 사양이 되며, 이름은 Figma 또는 Spec이 됩니다. 추측이 틀렸다면(예: 자체 서버의 프로토타입) 검토 대상에서 종류를 바꿉니다.
  3. 대상을 열고, 사이트에 로그인이 필요하면 내장 브라우저에서 한 번 로그인합니다. 브라우저는 실행 사이에 쿠키를 유지하므로 로그인 상태가 이어집니다.
  4. 평소처럼 녹화합니다. 말하고, 가리키고, 디자인이나 문서 위에 그립니다.

디자인이나 문서에서 녹화한 지적 사항은 지적 사항 목록과 feedback.md에 그 종류가 표시되고, 에이전트에게 보내는 지시에도 그렇게 적힙니다. 그러면 에이전트는 코드 대신 디자인이나 문서를 고칩니다.

  • 문서가 프로젝트 안에 있으면(Markdown 사양, ADR) 에이전트가 그 파일을 편집합니다.
  • 편집할 수 없으면(Figma 파일, Google 문서) 에이전트는 멈춰서 묻지 않습니다. 해야 할 정확한 변경 내용을 한 줄 메모로 적어 지적 사항을 확인 대기로 설정하므로, 직접 반영하거나 다른 사람에게 넘길 수 있습니다.

예: Google Docs에서 요금 사양을 읽다가 요금제 표에 동그라미를 치고 "Pro 요금제는 이제 8,800엔이 아니라 9,800엔"이라고 말합니다. feedback.md에는 이 지적 사항이 Spec 대상 아래에 Kind: document로 기록되고, 에이전트는 요금 페이지 코드를 건드리는 대신 사양에 넣을 수정된 문장으로 답합니다. 사양과 실행 중인 앱을 같은 녹화에 담으면 지적 사항이 대상별로 나뉘므로, 에이전트가 사양을 먼저 고치고 그다음 그것을 구현하는 코드를 고칠 수 있습니다.

저장하지 않은 figma.com, docs.google.com, notion.so 등의 페이지도 인식됩니다. 프로젝트 폴더 안의 파일(Markdown, Mermaid)은 리뷰 대상 패널의 파일 목록에서 리뷰합니다.

## 다른 사이트를 참고로 쓰기

경쟁사 사이트나 디자인이 마음에 드는 페이지를 녹화하면서 무엇을 가져올지 말할 수도 있습니다("이걸 본보기로 해", "이 검은 배경은 별로야"). 그 사이트는 고칠 수 없으므로 에이전트도 절대 고치려 하지 않습니다. 이런 지적 사항은 내 앱을 위한 참고로 다룹니다.

  1. 그 사이트를 대상으로 추가하고 검토 대상에서 참고를 고릅니다. 이름에 "competitor"나 "reference"가 들어 있으면(예: Competitor: Acme) 자동으로 골라집니다.
  2. 평소처럼 녹화합니다. 원하면 같은 녹화 안에서 그 사이트와 내 앱을 오가도 됩니다.

참고 사이트에서 녹화한 지적 사항은 지적 사항 목록에 참고로, feedback.md에 Kind: reference로 표시됩니다. 지적 사항마다 에이전트는 다음과 같이 처리합니다.

  • 마음에 든 점은 내 앱의 알맞은 곳에 도입하고, 어디에 도입했는지 적습니다.
  • 마음에 들지 않은 점을 내 앱이 하고 있지 않은지 확인하고, 하고 있다면 내 앱을 고칩니다.
  • 살릴 것이 없는 감상이면 아무것도 바꾸지 않고, "외부 사이트라 대응 불필요(참고)" 같은 메모를 붙여 지적 사항을 확인 대기로 설정합니다.

에이전트는 외부 사이트를 절대 편집하지 않고, 멈춰서 묻지도 않습니다. 종류를 고르지 않아도, 대상 이름에 "competitor"나 "reference"(또는 競合 / 参考)가 들어 있거나, 저장하지 않은 사이트에서 녹화했고 그 호스트가 프로젝트의 어떤 앱 URL과도 맞지 않으면 그 지적 사항은 참고로 다뤄집니다. localhost와 사설 주소는 외부로 보지 않으며, 앱 URL을 하나도 저장하지 않은 프로젝트에서는 이런 추측을 하지 않습니다.
