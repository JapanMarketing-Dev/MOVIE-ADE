发送给 Agent 在内置终端中运行你的编码 Agent，一键把审查交给它。Claude Code 和 Codex 是常见的例子，但下面列表中的任何 Agent 都可以使用，你自己添加的 CLI 也可以。你也可以为在其他地方运行的 Agent 复制指令，或者把审查发布到 GitHub。 ## 审查反馈

反馈 标签页中的每张卡片支持：

  • 直接编辑标题和请求
  • 切换 发送 / 不发送
  • 观看录制（跳转到对应时间）和 替换图片（选择另一帧）
  • 确认 / 标记为需确认、与下一条合并、删除

按进度筛选 按状态显示或隐藏反馈（例如 仅显示 等待你检查的反馈）；全部显示 会清除筛选。

顶部有 撤销、打开文件夹、拷贝给 Agent、发送到 GitHub / GitLab、整理 和 发送给 Agent。没有成为反馈的语音列在 已排除的语音 下，点击 恢复为反馈 可以把它找回来。

{{shot:findings|反馈标签页}} ## 在内置终端中运行 Agent

打开项目时，Ferret 会为 设置 → Agent → 打开项目时启动 中的每个 Agent 各启动一个终端标签页，位于项目文件夹中。默认是 Claude Code 和 Codex，启动时跳过权限确认，并开启 Claude in Chrome：

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

你也可以改为从支持列表中任选 Agent（按你选择的顺序启动），或者一个都不选。

你自己打开的 Agent 也以同样的方式启动。Ferret 还会为 Claude Code 和 Codex 把项目文件夹标记为受信任，因此它们不会询问该文件夹。若要以普通模式启动（在信任文件夹、编辑文件或运行命令之前都会询问），请关闭 设置 → Agent → 启动 Agent 时跳过权限确认。每个 Agent 的命令和参数位于 设置 → Agent（命令）和 settings.json（agents.launch）中，并按你写的原样使用。要在不使用 Claude in Chrome 的情况下启动 Claude Code，请在那里删除 --chrome。如果参数中已经选择了权限模式（例如 --permission-mode plan，或 Codex 的 --sandbox workspace-write），就不会再添加跳过确认的参数。

如果没有选择任何 Agent，则会打开普通的 shell。+ 菜单可以打开 新建终端、在新标签页中启动你的任意 Agent，或跳转到 Agent 设置…。它的搜索框还能查找标签页、已保存的 URL 和文件。

把文件拖放到终端。从访达（Windows 上为文件资源管理器，Linux 上为文件管理器）把文件、文件夹或图片拖到终端窗格上，它们的路径会以空格分隔输入到该窗格中，不会按 Enter。Agent 运行时也是如此：Claude Code 会把拖入的图片路径当作图片读取。从 文件 拖出的行（选中后可一次拖多个）也同样处理：终端位于项目文件夹中时，路径相对于项目文件夹；用 cd 切换到其他位置后则为绝对路径。包含空格或其他特殊字符的路径会按 shell 加上引号：zsh 和 bash 中为 '…'，命令提示符中为 "…"，PowerShell 中为 '…'。

标签页会显示 Agent 的状态：运行中、等待输入、完成（未读）、空闲。完成（未读） 表示在你查看其他标签页时 Agent 已完成；打开该标签页后会变为 空闲。侧边栏也会以同样的方式标记每个项目，无需切换项目就能看到：Agent 运行时显示移动的条形，有 Agent 在等你时显示问号，该项目的 Agent 都已完成而你还没打开标签页时显示对勾。

通知。打开 设置 → Agent → Agent 完成或需要我确认时通知我 后，当项目中的所有 Agent 都已完成，或某个 Agent 正在等待授权或回答时，会收到系统通知。正在查看的标签页不会显示任何通知。点击通知即可切换到该项目并打开该标签页。

## 发送给 Agent / 拷贝给 Agent {{clip:send|在反馈标签页中按“发送给 Agent”，发送给内置终端中的 Agent。}}
  1. 点击 发送给 Agent。默认（自动（当前标签页或正在运行的 Agent））会发送给当前终端标签页中的 Agent，或某个正在运行的 Agent。使用按钮旁边的箭头（选择要发送给的 Agent）可以指定某个 Agent 或标签页。
  2. Ferret 会把指令写入 Agent 的输入框并提交。在终端中查看进度。

如果没有正在运行的 Agent，Ferret 会先启动一个，并在它就绪后立即发送。当 Agent 正在等待权限确认的回答时，不会发送任何内容。请先在终端中回答。

拷贝给 Agent 会把同样的指令放到剪贴板，供在其他地方（另一个终端、IDE 或应用）运行的 Agent 使用。只有切换为 发送 的反馈会被处理。视频永远不会包含在内。

## 用判定模型做验收检查 {{clip:verify|Agent 修复反馈，并用判定模型逐条检查，直到全部通过。}}

开启后，你的编码 Agent 会在报告完成前，逐条对照反馈检查自己的工作。Ferret 本身不做任何判断：它给 Agent 提供一个判定模型（任何兼容 System One 的 API），并在 feedback.md 中要求它循环执行，直到每条反馈都通过。

  1. Agent 实现这些反馈。
  2. 对每条反馈，它截取一张 AFTER 截图（与 BEFORE 静帧相同的视口和页面状态），然后向判定模型发送一个请求，包含反馈文本、“完成条件”一行以及 BEFORE/AFTER 图片。
  3. 当 P(done) 不低于阈值（默认 0.7）且选择为 done 时，该反馈通过。Agent 修复其余反馈，并在每一轮重新判定所有反馈；只有当所有反馈在同一轮中都通过时才停止，或者因为必须说明的正当理由而停止：API 无法访问、某条反馈超出范围，或某条反馈卡住且分数不再变化。
  4. 最终的“已完成 / 未完成”列表包含每条反馈的分数和轮数。

在 设置 → 判定模型 中进行设置，并开启 在 Agent 指令中加入判定模型检查。预设只会填写字段；每个字段都可以编辑，自定义 可用于任何兼容的 API。

使用 Ollama 时，先安装它（Clef / Clef Flash 需要 0.35.1 或更高版本），然后在终端中拉取模型。Ferret 不会运行安装程序：

ollama pull clef-flash

密钥来自密钥字段（与你的其他 API 密钥一起保存）、你指定的环境变量（应用的环境、项目的 .env 或 ~/.ferret/.env），或 settings.json 中的 apiKey。额外请求头可以用 ${VAR} 从环境变量读取值。

密钥如何不进入提示词

Agent 永远看不到你的密钥。Ferret 在 127.0.0.1 上运行一个本地中继，并给每个终端提供 FERRET_DECISION_URL（中继地址，带有每个终端独立的令牌）、FERRET_DECISION_MODEL 和 FERRET_DECISION_IMAGES（在一个版本内，旧的 MOVIE_ADE_DECISION_* 名称也会一并设置）。中继添加密钥和请求头后原样转发请求，因此提示词、feedback.md 和 Agent 的对话记录中都不含机密信息。更改设置后新打开的终端会使用新设置。

Cloudflare 与 System One 文档有两处不同（已对照实际 API 确认）：图片必须是 data URI（data:image/jpeg;base64,…，否则返回 422 "image must be an embedded base64 data URI"），并且应答被包装为 { "result": { … }, "success": true }（错误返回为 { "success": false, "errors": [ … ] }）。Cloudflare 预设会把 图片编码 设为 data URI，Agent 通过 FERRET_DECISION_IMAGE_FORMAT 获得该值，指令也会告诉它们在存在 .result 时读取它。中继对两个方向都原样传递。若要使用 Global API Key 而不是 API 令牌，请把 认证 设为 无密钥，并添加请求头 X-Auth-Email: ${CLOUDFLARE_EMAIL} 和 X-Auth-Key: ${CLOUDFLARE_API_KEY}。

只有 Clef 和 Clef Flash 能读取图片。使用仅文本的模型时，请关闭 发送 BEFORE/AFTER 图片；这时 Agent 只根据文本判定，可靠性较低。

Ollama 与大图片

Ollama 0.35.0 把 /v1/systemone 请求限制在 64 KiB，因此带截图的请求会以 HTTP 413 失败。指令会告诉 Agent 把两张图片都缩小到宽度不超过 1024px 的 JPEG（质量约 70）。如果仍然得到 413，请把 Ollama 更新到 0.35.1 或更高版本，或改用 Cloudflare Workers AI。

## 底栏中的 API 用量

判定调用都经过中继，因此 Ferret 可以统计它们。底栏中 Agent 用量表旁边的项目会显示判定模型以及今天的调用次数、token 数和费用（例如 clef-flash · 42 calls · 18.3k tok）。点击它可以查看今天、本月、按项目、按模型和按类型（判定 / 转写 / 整理）的统计，以及最近 50 次调用。

只有在 API 报告费用时（Vercel AI Gateway 会报告），或你在 设置 → 判定模型 中设置了每 100 万 token 的价格时，才会显示费用；否则显示“—”。只记录元数据（时间、项目、模型、状态、延迟、大小、图片数、token 数、费用），绝不记录图片、文本或密钥，记录保存在 ~/.ferret/usage/decision-YYYY-MM.jsonl，每月一个文件。

## 发送到 GitHub 或 GitLab（Issue / PR 或 MR 评论）

发送到 GitHub 会把审查发布为一个新 Issue，或发布为你某个打开的 pull request 上的评论。认证交给 GitHub CLI 处理。Ferret 从不读取或保存令牌。

  1. 安装 gh：brew install gh（macOS）、winget install --id GitHub.cli（Windows），或参阅 cli/cli。
  2. 设置 → GitHub / GitLab → 在终端中登录 会在内置终端中运行 gh auth login --web -h github.com。
  3. 点击 发送到 GitHub，选择 新建 Issue 或某个 PR，然后检查 标题 和 正文（可编辑）。
  4. 勾选确认复选框，然后点击 创建 Issue 或 发表评论。

细节：

  • 仓库取自 git remote get-url origin。
  • Ferret 会运行 gh issue create --repo … --title … --body-file - 或 gh pr comment <n> --repo … --body-file -。
  • 正文是去掉图片行的 feedback.md（不上传图片），最多 60,000 个字符。
  • 候选 PR 是你自己打开的 PR（最多 30 个）。

如果设置了 GH_TOKEN 或 GITHUB_TOKEN，gh 会优先使用它，设置面板会对此发出警告。

GitLab。当 origin 是 GitLab 项目（gitlab.com 或自托管的 GitLab）时，同一个按钮会通过 GitLab CLI（glab）发送到 GitLab：新建 Issue，或在你某个打开的 merge request 上发表评论。通过 设置 → GitHub / GitLab 登录，它会在内置终端中运行 glab auth login（自托管 GitLab 会带上 --hostname）。Ferret 从不读取或保存令牌，并会在设置了 GITLAB_TOKEN 时发出警告。

点星提示。在你第一次 发送给 Agent 之后，以及完成的审查达到 3、10 和 30 次时，Ferret 可能会请你在 GitHub 上为它点星。它最多询问 3 次，每次至少间隔 3 天，并且录制时从不询问。在 GitHub 上点星 会通过你自己的 gh 登录点星（如果没有 gh，则打开 GitHub），不再询问 会停止提示。你也可以通过 帮助 → 在 GitHub 上为 Ferret 点星 点星。
