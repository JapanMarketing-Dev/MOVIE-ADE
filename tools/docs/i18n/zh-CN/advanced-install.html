## 验证下载（已签名的 SHA256SUMS）

每个版本都附有 SHA256SUMS 文件及其签名 SHA256SUMS.sig。签名使用 Ferret 发布密钥生成，该密钥与下载服务器分开保管，因此即使下载服务器上的安装程序被篡改，也无法附带有效的签名。公钥不从下载服务器获取：请从代码仓库获取（build/release-signing/allowed_signers），或从这里复制：

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

其指纹为 SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ。GitHub 上的每个版本也附有相同的文件。先用 ssh-keygen（macOS、Windows 10 及更高版本和 Linux 均自带）验证签名，再将下载文件的哈希值与已签名的列表进行比对：

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

如果 ssh-keygen 没有输出 Good "ferret-release" signature，或者哈希值不在列表中，请停止使用该文件。Ferret 的 检查更新 会使用内置于应用中的密钥执行同样的检查，不会提供签名不匹配的版本。在 macOS 上，你还可以用 spctl -a -vv /Applications/Ferret.app 检查 Developer ID 签名和公证。对于 0.3.0 及更早的版本，请与 releases/<version>/manifest.json 中的哈希值进行比对。

## 旧版 macOS 版本

对于 0.2.0 build 2 及更早的版本：如果 macOS 提示无法验证开发者，请关闭对话框，打开 系统设置 → 隐私与安全性，点击 Ferret 提示旁边的 仍要打开，然后点击 打开 确认。如果提示应用“已损坏”，请移除隔离属性：

xattr -dr com.apple.quarantine /Applications/Ferret.app
## 从源码构建

需要 Node.js 20+（CI 和本地开发使用 22）、pnpm 和 git。

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

打包安装程序（输出到 dist/release/，配置在 electron-builder.config.cjs 中）。Linux 版只能在 Linux 上构建。

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

build:<os>:dev 脚本只生成未打包的应用（--dir），用于本地测试时更快。

在 Windows 上，pnpm install 会使用 node-pty 自带的预编译二进制文件，而不是重新构建（重新构建需要 Visual Studio C++ 生成工具）。设置 ADE_FORCE_NATIVE_REBUILD=1 可强制重新构建。

如果终端提示无法加载 node-pty，请运行 pnpm rebuild:native。

## 更新

Ferret 会在启动时、每 6 小时以及点击 检查更新 时（页脚 → 更新）检查新版本。它从下载服务器（R2）获取 latest.json，并用内置在应用中的发布密钥校验该版本 SHA256SUMS 的签名。签名不匹配的版本不会提示。

发现新版本后，Ferret 会在后台下载，并在 更新 中显示进度。只有当下载文件的大小和 SHA-256 与已签名的列表一致时才会使用。之后 更新 和页脚会出现 重新启动并更新。点击后会重新启动并进入新版本。如果终端中有 Agent 正在工作或正在录制，Ferret 会先询问；到目前为止的录制会在重新启动前保存。

安装方式下载的内容安装方式
macOSFerret-<version>-mac-<arch>.zip，列在 UPDATE-SHA256SUMS 中，并用同一发布密钥签名交给 macOS 的更新机制（Squirrel.Mac），它还会确认新应用使用相同的 Developer ID 签名；在 Ferret 重新启动时替换
Windows安装程序（.exe）在 Ferret 重新启动时以无窗口方式运行，完成后打开新版本
Linux（AppImage）新的 .AppImage替换你启动的 AppImage，然后打开新版本
Linux（deb）.deb打开安装程序 会把它保存到下载文件夹，并用你的软件安装程序打开

如果只想在自己选择时下载，请在 更新 中关闭 自动下载新版本（或在 settings.json 中设置 "autoUpdate": false），出现新版本时再点击 下载。开发版（pnpm dev）不会在后台下载；下载 会把校验过的安装程序保存到下载文件夹。
