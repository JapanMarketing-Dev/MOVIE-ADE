项目与 URL 项目就是一个文件夹（通常是仓库的根目录）。每个项目都保存自己的 URL，因此本地、开发和生产环境只需一次点击即可切换。 ## 添加项目
  1. 使用 文件 → 打开项目文件夹…（{{keys:Mod+O}}）、侧边栏中的 添加项目，或标题栏项目菜单中的 添加项目…。
  2. 选择项目的来源：
    • 在这台电脑上：选择一个文件夹。
    • 从 GitHub / GitLab 克隆：从你的仓库中选择一个（通过你的 gh 或 glab 登录列出），或粘贴 URL，再选择父文件夹，Ferret 会克隆并打开它。
    • 通过 SSH 打开：从 ~/.ssh/config 中选择一个主机。终端和 Agent 在远程机器上运行；审查保存在这台电脑上。

也可以从访达（Windows 上为文件资源管理器，Linux 上为文件管理器）拖动文件夹，放到侧边栏的项目列表上。拖动时列表会高亮显示。请放下文件夹而不是文件；放下多个文件夹时，会逐个添加并打开最后一个。

名称默认是文件夹名。添加一个已登记的文件夹时，会直接打开它（在 macOS 和 Windows 上，路径比较不区分大小写）。在侧边栏菜单中可以对项目执行 重命名 或 从列表中移除。移除绝不会删除文件夹。

要调整列表顺序，可以上下拖动项目（会出现一条线标出放置位置），也可以在选中的项目上按 {{keys:Alt+Up}} / {{keys:Alt+Down}}，或使用其菜单中的 上移 / 下移。顺序会被保存，重启后依然保留。

评审搜索框旁边的筛选按钮还可以设置 项目排序：手动（拖动顺序）、活动优先（Agent 正在等你、正在工作或刚完成的项目排在前面）、最近使用、名称 或 添加时间。在其他排序下拖动项目时，当前显示的顺序会成为手动顺序，排序也会切换为 手动（拖动顺序）。点击项目行上的星标，或使用菜单中的 加星标，可让项目在任何排序下都固定在列表顶部；选择 仅显示星标 会隐藏其他项目。星标和排序在重启后依然保留。

终端在项目文件夹中打开，审查保存在 <project>/.ferret/ 下。

## 保存 URL
  1. 在内置浏览器中打开页面。
  2. 点击浏览器工具栏中的 +（保存当前 URL）。当前 URL 会预先填好。
  3. 输入 名称，然后点击 保存。

每个保存的 URL 在 审查内容 下都有一个类型：应用（你正在开发的应用）、设计（Figma、Penpot、Canva、原型）、文档 / 规格（Google Docs、Notion、Confluence、GitHub 上的 Markdown 规格、PDF）或 参考（竞品或其他你无法修改的外部网站）。类型会根据 URL 和名称推断，你也可以更改。请参阅不只审查代码，也审查设计和文档和把其他网站作为参考。

只接受 http:// 和 https:// URL。对于应用 URL，如果保留建议的名称，它会根据主机推断：

在反馈模式下，右侧的 审查对象 面板会列出当前项目中所有可以审查的内容。切换对象不会停止录制。可以用 显示 → 显示 / 隐藏审查对象（{{keys:Mod+Shift+K}}）或 隐藏面板 来切换面板。

  • 目标：项目中保存的 URL。每个 URL 下方是你在该站点访问过的页面树。访问过但未保存的站点会作为单独的分组显示。
  • 文件：项目文件夹。文件以预览方式打开（渲染 Markdown 和 Mermaid，其他文本为只读），因此也可以审查文档。铅笔图标（在编辑器中打开）会在编辑器中打开它。

筛选对象 会同时筛选目标、页面和文件，模糊匹配方式与 转到文件… 相同。在列表中，按 ↑ ↓ Enter 或 1–9 切换对象。打开 URL… 用于临时打开一个 URL，保存到项目 URL 会把它保存下来。

目标来自 settings.json 中的 projects[].urls（参见示例）。每个条目需要一个 url、一个 launchCommand（在终端中运行，例如用来启动桌面应用）或一个 windowMatch（要录制的窗口），还可以带一个 purpose（app、design、doc 或 reference）。在录制前选择窗口类目标，会把它设为录制来源；在录制中选择，则会把该窗口加入录制并显示它（见同时录制多个窗口）。访问过的页面按项目记住，仅保存在这台机器上（最多 200 个）。

## 打开和切换环境

点击保存的 URL 即可打开。如果当前页面位于另一个已保存的 URL 下，Ferret 会保留路径、查询参数和哈希，只替换源（origin）。例如在 http://localhost:3000/pricing?plan=pro 上点击 prd，会打开 https://example.com/pricing?plan=pro。

与当前页面匹配（最长前缀）的标签会高亮显示。右键点击标签或使用其铅笔图标，可以编辑或 删除 它。项目打开时如果没有上次的 URL，会载入它的第一个已保存 URL。

标签按类型分组：先是应用 URL，然后是设计，接着是文档，最后是参考，每种类型之间有分隔线和图标。切换到设计、文档或参考（或从它们切换回来）时，会按原样打开保存的 URL，不会沿用路径。

## 不只审查代码，也审查设计和文档

反馈不一定针对代码。任何能在内置浏览器中打开的内容，都可以用同样的方式录制并用画笔标注：Figma 或 Penpot 设计、原型、Google Docs 或 Notion 中的规格、GitHub 上的设计文档、PDF。在审查之前，把这些 URL 保存到项目中，和 local、dev 放在一起。

  1. 从侧边栏菜单打开 编辑项目…（或点击浏览器工具栏中的 +），然后点击 添加目标。
  2. 粘贴 URL。figma.com 链接会成为 设计，docs.google.com 或 notion.so 链接会成为 文档 / 规格，名称分别为 Figma 或 Spec。如果推断有误（例如放在你自己服务器上的原型），请在 审查内容 下更改类型。
  3. 打开该目标；如果网站需要登录，在内置浏览器中登录一次即可。内置浏览器会在多次启动之间保留 Cookie，因此你会保持登录状态。
  4. 照常录制：一边说话，一边指点，在设计或文档上画出标注。

在设计或文档上录制的反馈，会在 反馈 标签页和 feedback.md 中标上对应的类型，发送给 Agent 的指令也会说明这一点。于是 Agent 会修改设计或文档，而不是代码：

  • 如果文档就在项目中（Markdown 规格、ADR），Agent 会编辑该文件。
  • 如果 Agent 无法编辑它（Figma 文件、Google 文档），Agent 不会停下来问你：它会把这条反馈设为 待检查，并用一行说明写明需要做的具体修改，由你来应用或转交给他人。

示例：在 Google Docs 中阅读价格规格时，你圈出套餐表并说“Pro 套餐现在是 9,800 日元，不是 8,800”。feedback.md 会把这条反馈列在 Spec 目标下，并标注 Kind: document；Agent 会给出规格中修正后的句子，而不会去改价格页面的代码。如果在同一次录制中同时录下规格和运行中的应用，反馈会按目标分开，Agent 就可以先更新规格，再更新实现它的代码。

figma.com、docs.google.com、notion.so 等主机上未保存的页面同样能被识别。项目文件夹中的文件（Markdown、Mermaid）可以在 审查对象 面板的 文件 列表中审查。

## 把其他网站作为参考

你也可以录制竞品的网站，或任何你喜欢其外观的页面，并说出要从中借鉴什么（“以这个为样板”“这个黑色背景不行”）。你无法修改那个网站，所以 Agent 也绝不会尝试修改：它会把这些反馈当作你自己应用的参考。

  1. 把该网站添加为目标，并在 审查内容 下选择 参考。名称中含有“competitor”或“reference”（例如 Competitor: Acme）时会自动选好。
  2. 照常录制；如有需要，也可以在同一次录制中在该网站和你的应用之间切换。

在参考网站上录制的反馈，会在 反馈 标签页中标为 参考，在 feedback.md 中标为 Kind: reference。对每条这样的反馈，Agent 会：

  • 把你喜欢的地方用在你的应用中合适的位置，并注明在哪里采用；
  • 检查你的应用是否也有你不喜欢的做法，如果有，就修正你的应用；
  • 如果某条评论没有可以落实的内容，就不做任何修改，把这条反馈设为 待检查，并附上类似“外部网站，无需处理（参考）”的说明。

Agent 绝不会修改外部网站，也绝不会停下来问你。即使没有选择类型，以下情况的反馈也会被当作参考：目标名称中含有“competitor”或“reference”（或 競合 / 参考），或者反馈是在一个未保存的网站上录制的，而该网站的主机与项目中任何应用 URL 都不匹配。localhost 和私有地址绝不会被视为外部网站；没有保存任何应用 URL 的项目不会进行这种推断。
