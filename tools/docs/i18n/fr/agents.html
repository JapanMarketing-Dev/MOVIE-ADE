Envoyer aux agents Lancez votre agent de code dans le terminal intégré et confiez-lui une relecture en un clic. Claude Code et Codex sont les exemples habituels, mais tout agent de la liste ci-dessous fonctionne, de même qu'une CLI que vous ajoutez vous-même. Vous pouvez aussi copier l'instruction pour un agent qui tourne ailleurs. ## Relire les remarques

Chaque carte de l'onglet Remarques permet :

  • de modifier directement le titre et la demande
  • de basculer entre Envoyer et Ne pas envoyer
  • Voir l'enregistrement (se place à ce moment-là) et Remplacer l'image (choisir une autre image de la vidéo)
  • Valider, Supprimer

Filtrer par avancement affiche ou masque les remarques selon leur statut (par exemple Seulement celles qui attendent votre relecture) ; Tout afficher retire le filtre.

Pour réordonner les remarques, faites glisser la poignée à gauche du titre d'une carte, ou sélectionnez la poignée et appuyez sur ↑ / ↓. Les numéros, feedback.md et ce que vous envoyez à l'agent suivent le nouvel ordre. Quand un filtre est actif, l'ordre change parmi les remarques visibles et les remarques masquées gardent leur place. Quand une revue porte sur plusieurs pages ou fichiers, les remarques se déplacent au sein de leur propre groupe. Trier les remarques, dans l'en-tête, bascule entre Manuel (ordre de glisser), Moment de l'enregistrement et Avancement (non commencées d'abord, terminées à la fin) ; trier par avancement enregistre cet ordre comme ordre manuel.

L'en-tête contient Annuler, Ouvrir le dossier, Copier pour l'agent, Organiser et Envoyer à l'agent. Les paroles qui ne sont pas devenues des remarques sont listées sous Paroles exclues, où Restaurer en remarque les récupère. Les paroles sans mot porteur de sens ne deviennent jamais des remarques et figurent aussi dans cette liste : les phrases que la transcription invente parfois à partir du silence, comme « Shh. » ou « Merci d’avoir regardé », les mots de remplissage comme « euh », et un « OK » ou « oui » isolé sans trait de stylo.

{{shot:findings|L'onglet Remarques}} ## Lancer des agents dans le terminal intégré

À l'ouverture d'un projet, Ferret ouvre un onglet de terminal par agent choisi dans Réglages → Agents → Démarrer à l'ouverture d'un projet, dans le dossier du projet. Par défaut, ce sont Claude Code et Codex, démarrés sans demandes d'autorisation et avec Claude in Chrome activé :

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

Vous pouvez choisir à la place n'importe quels agents de la liste des agents pris en charge (ils démarrent dans l'ordre où vous les choisissez), ou aucun.

Les agents que vous ouvrez vous-même démarrent de la même façon. Ferret marque aussi le dossier du projet comme fiable pour Claude Code et Codex, qui ne posent donc pas de question sur le dossier. Pour les démarrer dans leur mode normal, où ils demandent avant de faire confiance à un dossier, de modifier des fichiers ou d'exécuter des commandes, désactivez Réglages → Agents → Démarrer les agents sans demandes d'autorisation. La commande et les arguments de chaque agent se trouvent sous Réglages → Agents (Commande) et dans settings.json (agents.launch), et sont utilisés tels que vous les écrivez. Retirez-y --chrome pour démarrer Claude Code sans Claude in Chrome. Si les arguments choisissent déjà un mode d'autorisation (par exemple --permission-mode plan, ou --sandbox workspace-write pour Codex), l'option d'ignorance n'est pas ajoutée.

Si aucun agent n'est sélectionné, un shell simple s'ouvre. Le menu + ouvre un Nouveau terminal, lance l'un de vos agents dans un nouvel onglet ou mène à Réglages des agents…. Son champ de recherche trouve aussi les onglets, les URL enregistrées et les fichiers.

Déposer des fichiers dans le terminal. Faites glisser des fichiers, des dossiers ou des images depuis le Finder (l'Explorateur de fichiers sous Windows, votre gestionnaire de fichiers sous Linux) sur un panneau de terminal : leurs chemins y sont saisis, séparés par des espaces, sans appuyer sur Entrée. Cela fonctionne de la même façon pendant qu'un agent tourne : Claude Code lit le chemin d'une image déposée comme une image. Les lignes glissées depuis Fichiers (plusieurs à la fois si vous les sélectionnez) fonctionnent de la même façon : le chemin est relatif au dossier du projet tant que le terminal s'y trouve, et absolu après un cd ailleurs. Les chemins contenant des espaces ou d'autres caractères spéciaux sont mis entre guillemets pour le shell : '…' dans zsh et bash, "…" dans l'invite de commandes et '…' dans PowerShell.

Les onglets affichent l'état de l'agent : En cours, En attente d'une saisie, Terminé (non lu), Inactif. Terminé (non lu) signifie que l'agent a terminé pendant que vous regardiez un autre onglet ; l'état passe à Inactif dès que vous ouvrez cet onglet. La barre latérale signale chaque projet de la même façon, pour que vous le voyiez sans changer de projet : des barres animées pendant qu'un agent tourne, un point d'interrogation quand l'un d'eux vous attend, et une coche quand les agents du projet ont terminé et que vous n'avez pas encore ouvert l'onglet.

Notifications. Activez Réglages → Agents → Me prévenir quand les agents terminent ou ont besoin de moi pour recevoir une notification système quand tous les agents d'un projet ont terminé, ou quand un agent attend une autorisation ou une réponse. Rien ne s'affiche pour l'onglet que vous regardez. Cliquez sur la notification pour passer à ce projet et ouvrir l'onglet.

{{clip:terminals|Faire glisser des onglets et des panneaux de terminal pour les diviser, les déplacer et les remettre en onglets.}}

Faire glisser pour diviser. Faites glisser un onglet, ou un panneau par sa poignée (affichée dès qu'un onglet est divisé), et déposez-le :

  • sur le quart extérieur d'un bord de panneau : Diviser à gauche / Diviser à droite / Diviser en haut / Diviser en bas
  • au centre d'un panneau : Ouvrir dans un onglet (un panneau quitte sa division et devient son propre onglet)
  • sur la fine bande qui entoure toute la zone du terminal : Diviser toute la zone à gauche, etc. (lorsqu'il y a au moins 2 panneaux)
  • sur la barre d'onglets : Placer ici comme onglet

Les processus continuent de tourner pendant le déplacement, et un onglet laissé vide se ferme. Divisions au clavier :

## Retrouver les terminaux après un redémarrage

Quand Ferret se ferme, il mémorise les onglets de terminal de chaque projet : leur ordre et leurs divisions, le dossier dans lequel chacun a été ouvert, l’agent et le compte utilisés, et jusqu’à 2 000 lignes de chaque écran. Au prochain démarrage de Ferret, les onglets reviennent dans le même ordre. L’ancien texte s’affiche d’abord, puis une ligne grisée comme — Suite de la session précédente (2026-10-05 14:30) —, puis un nouveau shell démarre dans le même dossier.

Les onglets d’agent redémarrent avec leur conversation : Claude Code avec --continue et Codex avec resume --last, qui reprennent la conversation la plus récente de ce dossier. Si plusieurs onglets exécutent le même agent dans le même dossier avec le même compte, seul le premier la reprend et les autres repartent de zéro : deux onglets ne reprennent jamais la même conversation. Si Claude Code n’a aucune conversation dans ce dossier, ou si le projet est sur un hôte SSH, il démarre normalement.

Rouvrir un terminal fermé. Terminal → Rouvrir le terminal fermé ({{keys:Mod+Shift+T}} quand un terminal a le focus) rétablit le dernier onglet ou panneau fermé dans ce projet, avec son texte, et reprend son agent de la même façon. Les 10 derniers terminaux fermés sont conservés, y compris d’un démarrage à l’autre.

L’historique est enregistré en texte brut, sans couleurs, dans le dossier de données de Ferret (terminal-restore.json, lisible par vous seul), jamais dans le projet. Les onglets de connexion ouverts depuis Ajouter un compte et les commandes ponctuelles ne sont pas conservés. Pour ne plus l’enregistrer, désactivez Réglages → Agents → Enregistrer l’historique du terminal et le restaurer ; ce qui a été enregistré est aussi supprimé. Supprimer l’historique enregistré, juste à côté, le supprime à tout moment.

Ferret n'est pas lié à un seul agent. Il reconnaît les agents de code ci-dessous : il peut les démarrer, les détecter dans un terminal pour Envoyer à l'agent et indiquer s'ils sont installés. Réglages → Agents les liste avec Installé / Introuvable, un bouton Installer lorsque l'éditeur publie un installeur en une ligne, ainsi que la commande et les arguments de chacun.

Absent de la liste ? Les agents qui tournent en dehors de Ferret peuvent utiliser Copier pour l'agent.

  • Organiser : s'exécute avec votre connexion Claude Code ou Codex, ou avec une API de LLM que vous configurez.
## Envoyer à l'agent / Copier pour l'agent {{clip:send|De l'onglet Remarques à l'agent du terminal intégré avec Envoyer à l'agent.}}
  1. Cliquez sur Envoyer à l'agent. Par défaut (Auto (onglet actuel ou agent en cours)), l'envoi part vers l'agent de l'onglet de terminal actuel, ou vers un agent en cours d'exécution. Utilisez la flèche à côté du bouton (Choisir l'agent destinataire) pour choisir un agent ou un onglet précis.
  2. Ferret écrit l'instruction dans la saisie de l'agent et la valide. Suivez l'avancement dans le terminal.

Si aucun agent ne tourne, Ferret en démarre un d'abord et envoie dès qu'il est prêt. Si l'agent est en train de travailler, l'instruction est quand même envoyée et l'agent la lit après sa tâche en cours. Rien n'est envoyé tant que l'agent attend une autorisation ou une réponse. Répondez d'abord dans le terminal.

Copier pour l'agent place la même instruction dans le presse-papiers pour un agent qui tourne ailleurs (un autre terminal, un IDE ou une application). Seules les remarques réglées sur Envoyer sont concernées. La vidéo n'est jamais incluse.

## Vérification d'acceptation avec un modèle de décision {{clip:verify|L'agent corrige les remarques et vérifie chacune avec le modèle de décision avant que vous ne les regardiez.}}

Activez cette option et votre agent de code vérifie son propre travail une fois par rapport à chaque remarque avant que vous ne regardiez. Ferret ne juge rien lui-même : il fournit à l'agent un modèle de décision (n'importe quelle API compatible System One) et lui explique, dans feedback.md, comment l'utiliser. Le modèle de décision est la propre vérification de l'agent, jamais une question pour vous : l'agent ne vous demande rien. Vous comparez seulement AVANT et APRÈS et appuyez sur OK ou NG.

  1. L'agent implémente les remarques.
  2. Pour chaque remarque, il prend une capture d'écran APRÈS (même viewport et même état de la page que l'image AVANT) et envoie au modèle de décision une requête avec le texte de la remarque, sa ligne « Terminé quand » et les images AVANT/APRÈS.
  3. Le modèle de décision est appelé au plus une fois par remarque à chaque envoi de remarques à l'agent. Il n'y a ni deuxième évaluation ni boucle : un modèle qui ne dit jamais « done » ne peut pas occuper l'agent indéfiniment.
  4. L'agent lit ce résultat unique. Une remarque passe lorsque P(done) atteint au moins le seuil (0,7 par défaut) et que le choix est done, et vous parvient telle quelle. Sinon, si le résultat montre un écart clair que l'agent peut corriger, il peut améliorer la correction une fois de plus et refaire la capture APRÈS, sans réévaluer.
  5. Dans les deux cas, l'agent passe la remarque à À vérifier avec son APRÈS, ce score unique et au plus une note d'une ligne. Une remarque hors périmètre ou une API de décision injoignable n'arrêtent pas le travail : la remarque passe à À vérifier sans score.
  6. Dans Remarques, chaque remarque qui vous attend affiche AVANT, APRÈS et le score comme éléments d'appréciation. OK la marque comme terminée ; NG avec un commentaire la renvoie à l'agent comme une nouvelle demande, où elle est de nouveau évaluée une fois. La liste finale Terminé / Non terminé de l'agent dans le terminal indique le score de chaque remarque et si la correction a été améliorée une fois de plus.

Configurez-le dans Réglages → Modèle de décision et activez Ajouter la vérification par modèle de décision aux instructions de l'agent. Les préréglages ne font que remplir les champs ; chaque champ reste modifiable, et Personnalisé fonctionne avec n'importe quelle API compatible.

Le préréglage OpenAI utilise la Decisions API d'OpenAI, qui a son propre format de requête (input, une liste de questions et answers). Les agents envoient toujours le format System One au relais : pour ce préréglage uniquement, le relais convertit la requête (les images BEFORE/AFTER deviennent des data URL input_image) et reconvertit les réponses, si bien que les instructions de l'agent ne changent pas. Il utilise votre clé d'API OpenAI, la même que pour la transcription. OpenAI ne facture que les tokens d'entrée (0,10 $ par million).

Pour Ollama, installez-le (0.35.1 ou ultérieur pour Clef / Clef Flash) et téléchargez le modèle dans un terminal. Ferret n'exécute pas d'installeur :

ollama pull clef-flash

Les clés proviennent du champ de clé (enregistré avec vos autres clés d'API), d'une variable d'environnement que vous nommez (l'environnement de l'application, le .env du projet ou ~/.ferret/.env), ou de apiKey dans settings.json. Les en-têtes supplémentaires peuvent lire des valeurs dans des variables d'environnement avec ${VAR}.

Comment la clé reste hors des prompts

Les agents ne voient jamais votre clé. Ferret exécute un relais local sur 127.0.0.1 et fournit à chaque terminal FERRET_DECISION_URL (le relais, avec un jeton propre à chaque terminal), FERRET_DECISION_MODEL et FERRET_DECISION_IMAGES (pendant une version, les anciens noms MOVIE_ADE_DECISION_* sont aussi définis). Le relais ajoute la clé et les en-têtes et transmet la requête sans la modifier : les prompts, feedback.md et les transcriptions des agents ne contiennent donc aucun secret. Le jeton de chaque terminal permet 500 appels, 30 par minute, 20 M de tokens et 5 $ (quand le coût est connu), et chaque projet permet 2 000 appels et 20 $ par jour ; une fois une limite atteinte, le relais répond 429 avec la raison, et un nouvel onglet de terminal reçoit un nouveau jeton. Modifier les réglages du modèle de décision met fin aux jetons des terminaux ouverts ; les terminaux ouverts ensuite utilisent les nouveaux réglages.

Cloudflare diffère de la documentation System One sur deux points (vérifiés sur l'API réelle) : les images doivent être des data URI (data:image/jpeg;base64,…, sinon erreur 422 « image must be an embedded base64 data URI »), et la réponse est enveloppée sous la forme { "result": { … }, "success": true } (les erreurs reviennent sous la forme { "success": false, "errors": [ … ] }). Le préréglage Cloudflare règle Encodage des images sur data URI, les agents le reçoivent via FERRET_DECISION_IMAGE_FORMAT, et les instructions leur demandent de lire .result lorsqu'il est présent. Le relais transmet les deux sens sans modification. Pour utiliser une Global API Key au lieu d'un jeton d'API, réglez Authentification sur Sans clé et ajoutez les en-têtes X-Auth-Email: ${CLOUDFLARE_EMAIL} et X-Auth-Key: ${CLOUDFLARE_API_KEY}.

Seuls Clef et Clef Flash lisent les images. Avec un modèle texte uniquement, désactivez Envoyer les images AVANT/APRÈS ; l'agent juge alors à partir du texte seul, ce qui est moins fiable.

Ollama et les images volumineuses

Ollama 0.35.0 limite les requêtes /v1/systemone à 64 Kio : les requêtes avec des captures d'écran échouent donc avec une erreur HTTP 413. Les instructions demandent à l'agent de réduire les deux images à 1024 px de large au maximum, en JPEG (qualité d'environ 70). S'il obtient encore une erreur 413, mettez Ollama à jour en 0.35.1 ou ultérieur, ou passez à Cloudflare Workers AI.

## Utilisation de l'API dans le pied de page

Les appels au modèle de décision passent par le relais, ce qui permet à Ferret de les compter. L'élément du pied de page situé à côté de l'indicateur d'utilisation de l'agent affiche le modèle de décision ainsi que les appels, les jetons et le coût du jour (par exemple clef-flash · 42 calls · 18.3k tok). Cliquez dessus pour voir le jour, le mois, le détail par projet, par modèle et par type (décision / transcription / organisation), ainsi que les 50 derniers appels.

Le coût n'apparaît que si l'API le communique (c'est le cas de Vercel AI Gateway) ou si vous définissez des prix par million de jetons dans Réglages → Modèle de décision ; sinon « — » s'affiche. Seules les métadonnées sont journalisées (heure, projet, modèle, statut, latence, taille, nombre d'images, jetons, coût), jamais les images, le texte ni les clés, dans ~/.ferret/usage/decision-YYYY-MM.jsonl, un fichier par mois.

## Personnaliser l'instruction

Modifiez Réglages → Agents → Instructions pour l'agent. Deux variables sont remplacées :

Read {{relpath}} and the PNGs next to it. Fix only findings marked to send, one commit per finding, then run the tests.

Le réglage est stocké sous agentPrompt dans settings.json.

## Mettre une étoile à Ferret sur GitHub

Après votre premier Envoyer à l'agent, puis lorsque vous atteignez 3, 10 et 30 relectures terminées, Ferret peut vous proposer de lui mettre une étoile sur GitHub. Il le demande au maximum 3 fois, à au moins 3 jours d'intervalle, et jamais pendant un enregistrement. Mettre une étoile sur GitHub ajoute l'étoile via votre propre connexion gh (ou ouvre GitHub si gh n'est pas disponible), et Ne plus demander arrête ces demandes. Vous pouvez aussi mettre une étoile depuis Aide → Mettre une étoile à Ferret sur GitHub.

## CLI des services

Réglages → CLI des services liste les outils en ligne de commande des services que vous utilisez souvent, pour que vos agents puissent s'en servir. Leur installation est facultative : installez seulement ce dont vous avez besoin ; Ferret fonctionne sans aucun d'eux. Chaque ligne indique si l'outil est installé et sa version, un lien vers le site du service, et des boutons qui lancent la commande officielle d'installation ou de connexion pour votre système dans un nouvel onglet de terminal :

  • Hébergement Git : GitHub (gh), GitLab (glab)
  • Hébergement et déploiement : Vercel, Netlify, Cloudflare (wrangler), Firebase, Fly.io, Railway, Heroku
  • Cloud : AWS, Google Cloud (gcloud), Azure (az)
  • Bases de données et backend : Supabase, Neon, PlanetScale, Turso
  • Erreurs et supervision : Sentry (sentry-cli), Datadog (datadog-ci)
  • Paiements : Stripe
  • Conteneurs : Docker, kubectl
  • Mobile : Xcode Command Line Tools (macOS uniquement), Android Platform Tools (adb), Expo EAS, fastlane
  • Machines virtuelles : UTM (macOS uniquement), Lima, Multipass
  • IA et modèles : Ollama

Lorsqu'un outil n'a pas d'installeur officiel en une ligne pour votre OS, Documentation ouvre sa page d'installation à la place. La liste refait sa vérification d'elle-même une fois l'installation terminée.
