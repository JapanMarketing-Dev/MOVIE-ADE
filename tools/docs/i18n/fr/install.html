Installation Ferret est une application de bureau pour macOS, Windows et Linux. La version macOS est signée avec un Developer ID et notariée par Apple. Les versions Windows et Linux ne sont pas encore signées : ces systèmes vous demandent donc de confirmer le premier lancement. ## Téléchargement

Récupérez le fichier correspondant à votre OS et à votre processeur sur la page de téléchargement. Les fichiers sont servis depuis Cloudflare R2, et non depuis GitHub Releases, et seules les 10 versions les plus récentes sont conservées.

OSFichiers
macOS (Apple silicon / Intel)Ferret-<version>-mac-arm64.dmg, Ferret-<version>-mac-x64.dmg
Windows (x64 / arm64)Ferret-<version>-win-x64.exe, Ferret-<version>-win-arm64.exe (installeur NSIS)
Linux (x64)Ferret-<version>-linux-x86_64.AppImage, Ferret-<version>-linux-amd64.deb

Les versions jusqu'à 0.1.x ont été publiées sous l'ancien nom, en MOVIE-ADE-<version>-…. Les noms Ferret-… commencent avec la 0.2.0.

Ferret prend en charge macOS, Windows et Linux. Les versions Windows et Linux ne sont pas encore signées : le premier lancement vous demande donc une confirmation (voir les étapes ci-dessous).

## Vérifier le téléchargement (SHA256SUMS signé)

Chaque version est accompagnée d'un fichier SHA256SUMS et de sa signature SHA256SUMS.sig. La signature est faite avec la clé de publication de Ferret, conservée à l'écart du serveur de téléchargement : un installeur modifié sur ce serveur ne peut donc pas être accompagné d'une signature valide. La clé publique n'est pas récupérée depuis le serveur de téléchargement : prenez-la dans le dépôt (build/release-signing/allowed_signers) ou copiez-la ici :

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

Son empreinte est SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ. Les mêmes fichiers sont joints à chaque version sur GitHub. Vérifiez la signature avec ssh-keygen (inclus dans macOS, Windows 10 et versions ultérieures, et Linux), puis comparez l'empreinte de votre téléchargement avec la liste signée :

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

Arrêtez-vous si ssh-keygen n'affiche pas Good "ferret-release" signature ou si l'empreinte ne figure pas dans la liste. La fonction Rechercher des mises à jour de Ferret fait la même vérification avec la clé intégrée à l'application et ne propose pas une version dont la signature ne correspond pas. Sur macOS, vous pouvez aussi vérifier la signature Developer ID et la notarisation avec spctl -a -vv /Applications/Ferret.app. Les installeurs Windows et Linux ne sont pas encore signés par Microsoft ni par une distribution Linux. Les versions jusqu'à 0.3.0 ont été publiées avant la mise en place de la signature et n'ont que les empreintes non signées de releases/<version>/manifest.json.

## macOS
  1. Ouvrez le .dmg et faites glisser Ferret.app dans /Applications.
  2. Lancez-la. L'application est signée avec un Developer ID et notariée par Apple (le ticket est agrafé) : elle s'ouvre donc sans avertissement.

Pour vérifier vous-même la signature :

spctl -a -vv /Applications/Ferret.app
# accepted
# source=Notarized Developer ID

Anciennes versions uniquement (0.2.0 build 2 et antérieures) : elles n'étaient pas signées. Pour celles-ci, macOS indique que le développeur ne peut pas être vérifié : fermez la boîte de dialogue, ouvrez Réglages Système → Confidentialité et sécurité, cliquez sur Ouvrir quand même à côté du message concernant Ferret, puis confirmez avec Ouvrir. Si macOS indique que l'application « est endommagée », supprimez l'attribut de quarantaine :

xattr -dr com.apple.quarantine /Applications/Ferret.app
## Windows
  1. Exécutez Ferret-<version>-win-<arch>.exe.
  2. Quand SmartScreen affiche « Windows a protégé votre ordinateur », cliquez sur Informations complémentaires, puis sur Exécuter quand même.
  3. Choisissez le dossier d'installation. L'installeur crée un raccourci sur le bureau.
## Linux

AppImage :

chmod +x Ferret-<version>-linux-x86_64.AppImage
./Ferret-<version>-linux-x86_64.AppImage

Debian / Ubuntu :

sudo apt install ./Ferret-<version>-linux-amd64.deb

Le paquet deb installe le paquet et la commande ferret.

Sur Ubuntu 23.10 et versions ultérieures, l'AppImage peut s'arrêter au lancement avec une erreur de sandbox, car AppArmor restreint les espaces de noms utilisateur dont se sert la sandbox d'Electron. Installez plutôt le .deb, qui configure l'outil d'aide de la sandbox.

## Compiler depuis les sources

Nécessite Node.js 20+ (la CI et le développement local utilisent la 22), pnpm et git.

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

Pour produire les installeurs (sortie dans dist/release/, configuration dans electron-builder.config.cjs). La version Linux ne se compile que sous Linux.

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

Les scripts build:<os>:dev produisent uniquement une application non empaquetée (--dir), plus rapide pour les tests en local.

Sous Windows, pnpm install utilise les binaires précompilés fournis avec node-pty au lieu de les recompiler (ce qui exigerait les outils de compilation C++ de Visual Studio). Définissez ADE_FORCE_NATIVE_REBUILD=1 pour forcer la recompilation.

Si le terminal indique que node-pty n'a pas pu être chargé, exécutez pnpm rebuild:native.

## Mises à jour

Ferret ne se met pas à jour automatiquement. Dans le pied de page, ouvrez Mises à jour et cliquez sur Rechercher des mises à jour. Ferret récupère latest.json sur le serveur de téléchargement (R2), compare les versions et renvoie vers la page de téléchargement. Depuis la 0.4.0, il vérifie aussi la signature du SHA256SUMS de cette version avec la clé de publication intégrée à l'application, et ne propose pas une version dont la signature ne peut pas être vérifiée. Rien n'est vérifié tant que vous ne cliquez pas, et rien n'est installé automatiquement.
