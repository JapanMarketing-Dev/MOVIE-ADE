अकाउंट और usage कई Claude Code या Codex logins के बीच बदलें, और फ़ुटर में अपनी rate-limit windows पर नज़र रखें। फ़िलहाल ये दोनों फ़ीचर सिर्फ़ Claude Code और Codex के साथ काम करते हैं; दूसरे agents हमेशा की तरह अपना ही login इस्तेमाल करते रहते हैं। ## कई अकाउंट

अकाउंट वैकल्पिक हैं। इन्हें सिर्फ़ तभी जोड़ें जब आप कई अकाउंट के बीच बदलते हों।

  1. Settings → अकाउंट खोलें, या फ़ुटर के usage मेन्यू से अकाउंट प्रबंधित करें…।
  2. अकाउंट जोड़ें बिल्ट-इन टर्मिनल टैब में agent का login शुरू करता है।
  3. इस्तेमाल करने वाला अकाउंट चुनें। चल रहे टैब अपना अकाउंट रखते हैं। नए टैब चुना गया अकाउंट इस्तेमाल करते हैं।

यह कैसे काम करता है: जोड़े गए हर अकाउंट को अपनी config directory मिलती है, <userData>/accounts/<agent>/<id>/। Ferret agent को CLAUDE_CONFIG_DIR (Claude Code) या CODEX_HOME (Codex) के साथ उसी directory की ओर इशारा करते हुए launch करता है। सिस्टम डिफ़ॉल्ट आपकी सामान्य ~/.claude / ~/.codex को बिना बदले इस्तेमाल करता है।

अकाउंट हटाने से उसकी config directory डिलीट हो जाती है। इससे server पर आप sign out नहीं होते।

## फ़ुटर में usage

फ़ुटर दिखाता है कि हर rate-limit window का कितना हिस्सा इस्तेमाल हो चुका है: 5 घंटे की window और साप्ताहिक window, साथ में Claude के लिए हर मॉडल की साप्ताहिक window। 60% पर रंग पीला और 80% पर लाल हो जाता है। मान हर 15 मिनट में, या usage रिफ़्रेश करें पर रिफ़्रेश होते हैं।

कितना दिखता है, यह फ़ुटर में उपलब्ध जगह पर निर्भर करता है। जगह हो तो यह bars, window के नाम और प्रतिशत दिखाता है। फ़ुटर जितना संकरा होता है, यह कम काम के हिस्से पहले हटाता जाता है, यहाँ तक कि हर agent के लिए सिर्फ़ एक प्रतिशत बचता है। सब कुछ एक popover में देखने के लिए usage पर क्लिक करें।

Usage सीधे Anthropic (api.anthropic.com/api/oauth/usage) और ChatGPT (chatgpt.com/backend-api/wham/usage) से, साइन इन किए गए अकाउंट के अपने credentials के साथ लाया जाता है।

{{shot:usage|फ़ुटर में usage}} ## उपयोग सीमा पर भी काम जारी रखें

जब कोई agent अपनी उपयोग सीमा पर पहुँचता है, तो Ferret उसी प्रोजेक्ट फ़ोल्डर में वही काम जारी रखता है, ताकि लंबा काम सीमा पर न रुके। यह डिफ़ॉल्ट रूप से चालू है और Settings → अकाउंट → उपयोग सीमा पर बदलाव में सेट होता है।

काम प्रोजेक्ट की एक ही फ़ाइल, .ferret/handoff.md, के ज़रिए सौंपा जाता है, इसलिए यह अकाउंट्स के बीच और अलग-अलग agents के बीच एक जैसा काम करता है। Agent को भेजें के निर्देश agent से कहते हैं कि वह हर पड़ाव पर और उपयोग सीमा के क़रीब पहुँचने पर इस फ़ाइल को अपडेट रखे: लक्ष्य, क्या हो चुका है, बाक़ी काम checklist के रूप में, उसने कौन-सी फ़ाइलें बदलीं, अगला कदम, संबंधित feedback.md और review के paths, और ध्यान रखने वाली बातें। .ferret/ git से बाहर रहता है (यह .gitignore में नहीं, .git/info/exclude में जोड़ा जाता है)।

  1. Ferret सीमा को टर्मिनल में agent के अपने संदेश से पहचानता है (जैसे Claude Code में 5-hour limit reached ∙ resets 3pm, Codex में You've hit your usage limit), या फ़ुटर के usage के threshold तक पहुँचने से (डिफ़ॉल्ट 95%; 5 घंटे, साप्ताहिक और हर मॉडल की windows में से सबसे ऊँचा)।
  2. बदलने से पहले Ferret मौजूदा agent से .ferret/handoff.md अपडेट करने को कहता है। अगर agent उस पर काम शुरू नहीं करता (जैसे इसलिए कि वह पहले से सीमा पर है), तो Ferret जो जानता है वह फ़ाइल में जोड़ देता है: आख़िरी अनुरोध, feedback.md कहाँ है, और git status से बदली हुई फ़ाइलें।
  3. फिर Ferret उसी agent के किसी दूसरे साइन इन किए गए अकाउंट पर जाता है, जिसका usage सबसे कम हो। जब agent के सभी अकाउंट अपनी सीमा पर हों, तो काम Agent का क्रम में अगले agent पर चला जाता है (डिफ़ॉल्ट: Claude Code → Codex → Gemini CLI)।
  4. नया agent उसी प्रोजेक्ट में नए टैब में खुलता है और उसे ऐप की भाषा में कहा जाता है कि पहले .ferret/handoff.md पढ़े और बाक़ी काम जारी रखे।
  5. फ़ुटर अभी <agent> पर दिखाता है और एक सूचना बताती है कि क्या बदला, जैसे Codex अपनी उपयोग सीमा पर पहुँच गया, इसलिए काम Claude Code ने संभाल लिया। जिस टैब की सीमा पूरी हुई थी वह बंद हो जाता है, ताकि सीमा रीसेट होने पर वह वही काम फिर से न उठाए।
