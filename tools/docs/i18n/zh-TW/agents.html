傳送給 Agent 在內建終端機中執行你的程式設計 Agent，按一下就把審查交給它。常見的例子是 Claude Code 和 Codex，但下方清單中的任何 Agent 都能使用，你自己新增的 CLI 也可以。你也可以把指示複製給在其他地方執行的 Agent。 ## 檢查意見

意見 分頁中的每張卡片都可以：

  • 直接編輯標題與要求
  • 切換 傳送 / 不傳送
  • 觀看錄影（跳到該時間點）與 替換圖片（改選其他影格）
  • 確認、刪除

依進度篩選 可依狀態顯示或隱藏意見（例如 僅顯示 等待你確認的意見）；全部顯示 會清除篩選。

要調整意見的順序，可以拖曳卡片標題左側的把手，或選取把手後按 ↑ / ↓。編號、feedback.md 以及傳送給 Agent 的內容都會依新順序排列。篩選時，只會在看得到的意見之間調整順序，隱藏的意見維持原位。一次審查涵蓋多個頁面或檔案時，意見只會在各自的分組內移動。標頭的 意見排序 可在 手動（拖曳順序）、錄製時間 與 進度（未處理在前，已完成在後）之間切換；依進度排序時，該順序會儲存為手動順序。

標頭有 還原、開啟資料夾、拷貝給 Agent、整理 與 傳送給 Agent。沒有成為意見的語音會列在 已排除的語音 中，按 還原為意見 即可取回。沒有實際意義的話語也不會成為意見，同樣列在這裡：語音辨識有時會從靜音中憑空產生的句子（例如「Shh.」或「謝謝觀看」）、只有「嗯」之類語氣詞的話語，以及沒有筆跡標註時單獨的「好」或「OK」。

開啟專案時，Ferret 會依 設定 → Agent → 開啟專案時啟動 中選擇的 Agent，在專案資料夾中為每個 Agent 開一個終端機分頁。預設是 Claude Code 和 Codex，啟動時略過權限確認，並開啟 Claude in Chrome：

你自己開啟的 Agent 也會以相同方式啟動。Ferret 也會為 Claude Code 和 Codex 將專案資料夾標記為受信任，因此它們不會詢問這個資料夾。若要以一般模式啟動（在信任資料夾、編輯檔案或執行指令前都會詢問），請關閉 設定 → Agent → 啟動 Agent 時略過權限確認。每個 Agent 的指令與參數位於 設定 → Agent（指令）以及 settings.json（agents.launch）中，並會照你寫的內容使用。若要在不使用 Claude in Chrome 的情況下啟動 Claude Code，請在那裡刪除 --chrome。如果參數已經選擇了權限模式（例如 --permission-mode plan，或 Codex 的 --sandbox workspace-write），就不會再加上略過確認的參數。

若沒有選擇任何 Agent，會開啟一般的 shell。+ 選單可以開啟 新增終端機、在新分頁中啟動你的任一 Agent，或跳到 Agent 設定…。它的搜尋框也能找到分頁、已儲存的 URL 和檔案。

把檔案拖放到終端機。從 Finder（Windows 上為檔案總管，Linux 上為檔案管理員）把檔案、資料夾或圖片拖到終端機窗格上，它們的路徑會以空格分隔輸入到該窗格，不會按下 Enter。Agent 執行時也一樣：Claude Code 會把拖入的圖片路徑當作圖片讀取。從 檔案 拖出的列（選取後可一次拖多個）也以相同方式處理：終端機位於專案資料夾時，路徑是相對於專案資料夾的路徑；用 cd 移到其他位置後則是絕對路徑。含有空格或其他特殊字元的路徑會依 shell 加上引號：zsh 和 bash 為 '…'，命令提示字元為 "…"，PowerShell 為 '…'。

分頁會顯示 Agent 的狀態：執行中、等待輸入、完成（未讀）、閒置。完成（未讀） 表示 Agent 在你查看其他分頁時已完成；開啟該分頁後會變成 閒置。側邊欄也會以相同方式標示每個專案，不必切換專案就能看到：Agent 執行時顯示移動的長條，有 Agent 在等你時顯示問號，該專案的 Agent 都已完成而你尚未開啟分頁時顯示勾號。

通知。開啟 設定 → Agent → Agent 完成或需要我確認時通知我 後，當專案中的所有 Agent 都已完成，或某個 Agent 正在等待授權或回答時，會收到系統通知。正在查看的分頁不會顯示任何通知。點擊通知即可切換到該專案並開啟該分頁。

## 重新啟動後還原終端機

Ferret 結束時，會記住每個專案的終端機分頁：順序與分割、每個分頁開啟時的資料夾、執行的 Agent 與帳號，以及每個畫面最多 2,000 行文字。下次啟動 Ferret 時，分頁會依相同順序還原。先顯示先前的文字，接著是一行淡色的 — 接續上次（2026-10-05 14:30）—，然後在同一資料夾啟動新的 shell。

Agent 分頁會接續先前的對話啟動：Claude Code 使用 --continue，Codex 使用 resume --last，接續該資料夾中最近的一次對話。若多個分頁在同一資料夾、以同一帳號執行同一個 Agent，只有第一個會接續對話，其餘重新開始，因此不會有兩個分頁接續同一個對話。若該資料夾中沒有 Claude Code 的對話，或專案位於 SSH 主機上，則正常啟動。

重新開啟已關閉的終端機。終端機 → 重新開啟已關閉的終端機（終端機有焦點時按 {{keys:Mod+Shift+T}}）會還原你在此專案中最後關閉的分頁或窗格及其文字，並以相同方式接續其 Agent 的對話。最多保留最近關閉的 10 個終端機，重新啟動後也會保留。

歷史只以不含顏色的純文字儲存在 Ferret 的資料資料夾中（terminal-restore.json，只有你本人可讀），不會寫入專案。從 新增帳號 開啟的登入分頁與一次性指令不會保留。若要停止儲存，請關閉 設定 → Agent → 儲存終端機歷史並還原，已儲存的內容也會刪除。旁邊的 刪除已儲存的歷史 可隨時刪除。

## 傳送給 Agent / 拷貝給 Agent {{clip:send|在意見分頁按「傳送給 Agent」，交給內建終端機中的 Agent。}}

## 用判定模型做驗收檢查 {{clip:verify|Agent 修正意見，並在你查看之前用判定模型逐一檢查。}}

開啟後，你的程式設計 Agent 會在你查看之前依每則意見把自己的成果檢查一次。Ferret 本身不做任何判定：它把判定模型（任何相容 System One 的 API）提供給 Agent，並在 feedback.md 中告訴它如何使用。判定模型是 Agent 自己的檢查，絕不是向你提問：Agent 不會問你任何問題。你只需比較 BEFORE 與 AFTER，然後按 OK 或 NG。

  1. Agent 實作意見。
  2. 對每則意見，Agent 擷取 AFTER 螢幕截圖（與 BEFORE 靜態畫面相同的視窗範圍與頁面狀態），並把意見內容、其「完成條件」行以及 BEFORE/AFTER 圖片，以一個請求傳給判定模型。
  3. 每次你把意見送給 Agent 時，判定模型每則意見最多呼叫一次。沒有第二次判定，也沒有迴圈，因此一個始終不說 "done" 的模型也無法讓 Agent 一直忙下去。
  4. Agent 讀取那一次的結果。當 P(done) 達到門檻（預設 0.7）且選擇為 done 時，該意見即通過，原樣交給你。否則，如果結果顯示出 Agent 能修正的明確差距，它可以再改善一次修正並重新擷取 AFTER，不再判定。
  5. 無論哪種情況，Agent 都將該意見設為 待檢查，附上它的 AFTER、那一次的分數，以及最多一行說明。超出範圍的意見，或無法連線的判定 API，都不會讓工作停下來：該意見不帶分數進入 待檢查。
  6. 在 意見 中，每則等你處理的意見都會把 BEFORE、AFTER 與分數作為參考資料顯示出來。OK 會將它標為完成；NG 加上留言會將它作為新的請求傳回給 Agent，在那裡它會再被判定一次。Agent 在終端機中給出的最後「完成 / 未完成」清單會包含每則意見的分數，以及是否又改善了一次修正。

請在 設定 → 判定模型 中設定，並開啟 在 Agent 指示中加入判定模型檢查。預設組合只會幫你填入欄位；每個欄位都能再編輯，自訂 可搭配任何相容的 API。

使用 Ollama 時，請先安裝（Clef / Clef Flash 需要 0.35.1 以上），並在終端機中下載模型。Ferret 不會執行安裝程式：

ollama pull clef-flash

金鑰來自金鑰欄位（與你的其他 API 金鑰一起儲存）、你指定的環境變數（App 的環境、專案的 .env 或 ~/.ferret/.env），或 settings.json 中的 apiKey。額外標頭可以用 ${VAR} 讀取環境變數的值。

金鑰如何不出現在提示詞中

Agent 永遠看不到你的金鑰。Ferret 會在 127.0.0.1 上執行本機中繼，並提供每個終端機 FERRET_DECISION_URL（中繼的位址，附每個終端機專用的權杖）、FERRET_DECISION_MODEL 與 FERRET_DECISION_IMAGES（在一個版本內，也會同時設定舊的 MOVIE_ADE_DECISION_* 名稱）。中繼會加上金鑰與標頭，並原封不動地轉送請求，因此提示詞、feedback.md 和 Agent 的對話紀錄中都不含機密。每個終端機的權杖最多可呼叫 500 次、每分鐘 30 次、2,000 萬 token 與 5 美元（已知費用時），每個專案每天最多 2,000 次與 20 美元；達到上限時中繼會回傳 429 並附上原因，新開的終端機分頁會取得新的權杖。變更判定模型的設定後，已開啟終端機的權杖會失效，之後開啟的終端機會套用新設定。

Cloudflare 與 System One 文件有兩點不同（已用實際 API 確認）：圖片必須是 data URI（data:image/jpeg;base64,…，否則會回傳 422 "image must be an embedded base64 data URI"），且回應會包裝成 { "result": { … }, "success": true }（錯誤則回傳 { "success": false, "errors": [ … ] }）。Cloudflare 預設組合會把 圖片編碼 設為 data URI，Agent 會以 FERRET_DECISION_IMAGE_FORMAT 取得此設定，指示中也會要求它在有 .result 時讀取該欄位。中繼對雙向內容都原封不動地傳遞。若要改用 Global API Key 而非 API 權杖，請把 驗證 設為 無金鑰，並加入標頭 X-Auth-Email: ${CLOUDFLARE_EMAIL} 與 X-Auth-Key: ${CLOUDFLARE_API_KEY}。

只有 Clef 和 Clef Flash 能讀取圖片。使用僅限文字的模型時，請關閉 傳送 BEFORE/AFTER 圖片；此時 Agent 只依文字判定，可靠度較低。

Ollama 與大型圖片

Ollama 0.35.0 將 /v1/systemone 請求限制在 64 KiB，因此附上螢幕截圖的請求會以 HTTP 413 失敗。指示會要求 Agent 把兩張圖片都縮小到寬度最多 1024px 的 JPEG（品質約 70）。如果仍然收到 413，請把 Ollama 更新到 0.35.1 以上，或改用 Cloudflare Workers AI。

## 頁尾的 API 用量

判定呼叫會經過中繼，因此 Ferret 可以計算它們。頁尾中 Agent 用量計量表旁的項目會顯示判定模型，以及今天的呼叫次數、權杖數與費用（例如 clef-flash · 42 calls · 18.3k tok）。按一下即可查看今天、本月、各專案、各模型與各類型（判定 / 轉錄 / 整理）的用量，以及最近 50 次呼叫。

只有在 API 回報費用（Vercel AI Gateway 會回報），或你在 設定 → 判定模型 中設定每 1M 權杖的價格時，才會顯示費用；否則會顯示「—」。只會記錄中繼資料（時間、專案、模型、狀態、延遲、大小、圖片數、權杖數、費用），絕不記錄圖片、文字或金鑰；記錄存放在 ~/.ferret/usage/decision-YYYY-MM.jsonl，每月一個檔案。
