Аккаунты и использование Переключайтесь между несколькими входами в Claude Code или Codex и следите за окнами лимитов запросов в нижней панели. Пока обе функции работают только с Claude Code и Codex; другие агенты, как обычно, используют собственный вход. ## Несколько аккаунтов

Аккаунты необязательны. Добавляйте их, только если переключаетесь между несколькими.

  1. Откройте Настройки → Аккаунты или выберите Управление аккаунтами… в меню использования в нижней панели.
  2. Добавить аккаунт запускает вход агента во вкладке встроенного терминала.
  3. Выберите аккаунт, который нужно использовать. Уже запущенные вкладки сохраняют свой аккаунт. Новые вкладки используют выбранный.

Как это работает: у каждого добавленного аккаунта своя папка конфигурации, <userData>/accounts/<agent>/<id>/. Ferret запускает агента с CLAUDE_CONFIG_DIR (Claude Code) или CODEX_HOME (Codex), указывающими на неё. Системный по умолчанию использует ваши обычные ~/.claude / ~/.codex без изменений.

Удаление аккаунта удаляет его папку конфигурации. Выход из аккаунта на сервере при этом не выполняется.

## Использование в нижней панели

Нижняя панель показывает, какая часть каждого окна лимита использована: 5-часовое окно и недельное окно, а для Claude ещё и недельное окно по каждой модели. При 60% цвет становится жёлтым, при 80% — красным. Значения обновляются каждые 15 минут или по кнопке Обновить использование.

Объём показываемых данных зависит от места в нижней панели. Если места достаточно, отображаются полосы, названия окон и проценты. По мере сужения панели сначала скрываются менее полезные части, вплоть до одного процента на агента. Щёлкните по показателю использования, чтобы увидеть всё во всплывающем окне.

Данные об использовании запрашиваются напрямую у Anthropic (api.anthropic.com/api/oauth/usage) и ChatGPT (chatgpt.com/backend-api/wham/usage) с учётными данными аккаунта, в который выполнен вход.

{{shot:usage|Использование в нижней панели}} ## Работа без остановки на лимитах использования

Когда агент достигает лимита использования, Ferret продолжает ту же работу в той же папке проекта, так что длинная задача не останавливается на лимите. По умолчанию это включено и настраивается в Настройки → Аккаунты → Переключение при лимите использования.

Работа передаётся через один файл в проекте, .ferret/handoff.md, поэтому это одинаково работает и между аккаунтами, и между разными агентами. Инструкции Отправить агенту просят агента обновлять этот файл на каждом этапе и при приближении к лимиту использования: цель, что сделано, оставшаяся работа в виде чек-листа, изменённые файлы, следующий шаг, пути к связанным feedback.md и ревью и всё, на что стоит обратить внимание. .ferret/ не попадает в git (папка добавляется в .git/info/exclude, а не в .gitignore).

  1. Ferret замечает лимит по сообщению самого агента в терминале (например, 5-hour limit reached ∙ resets 3pm в Claude Code, You've hit your usage limit в Codex) или когда использование в нижней панели доходит до порога (по умолчанию 95%; берётся наибольшее из 5-часового, недельного и помодельного окон).
  2. Перед переключением Ferret просит текущего агента обновить .ferret/handoff.md. Если агент не берётся за это (например, потому что уже достиг лимита), Ferret сам дописывает в файл то, что знает: последний запрос, где лежит feedback.md, и изменённые файлы из git status.
  3. Затем Ferret переключается на другой аккаунт того же агента, в который выполнен вход, — с наименьшим использованием. Когда все аккаунты агента достигли лимита, работа переходит к следующему агенту в Порядок агентов (по умолчанию: Claude Code → Codex → Gemini CLI).
  4. Новый агент открывается в новой вкладке в том же проекте и получает на языке приложения указание сначала прочитать .ferret/handoff.md и продолжить оставшуюся работу.
  5. В нижней панели показывается Сейчас: <agent>, а уведомление сообщает, что изменилось, например Codex достиг лимита использования, поэтому работу продолжил Claude Code. Вкладка, упёршаяся в лимит, закрывается, чтобы она не взялась за ту же задачу снова, когда её лимит восстановится.
