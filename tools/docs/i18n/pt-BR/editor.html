Editor e prévia Abra e edite os arquivos do projeto e veja a prévia de Markdown e Mermaid. Uma prévia aberta no navegador integrado pode ser gravada e revisada como qualquer página web. ## Abrir e editar arquivos
  • Arquivos (a árvore de arquivos): {{keys:Mod+Shift+E}}, com Filtrar por nome de arquivo, Atualizar e Recolher tudo.
  • Ir para arquivo…: {{keys:Mod+P}}.
  • Arraste um arquivo do Finder (do Explorador de Arquivos no Windows, do seu gerenciador de arquivos no Linux) para a barra de abas ou para o editor para abri-lo. Arquivos do projeto abrem no editor ou em um visualizador. Para trazer um arquivo de fora do projeto, solte-o em Arquivos, que o copia para o projeto. Uma pasta solta aqui abre como projeto. Arquivos arrastados de Arquivos abrem da mesma forma. Já imagens e vídeos soltos em um arquivo Markdown aberto são incorporados nele (veja Incorporar imagens e vídeos no Markdown).
  • Salve com {{keys:Mod+S}}. Ao fechar um arquivo modificado, aparece Salvar as alterações em <name>? com Salvar, Não salvar e Cancelar.
  • Se o arquivo mudar no disco enquanto você tem edições não salvas, escolha Recarregar do disco ou Manter minhas alterações.

O editor é o Monaco. Arquivos que não são texto abrem em um visualizador: imagens (com zoom; SVG também pode ser exibido como código), vídeo e áudio com barra de busca, PDF e, para qualquer outro arquivo binário, o tamanho e uma visualização hexadecimal dos primeiros bytes. Os visualizadores são somente leitura, e arquivos fora da pasta do projeto ou acessados por um link simbólico que sai dela não são exibidos.

## Trabalhar com arquivos na árvore de arquivos

Trabalhe com os arquivos direto em Arquivos, como você faria no VS Code. Clique com o botão direito em um item, ou no espaço vazio abaixo da árvore para trabalhar na raiz do projeto. Os nomes são digitados no próprio lugar, na árvore.

  • Novo arquivo / Nova pasta: os botões acima da árvore, ou clique com o botão direito. Um item novo vai para a pasta selecionada, ao lado do arquivo selecionado ou para a raiz do projeto. Digite um nome com barras, como src/routes/index.ts, para criar as pastas no caminho. Um arquivo novo abre no editor. Em uma pasta vazia, Arquivos mostra Esta pasta está vazia com os botões Novo arquivo e Nova pasta.
  • Recortar, Copiar e Colar: {{keys:Mod+X}}, {{keys:Mod+C}}, {{keys:Mod+V}}, ou clique com o botão direito. As pastas são copiadas com tudo o que há dentro. Duplicar cria uma cópia ao lado do original. Se o nome já existir, a cópia recebe o nome name copy, depois name copy 2.
  • Arraste itens para uma pasta (ou para o espaço vazio, para a raiz do projeto) para movê-los. Segure {{keys:Alt|Ctrl}} ao soltar para copiar em vez de mover. Arquivos e pastas arrastados do Finder (do Explorador de Arquivos no Windows) são copiados para o projeto; os originais ficam onde estavam.
  • Renomear: {{keys:F2 / Enter|F2}}, ou clique com o botão direito.
  • Excluir: {{keys:Mod+Backspace / Delete|Delete}}, ou clique com o botão direito. O Ferret pede confirmação e depois move o item para a Lixeira, então você pode restaurá-lo. As abas dos arquivos excluídos são fechadas; se alguma tinha edições não salvas, a confirmação avisa.
  • Desfazer: {{keys:Mod+Z}} desfaz a última criação, renomeação, movimentação, colagem ou duplicação. Itens excluídos são restaurados da Lixeira.
  • Copiar caminho ({{keys:Alt+Mod+C|Shift+Alt+C}}) e Copiar caminho relativo ({{keys:Alt+Shift+Mod+C|Ctrl+Shift+Alt+C}}) colocam o caminho na área de transferência.
  • Mostrar no Finder (Mostrar no Explorador de Arquivos no Windows, Abrir pasta que contém no Linux): {{keys:Alt+Mod+R|Shift+Alt+R}}. Abrir no terminal abre uma nova aba de terminal nessa pasta (para um arquivo, na pasta dele).
  • Para um arquivo, Abrir o abre no editor e Abrir no app padrão o abre no app que o seu sistema operacional usa para esse tipo.
  • Selecione vários itens com {{keys:Mod}}-clique ou {{keys:Shift}}-clique para recortá-los, copiá-los, movê-los ou excluí-los juntos.
  • {{keys:Esc}} cancela um nome que você está digitando.

As abas abertas acompanham um arquivo renomeado ou movido e mantêm as edições não salvas. O Ferret não sobrescreve um arquivo ou pasta existente com o mesmo nome e mantém tudo dentro da pasta do projeto: recusa .., caminhos absolutos, links simbólicos que apontam para fora, qualquer coisa dentro de .git, mover uma pasta para dentro dela mesma e nomes que algum sistema operacional não aceita: / \ < > : " | ? *, caracteres de controle, espaço ou ponto no final e nomes reservados do Windows, como CON ou NUL. Uma única cópia ou um único soltar pode ter até 10.000 itens e 1 GB.

## Prévia de Markdown e Mermaid

A prévia funciona para .md, .markdown, .mdx, .mmd e .mermaid. O Mermaid vem embutido no app, então os diagramas são renderizados offline.

Um arquivo Markdown tem duas visualizações no topo do editor: Código-fonte e Pré-visualização. A prévia é sempre editável, então você pode digitar direto nela; clique em Código-fonte para voltar ao texto. As duas mostram o mesmo conteúdo, e salvar, a marca de não salvo e a confirmação ao fechar funcionam do mesmo jeito.

  • Digite direto em títulos, parágrafos, listas, caixas de seleção, tabelas, links e texto em negrito, itálico ou código inline. Digitar #, -, 1. ou > e um espaço no início de uma linha inicia um título, uma lista ou uma citação.
  • Digite / no início de uma linha (ou depois de um espaço) para escolher um bloco em uma lista: títulos, listas com marcadores, numeradas ou de tarefas, uma tabela, um bloco de código, uma citação ou um divisor. Cada item diz o que cria e como é escrito em Markdown. Continue digitando para filtrar, use {{keys:Up}} {{keys:Down}} e {{keys:Enter}} para escolher, ou {{keys:Esc}} para manter a / como texto. Uma tabela começa com 3 × 3 e uma linha de cabeçalho; {{keys:Tab}} vai para a próxima célula e adiciona uma linha no final. Digitar / dentro de uma tabela adiciona ou exclui linhas e colunas, ou exclui a tabela.
  • Blocos de código são editados como código-fonte, com a linguagem num canto. Um bloco de código Mermaid (mermaid ou mmd) mostra o diagrama por padrão. Clique em Código no canto superior direito, ou dê um duplo clique no diagrama, para editar o código-fonte; quando o cursor sai do bloco, o diagrama volta. Se o código tiver um erro, a mensagem aparece com Corrigir o código. Os diagramas são desenhados dentro de um quadro isolado (sandbox), e o Markdown salvo fica como foi escrito.
  • O front matter (o bloco --- no topo) aparece como texto acima do documento e pode ser editado ali.
  • As partes que você não altera são salvas exatamente como foram escritas, incluindo o estilo dos títulos, os marcadores de lista, as linhas em branco, o alinhamento das tabelas e as quebras de linha. Um bloco que você edita mantém o estilo quando possível; caso contrário, esse bloco é escrito em uma forma padrão de Markdown, com - para listas e # para títulos.
  • Imagens e vídeos do projeto são exibidos. Imagens de outros sites não são carregadas; o nome do host aparece no lugar. O restante do HTML no arquivo é exibido como texto.

Arquivos .mdx (editados só como código-fonte), .mmd e .mermaid têm, em vez disso, uma prévia somente leitura:

  • Abrir prévia ao lado: ao lado do editor
  • Abrir prévia: no navegador integrado (ade-preview://), para que você possa gravá-la e revisá-la
## Incorporar imagens e vídeos no Markdown

Arraste imagens (PNG, JPEG, GIF, WebP, SVG, AVIF) ou vídeos (MP4, WebM, MOV) para um arquivo Markdown, em Código-fonte ou Pré-visualização, para incorporá-los onde você os soltar.

  • Arquivos que já estão no projeto, incluindo os arrastados de Arquivos, são vinculados com um caminho relativo ao arquivo Markdown. Nada é copiado.
  • Arquivos de fora do projeto (do Finder, da área de trabalho, do Explorador de Arquivos no Windows) são primeiro copiados para uma pasta ao lado do arquivo Markdown: assets, images, media ou img, se uma delas já existir; caso contrário, uma nova pasta assets. Espaços no nome viram - e, se o nome já existir, a cópia recebe o nome name-2. Os originais ficam onde estavam.
  • Imagens são escritas como ![name](assets/name.png) e vídeos como <video src="assets/name.mp4" controls></video>, que o GitHub também reproduz. Os dois aparecem em Pré-visualização.
  • Uma imagem pode ter até 50 MB e um vídeo até 500 MB, e um único soltar copia até 50 arquivos e 1 GB. Outros arquivos soltos junto com eles abrem no editor normalmente.
## Revisar documentos gravando
  1. No painel Alvos de revisão, abra o arquivo Markdown em Arquivos. Ele abre como prévia no navegador integrado.
  2. Grave normalmente. Comente a especificação ou o documento de design e circule o que está errado.
  3. Pare. Os apontamentos fazem referência ao caminho do arquivo relativo ao projeto, em vez de uma URL.
  4. Use Enviar ao Agent para que o documento seja corrigido.
