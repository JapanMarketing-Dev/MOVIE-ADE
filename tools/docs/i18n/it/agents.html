Inviare agli agent Esegui il tuo coding agent nel terminale integrato e consegnagli una revisione con un clic. Claude Code e Codex sono gli esempi più comuni, ma funziona qualsiasi agent dell'elenco qui sotto, e anche una CLI che aggiungi tu. Puoi anche copiare l'istruzione per un agent che gira altrove. ## Rivedere le segnalazioni

Ogni card nella scheda Segnalazioni consente di:

  • Modificare direttamente titolo e richiesta
  • Alternare Invia / Non inviare
  • Guarda registrazione (salta a quel momento) e Sostituisci immagine (scegli un altro fotogramma)
  • Conferma, Elimina

Filtra per avanzamento mostra o nasconde le segnalazioni in base allo stato (per esempio Solo quelle in attesa della tua verifica); Mostra tutto rimuove il filtro.

Per riordinare le segnalazioni, trascina la maniglia a sinistra del titolo di una scheda, oppure seleziona la maniglia e premi ↑ / ↓. I numeri, feedback.md e ciò che invii all'Agent seguono il nuovo ordine. Con un filtro attivo, l'ordine cambia tra le segnalazioni visibili e quelle nascoste mantengono la loro posizione. Quando una revisione riguarda più pagine o file, le segnalazioni si spostano all'interno del proprio gruppo. Ordina segnalazioni nell'intestazione passa tra Manuale (ordine di trascinamento), Momento della registrazione e Avanzamento (prima quelle non iniziate, in fondo quelle completate); ordinare per avanzamento salva quell'ordine come ordine manuale.

L'intestazione contiene Annulla, Apri cartella, Copia per l'Agent, Organizza e Invia all'Agent. Il parlato che non è diventato una segnalazione è elencato in Parlato escluso, dove Ripristina come segnalazione lo recupera. Il parlato senza parole significative non diventa mai una segnalazione ed è elencato anche lì: frasi che la trascrizione a volte inventa dal silenzio, come «Shh.» o «Grazie per la visione», intercalari come «ehm» e un «OK» o «sì» isolato senza segno di penna.

{{shot:findings|La scheda Segnalazioni}} ## Eseguire gli agent nel terminale integrato

Quando un progetto si apre, Ferret avvia una scheda del terminale per ogni agent indicato in Impostazioni → Agent → Avvia all'apertura di un progetto, nella cartella del progetto. Il valore predefinito è Claude Code e Codex, avviati senza richieste di autorizzazione e con Claude in Chrome attivo:

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

In alternativa scegli qualsiasi agent dall'elenco di quelli supportati (si avviano nell'ordine in cui li scegli), oppure nessuno.

Gli agent che apri tu si avviano allo stesso modo. Ferret segna inoltre la cartella del progetto come attendibile per Claude Code e Codex, così non fanno domande sulla cartella. Per avviarli nella loro modalità normale, in cui chiedono prima di fidarsi di una cartella, modificare file o eseguire comandi, disattiva Impostazioni → Agent → Avvia gli Agent senza richieste di autorizzazione. Il comando e gli argomenti di ogni agent si trovano in Impostazioni → Agent (Comando) e in settings.json (agents.launch), e vengono usati così come li scrivi. Rimuovi lì --chrome per avviare Claude Code senza Claude in Chrome. Se gli argomenti scelgono già una modalità di autorizzazione (per esempio --permission-mode plan, oppure --sandbox workspace-write per Codex), il flag di salto non viene aggiunto.

Se non è selezionato alcun agent, si apre una semplice shell. Il menu + apre un Nuovo terminale, avvia uno dei tuoi agent in una nuova scheda oppure porta a Impostazioni Agent…. La sua casella di ricerca trova anche schede, URL salvati e file.

Rilascia file nel terminale. Trascina file, cartelle o immagini dal Finder (da Esplora file su Windows, dal tuo file manager su Linux) su un riquadro del terminale, e i loro percorsi vengono digitati in quel riquadro, separati da spazi, senza premere Invio. Funziona allo stesso modo mentre un agent è in esecuzione: Claude Code legge il percorso di un'immagine rilasciata come un'immagine. Le righe trascinate da File (più di una alla volta, se le selezioni) funzionano allo stesso modo: il percorso è relativo alla cartella del progetto finché il terminale si trova lì, e assoluto dopo che hai fatto cd altrove. I percorsi con spazi o altri caratteri speciali vengono racchiusi tra virgolette per la shell: '…' in zsh e bash, "…" nel Prompt dei comandi e '…' in PowerShell.

Le schede mostrano lo stato dell'agent: In esecuzione, In attesa di input, Fatto (non letto), Inattivo. Fatto (non letto) significa che l'agent ha finito mentre guardavi un'altra scheda; diventa Inattivo appena apri quella scheda. La barra laterale contrassegna ogni progetto allo stesso modo, così lo vedi senza cambiare progetto: barre in movimento mentre un agent è in esecuzione, un punto interrogativo mentre uno ti sta aspettando, e un segno di spunta quando gli agent di quel progetto hanno finito e non hai ancora aperto la scheda.

Notifiche. Attiva Impostazioni → Agent → Avvisami quando gli agenti finiscono o hanno bisogno di me per ricevere una notifica di sistema quando tutti gli agent di un progetto hanno finito, o quando un agent attende un'autorizzazione o una risposta. Per la scheda che stai guardando non viene mostrato nulla. Fai clic sulla notifica per passare a quel progetto e aprire la scheda.

{{clip:terminals|Trascinare schede e riquadri del terminale per dividerli, spostarli e trasformarli di nuovo in schede.}}

Trascina per dividere. Trascina una scheda, oppure un riquadro tramite la sua maniglia (visibile quando una scheda è divisa), e rilasciala:

  • sul quarto esterno del bordo di un riquadro: Dividi a sinistra / Dividi a destra / Dividi in alto / Dividi in basso
  • al centro di un riquadro: Apri come scheda (un riquadro esce dalla divisione e diventa una scheda a sé)
  • sulla sottile fascia attorno all'intera area del terminale: Dividi l'intera area a sinistra e così via (quando ci sono 2 o più riquadri)
  • sulla barra delle schede: Posiziona qui come scheda

I processi continuano a girare mentre li sposti, e una scheda rimasta vuota si chiude. Divisioni da tastiera:

## Ritrovare i terminali dopo un riavvio

Quando Ferret si chiude, ricorda le schede del terminale di ogni progetto: ordine e divisioni, la cartella in cui è stata aperta ciascuna, l’agente e l’account con cui girava e fino a 2.000 righe di ogni schermo. Al successivo avvio di Ferret le schede tornano nello stesso ordine. Prima compare il testo precedente, poi una riga attenuata come — Continua dalla sessione precedente (2026-10-05 14:30) —, e quindi parte una nuova shell nella stessa cartella.

Le schede degli agenti ripartono con la loro conversazione: Claude Code con --continue e Codex con resume --last, che riprendono la conversazione più recente di quella cartella. Se più schede eseguono lo stesso agente nella stessa cartella con lo stesso account, solo la prima la riprende e le altre ripartono da zero, così due schede non riprendono mai la stessa conversazione. Se Claude Code non ha conversazioni in quella cartella, o il progetto è su un host SSH, si avvia normalmente.

Riaprire un terminale chiuso. Terminale → Riapri terminale chiuso ({{keys:Mod+Shift+T}} quando un terminale ha il focus) ripristina l’ultima scheda o riquadro chiuso in questo progetto, con il suo testo, e riprende il suo agente allo stesso modo. Vengono conservati gli ultimi 10 terminali chiusi, anche tra un riavvio e l’altro.

La cronologia è salvata come testo semplice, senza colori, nella cartella dati di Ferret (terminal-restore.json, leggibile solo da te), mai nel progetto. Le schede di accesso aperte da Aggiungi account e i comandi una tantum non vengono conservati. Per smettere di salvarla, disattiva Impostazioni → Agent → Salva la cronologia del terminale e ripristinala; anche ciò che è stato salvato viene eliminato. Elimina la cronologia salvata, lì accanto, la elimina in qualsiasi momento.

Impostazioni → Agent li elenca con Installato / Non trovato, un pulsante Installa dove il produttore pubblica un programma di installazione da una riga, e il comando e gli argomenti di ciascuno.

Non è nell'elenco? ## Invia all'Agent / Copia per l'Agent {{clip:send|Dalla scheda Segnalazioni all'agent nel terminale integrato con Invia all'Agent.}}
  1. Fai clic su Invia all'Agent. Per impostazione predefinita (Automatico (scheda attuale o un agent in esecuzione)) va all'agent nella scheda del terminale attuale, oppure a uno in esecuzione. Usa la freccia accanto al pulsante (Scegli l'agent a cui inviare) per scegliere un agent o una scheda precisi.
  2. Ferret scrive l'istruzione nell'input dell'agent e la invia. Segui l'avanzamento nel terminale.

Se nessun agent è in esecuzione, Ferret ne avvia uno e invia appena è pronto. Non viene inviato nulla mentre l'agent attende una risposta a una richiesta di autorizzazione: rispondi prima nel terminale.

Copia per l'Agent mette la stessa istruzione negli appunti per un agent che gira altrove (un altro terminale, un IDE o un'app). Vengono considerate solo le segnalazioni impostate su Invia. Il video non è mai incluso.

## Verifica di accettazione con un modello di decisione {{clip:verify|L'agent corregge le segnalazioni e verifica ciascuna con il modello di decisione prima che tu le guardi.}}

Attiva questa opzione e il tuo coding agent controlla il proprio lavoro una volta rispetto a ogni segnalazione prima che tu lo guardi. Ferret non giudica nulla da solo: dà all'agent un modello di decisione (qualsiasi API compatibile con System One) e gli spiega, in feedback.md, come usarlo. Il modello di decisione è la verifica dell'agent stesso, mai una domanda per te: l'agent non ti chiede nulla. Tu confronti solo PRIMA e DOPO e premi OK o NG.

  1. L'agent implementa le segnalazioni.
  2. Per ogni segnalazione cattura uno screenshot DOPO (stesso viewport e stesso stato della pagina dell'immagine PRIMA) e invia al modello di decisione una richiesta con il testo della segnalazione, la sua riga "Fatto quando" e le immagini PRIMA/DOPO.
  3. Il modello di decisione viene chiamato al massimo una volta per segnalazione ogni volta che invii segnalazioni all'agent. Non c'è una seconda valutazione né un ciclo, così un modello che non dice mai "done" non può tenere occupato l'agent all'infinito.
  4. L'agent legge quell'unico risultato. Una segnalazione passa quando P(done) è almeno pari alla soglia (predefinita 0.7) e la scelta è done, e ti arriva così com'è. Altrimenti, se il risultato mostra una differenza chiara che l'agent può correggere, può migliorare la correzione un'altra volta e catturare di nuovo il DOPO, senza valutare di nuovo.
  5. In entrambi i casi l'agent imposta la segnalazione su Da controllare con il suo DOPO, quell'unico punteggio e al massimo una nota di una riga. Una segnalazione fuori ambito o un'API di decisione non raggiungibile non fermano il lavoro: la segnalazione va su Da controllare senza punteggio.
  6. In Segnalazioni, ogni segnalazione che ti aspetta mostra PRIMA, DOPO e il punteggio come elementi di giudizio. OK la segna come fatta; NG con un commento la rimanda all'agent come nuova richiesta, in cui viene valutata di nuovo una volta. L'elenco finale Fatto / Non fatto dell'agent nel terminale include il punteggio di ogni segnalazione e se la correzione è stata migliorata un'altra volta.

Configuralo in Impostazioni → Modello di decisione e attiva Aggiungi la verifica con modello decisionale alle istruzioni dell'agent. Le preimpostazioni si limitano a compilare i campi; ogni campo resta modificabile, e Personalizzato funziona con qualsiasi API compatibile.

Il preset OpenAI usa la Decisions API di OpenAI, che ha un proprio formato di richiesta (input, un elenco di questions e answers). Gli agenti inviano sempre il formato System One al relay: solo per questo preset, il relay converte la richiesta (le immagini BEFORE/AFTER diventano data URL input_image) e riconverte le risposte, quindi le istruzioni per l'agente non cambiano. Usa la tua chiave API di OpenAI, la stessa della trascrizione. OpenAI addebita solo i token di input (0,10 $ per 1M).

Per Ollama, installalo (0.35.1 o successivo per Clef / Clef Flash) e scarica il modello in un terminale. Ferret non esegue programmi di installazione:

ollama pull clef-flash

Le chiavi provengono dal campo della chiave (salvata con le altre chiavi API), da una variabile d'ambiente che indichi tu (l'ambiente dell'app, il .env del progetto oppure ~/.ferret/.env), oppure da apiKey in settings.json. Gli header aggiuntivi possono leggere valori dalle variabili d'ambiente con ${VAR}.

Come la chiave resta fuori dai prompt

Gli agent non vedono mai la tua chiave. Ferret esegue un relay locale su 127.0.0.1 e fornisce a ogni terminale FERRET_DECISION_URL (il relay, con un token per terminale), FERRET_DECISION_MODEL e FERRET_DECISION_IMAGES (per una release vengono impostati anche i vecchi nomi MOVIE_ADE_DECISION_*). Il relay aggiunge la chiave e gli header e inoltra la richiesta senza modificarla, quindi prompt, feedback.md e trascrizioni degli agent non contengono segreti. Il token di ogni terminale consente 500 chiamate, 30 al minuto, 20 M di token e 5 $ (quando il costo è noto), e ogni progetto consente 2.000 chiamate e 20 $ al giorno; raggiunto un limite, il relay risponde 429 con il motivo, e una nuova scheda del terminale riceve un nuovo token. Cambiare le impostazioni del modello di decisione invalida i token dei terminali aperti; i terminali aperti dopo usano le nuove impostazioni.

Cloudflare differisce dalla documentazione di System One in due punti (verificati sull'API reale): le immagini devono essere data URI (data:image/jpeg;base64,…, altrimenti 422 "image must be an embedded base64 data URI"), e la risposta è racchiusa come { "result": { … }, "success": true } (gli errori tornano come { "success": false, "errors": [ … ] }). La preimpostazione Cloudflare imposta Codifica immagini su data URI, gli agent la ricevono come FERRET_DECISION_IMAGE_FORMAT, e le istruzioni dicono loro di leggere .result quando è presente. Il relay lascia passare entrambe le direzioni senza modifiche. Per usare una Global API Key invece di un token API, imposta Autenticazione su Nessuna chiave e aggiungi gli header X-Auth-Email: ${CLOUDFLARE_EMAIL} e X-Auth-Key: ${CLOUDFLARE_API_KEY}.

Solo Clef e Clef Flash leggono le immagini. Con un modello solo testo, disattiva Invia immagini PRIMA/DOPO; l'agent giudica allora solo dal testo, il che è meno affidabile.

Ollama e immagini grandi

Ollama 0.35.0 limita le richieste a /v1/systemone a 64 KiB, quindi le richieste con screenshot falliscono con HTTP 413. Le istruzioni dicono all'agent di ridurre entrambe le immagini a una larghezza massima di 1024px in JPEG (qualità circa 70). Se riceve ancora 413, aggiorna Ollama alla 0.35.1 o successiva, oppure passa a Cloudflare Workers AI.

## Utilizzo delle API nel footer

Le chiamate al modello di decisione passano per il relay, quindi Ferret può contarle. La voce del footer accanto all'indicatore di utilizzo degli agent mostra il modello di decisione e le chiamate, i token e il costo di oggi (per esempio clef-flash · 42 calls · 18.3k tok). Fai clic per vedere i dati di oggi e del mese in corso, suddivisi per progetto, per modello e per tipo (decisione / trascrizione / organizzazione), e le ultime 50 chiamate.

Il costo compare solo quando l'API lo riporta (Vercel AI Gateway lo fa) o quando imposti i prezzi per 1M di token in Impostazioni → Modello di decisione; altrimenti mostra "—". Vengono registrati solo metadati (ora, progetto, modello, stato, latenza, dimensione, numero di immagini, token, costo), mai immagini, testo o chiavi, in ~/.ferret/usage/decision-YYYY-MM.jsonl, un file al mese.

## Aggiungi una stella a Ferret su GitHub

Dopo il tuo primo Invia all'Agent, e quando raggiungi 3, 10 e 30 revisioni completate, Ferret può chiederti di aggiungere una stella su GitHub. Lo chiede al massimo 3 volte, ad almeno 3 giorni di distanza, e mai durante una registrazione. Aggiungi stella su GitHub aggiunge la stella tramite il tuo accesso a gh (oppure apre GitHub se gh non è disponibile), e Non chiedere più interrompe le richieste. Puoi anche aggiungere la stella da Aiuto → Aggiungi una stella a Ferret su GitHub.

## CLI dei servizi

Impostazioni → CLI dei servizi elenca gli strumenti da riga di comando dei servizi che usi spesso, così i tuoi agent possono lavorarci. Installarli è facoltativo: installa solo quello che ti serve; Ferret funziona anche senza. Ogni riga mostra se lo strumento è installato e la sua versione, un link al sito del servizio e pulsanti che eseguono il comando ufficiale di installazione o di accesso per il tuo sistema operativo in una nuova scheda del terminale:

  • Hosting Git: GitHub (gh), GitLab (glab)
  • Hosting e deploy: Vercel, Netlify, Cloudflare (wrangler), Firebase, Fly.io, Railway, Heroku
  • Cloud: AWS, Google Cloud (gcloud), Azure (az)
  • Database e backend: Supabase, Neon, PlanetScale, Turso
  • Errori e monitoraggio: Sentry (sentry-cli), Datadog (datadog-ci)
  • Pagamenti: Stripe
  • Container: Docker, kubectl
  • Mobile: Xcode Command Line Tools (Solo macOS), Android Platform Tools (adb), Expo EAS, fastlane
  • Macchine virtuali: UTM (Solo macOS), Lima, Multipass
  • IA e modelli: Ollama

Se uno strumento non ha un programma di installazione ufficiale da una riga per il tuo sistema operativo, Documentazione apre invece la sua pagina di installazione. Al termine di un'installazione l'elenco si aggiorna da solo.
