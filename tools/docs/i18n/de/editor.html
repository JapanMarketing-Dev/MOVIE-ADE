Editor und Vorschau Öffnen und bearbeiten Sie Projektdateien und zeigen Sie eine Vorschau von Markdown und Mermaid an. Eine im integrierten Browser geöffnete Vorschau lässt sich wie jede Webseite aufnehmen und prüfen. ## Dateien öffnen und bearbeiten
  • Dateien (der Dateibaum): {{keys:Mod+Shift+E}}, mit Nach Dateiname filtern, Aktualisieren und Alle einklappen.
  • Gehe zu Datei …: {{keys:Mod+P}}.
  • Ziehen Sie eine Datei aus dem Finder (unter Windows aus dem Datei-Explorer, unter Linux aus Ihrem Dateimanager) auf die Tableiste oder den Editor, um sie zu öffnen. Dateien im Projekt öffnen sich im Editor oder in einem Viewer. Um eine Datei von außerhalb ins Projekt zu holen, legen Sie sie auf Dateien ab; sie wird dann ins Projekt kopiert. Ein hier abgelegter Ordner wird als Projekt geöffnet. Aus Dateien gezogene Dateien öffnen sich auf dieselbe Weise. Bilder und Videos, die Sie auf einer geöffneten Markdown-Datei ablegen, werden stattdessen darin eingebettet (siehe Bilder und Videos in Markdown einbetten).
  • Speichern mit {{keys:Mod+S}}. Beim Schließen einer geänderten Datei fragt Ferret Änderungen an <name> sichern? mit Speichern, Nicht sichern und Abbrechen.
  • Ändert sich die Datei auf der Festplatte, während Sie ungesicherte Änderungen haben, wählen Sie Von Festplatte neu laden oder Meine Änderungen behalten.

Der Editor ist Monaco. Dateien, die kein Text sind, öffnen sich stattdessen in einem Viewer: Bilder (vergrößern und verkleinern; SVG lässt sich auch als Code anzeigen), Video und Audio mit Suchleiste, PDF und bei jeder anderen Binärdatei deren Größe und eine Hex-Ansicht der ersten Bytes. Viewer sind schreibgeschützt. Dateien außerhalb des Projektordners oder solche, die über einen symbolischen Link erreicht werden, der aus dem Ordner herausführt, werden nicht angezeigt.

## Mit Dateien im Dateibaum arbeiten

Arbeiten Sie direkt in Dateien mit Dateien, so wie in VS Code. Klicken Sie mit der rechten Maustaste auf ein Element oder auf die freie Fläche unter dem Baum, um auf der obersten Ebene des Projekts zu arbeiten. Namen geben Sie direkt im Baum ein.

  • Neue Datei / Neuer Ordner: die Schaltflächen über dem Baum oder Rechtsklick. Ein neues Element landet im ausgewählten Ordner, neben der ausgewählten Datei oder auf der obersten Ebene des Projekts. Geben Sie einen Namen mit Schrägstrichen ein, etwa src/routes/index.ts, um die Ordner auf dem Weg gleich mit anzulegen. Eine neue Datei öffnet sich im Editor. In einem leeren Ordner zeigt Dateien Dieser Ordner ist leer mit den Schaltflächen Neue Datei und Neuer Ordner.
  • Ausschneiden, Kopieren und Einfügen: {{keys:Mod+X}}, {{keys:Mod+C}}, {{keys:Mod+V}} oder Rechtsklick. Ordner werden mit ihrem gesamten Inhalt kopiert. Duplizieren legt eine Kopie neben dem Original an. Ist der Name schon vergeben, heißt die Kopie name copy, dann name copy 2.
  • Ziehen Sie Elemente auf einen Ordner (oder auf die freie Fläche für die oberste Ebene des Projekts), um sie zu verschieben. Halten Sie beim Ablegen {{keys:Alt|Ctrl}} gedrückt, um stattdessen zu kopieren. Dateien und Ordner, die Sie aus dem Finder (unter Windows aus dem Datei-Explorer) hineinziehen, werden ins Projekt kopiert; die Originale bleiben, wo sie waren.
  • Umbenennen: {{keys:F2 / Enter|F2}} oder Rechtsklick.
  • Löschen: {{keys:Mod+Backspace / Delete|Delete}} oder Rechtsklick. Ferret fragt zuerst nach und verschiebt das Element dann in den Papierkorb, sodass Sie es wiederherstellen können. Tabs gelöschter Dateien werden geschlossen; hatte einer davon ungesicherte Änderungen, weist die Rückfrage darauf hin.
  • Rückgängig: {{keys:Mod+Z}} macht das letzte neue Element, Umbenennen, Verschieben, Einfügen oder Duplizieren rückgängig. Gelöschte Elemente werden aus dem Papierkorb wiederhergestellt.
  • Pfad kopieren ({{keys:Alt+Mod+C|Shift+Alt+C}}) und Relativen Pfad kopieren ({{keys:Alt+Shift+Mod+C|Ctrl+Shift+Alt+C}}) legen den Pfad in die Zwischenablage.
  • Im Finder anzeigen (Im Datei-Explorer anzeigen unter Windows, Übergeordneten Ordner öffnen unter Linux): {{keys:Alt+Mod+R|Shift+Alt+R}}. Im Terminal öffnen öffnet einen neuen Terminal-Tab in diesem Ordner (bei einer Datei in ihrem Ordner).
  • Bei einer Datei öffnet Öffnen sie im Editor, und Mit Standard-App öffnen öffnet sie in der App, die Ihr Betriebssystem für diesen Typ verwendet.
  • Wählen Sie mehrere Elemente mit {{keys:Mod}}-Klick oder {{keys:Shift}}-Klick aus, um sie gemeinsam auszuschneiden, zu kopieren, zu verschieben oder zu löschen.
  • {{keys:Esc}} bricht die Eingabe eines Namens ab.

Geöffnete Tabs folgen einer umbenannten oder verschobenen Datei und behalten ungesicherte Änderungen. Ferret überschreibt keine vorhandene Datei und keinen vorhandenen Ordner mit demselben Namen und hält alles innerhalb des Projektordners: Abgelehnt werden .., absolute Pfade, symbolische Links, die nach außen zeigen, alles innerhalb von .git, das Verschieben eines Ordners in sich selbst sowie Namen, die ein Betriebssystem nicht verwenden kann: / \ < > : " | ? *, Steuerzeichen, ein Leerzeichen oder Punkt am Ende und unter Windows reservierte Namen wie CON oder NUL. Ein einzelner Kopier- oder Ablegevorgang kann bis zu 10.000 Elemente und 1 GB umfassen.

## Markdown- und Mermaid-Vorschau

Die Vorschau funktioniert für .md, .markdown, .mdx, .mmd und .mermaid. Mermaid ist in die App eingebaut, daher werden Diagramme auch offline gerendert.

Eine Markdown-Datei hat oben im Editor zwei Ansichten: Quelltext und Vorschau. Die Vorschau ist immer bearbeitbar, Sie können also direkt darin tippen; mit Quelltext kehren Sie zum Text zurück. Beide zeigen denselben Inhalt, und Speichern, die Markierung für ungesicherte Änderungen und die Rückfrage beim Schließen funktionieren gleich.

  • Tippen Sie direkt in Überschriften, Absätze, Listen, Kontrollkästchen, Tabellen, Links sowie fetten, kursiven oder Inline-Code. Wenn Sie am Zeilenanfang #, -, 1. oder > und ein Leerzeichen eingeben, beginnt eine Überschrift, eine Liste oder ein Zitat.
  • Codeblöcke und Mermaid-Diagramme bearbeiten Sie als Quelltext; die Sprache wird in der Ecke angezeigt. Um das Diagramm gezeichnet zu sehen, öffnen Sie die Datei unter Dateien im Bereich Review-Ziele.
  • Front Matter (der ----Block am Anfang) wird als Text über dem Dokument angezeigt und kann dort bearbeitet werden.
  • Teile, die Sie nicht ändern, werden genau so gespeichert, wie sie geschrieben sind, einschließlich Überschriftenstil, Listenzeichen, Leerzeilen, Tabellenausrichtung und Zeilenenden. Ein bearbeiteter Block behält seinen Stil, wo möglich; andernfalls wird dieser Block in einer Standard-Markdown-Form geschrieben, mit - für Listen und # für Überschriften.
  • Bilder und Videos im Projekt werden angezeigt. Bilder von anderen Websites werden nicht geladen; stattdessen wird ihr Hostname angezeigt. Anderes HTML in der Datei wird als Text angezeigt.

.mdx-Dateien (nur als Quelltext bearbeitet) sowie .mmd- und .mermaid-Dateien haben stattdessen eine schreibgeschützte Vorschau:

  • Vorschau seitlich öffnen: neben dem Editor
  • Vorschau öffnen: im integrierten Browser (ade-preview://), sodass Sie sie aufnehmen und prüfen können
## Bilder und Videos in Markdown einbetten

Ziehen Sie Bilder (PNG, JPEG, GIF, WebP, SVG, AVIF) oder Videos (MP4, WebM, MOV) auf eine Markdown-Datei, in Quelltext oder Vorschau, um sie an der Ablagestelle einzubetten.

  • Dateien, die bereits im Projekt liegen, auch solche, die aus Dateien gezogen werden, werden mit einem Pfad relativ zur Markdown-Datei verlinkt. Es wird nichts kopiert.
  • Dateien von außerhalb des Projekts (Finder, Schreibtisch, unter Windows der Datei-Explorer) werden zuerst in einen Ordner neben der Markdown-Datei kopiert: assets, images, media oder img, falls einer davon schon existiert, sonst in einen neuen Ordner assets. Leerzeichen im Namen werden zu -, und ist der Name schon vergeben, heißt die Kopie name-2. Die Originale bleiben, wo sie waren.
  • Bilder werden als ![name](assets/name.png) geschrieben und Videos als <video src="assets/name.mp4" controls></video>, was auch GitHub abspielt. Beides wird in Vorschau angezeigt.
  • Ein Bild darf bis zu 50 MB und ein Video bis zu 500 MB groß sein, und eine Ablage kopiert bis zu 50 Dateien und 1 GB. Andere Dateien, die zusammen mit ihnen abgelegt werden, öffnen sich wie gewohnt im Editor.
## Dokumentation per Aufnahme prüfen
  1. Öffnen Sie im Bereich Review-Ziele die Markdown-Datei unter Dateien. Sie öffnet sich als Vorschau im integrierten Browser.
  2. Nehmen Sie wie gewohnt auf. Gehen Sie die Spezifikation oder das Design-Dokument sprechend durch und kreisen Sie ein, was falsch ist.
  3. Stoppen Sie. Die Befunde verweisen statt auf eine URL auf den projektrelativen Pfad der Datei.
  4. Mit An Agent senden lassen Sie das Dokument korrigieren.
