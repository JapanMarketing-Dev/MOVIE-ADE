An Agents senden Führen Sie Ihren Coding-Agent im integrierten Terminal aus und übergeben Sie ihm ein Review mit einem Klick. Claude Code und Codex sind die üblichen Beispiele, aber jeder Agent aus der Liste unten funktioniert, ebenso eine CLI, die Sie selbst hinzufügen. Sie können die Anweisung auch für einen Agent kopieren, der anderswo läuft. ## Befunde eines Reviews

Jede Karte im Tab Befunde bietet:

  • Direktes Bearbeiten von Titel und Anforderung
  • Umschalter Senden / Nicht senden
  • Aufnahme ansehen (springt zu dieser Stelle) und Bild ersetzen (ein anderes Einzelbild wählen)
  • Bestätigen, Löschen

Nach Fortschritt filtern blendet Befunde nach Status ein oder aus (zum Beispiel Nur die, die auf Ihre Prüfung warten); Alle anzeigen hebt den Filter auf.

Um Befunde neu anzuordnen, ziehen Sie den Griff links neben dem Titel einer Karte, oder wählen Sie den Griff aus und drücken Sie ↑ / ↓. Die Nummern, feedback.md und das, was Sie an den Agent senden, folgen der neuen Reihenfolge. Bei aktivem Filter ändert sich die Reihenfolge unter den sichtbaren Befunden, ausgeblendete Befunde behalten ihren Platz. Umfasst eine Review mehrere Seiten oder Dateien, werden Befunde innerhalb ihrer eigenen Gruppe verschoben. Befunde sortieren in der Kopfzeile wechselt zwischen Manuell (Ziehreihenfolge), Aufnahmezeit und Fortschritt (nicht begonnene zuerst, erledigte zuletzt); das Sortieren nach Fortschritt speichert diese Reihenfolge als manuelle Reihenfolge.

In der Kopfzeile finden Sie Widerrufen, Ordner öffnen, Für Agent kopieren, Ordnen und An Agent senden. Gesprochenes, das nicht zu einem Befund wurde, steht unter Ausgeschlossene Sprache; dort holt Als Befund wiederherstellen es zurück. Sprache ohne sinnvolle Worte wird nie zu einem Befund und steht ebenfalls dort: Sätze, die die Transkription manchmal aus Stille erfindet, etwa „Shh.“ oder „Danke fürs Zuschauen“, Füllwörter wie „äh“ und ein bloßes „OK“ oder „ja“ ohne Stiftmarkierung.

{{shot:findings|Der Tab „Befunde“}} ## Agents im integrierten Terminal ausführen

Wenn ein Projekt geöffnet wird, startet Ferret für jeden Agent unter Einstellungen → Agents → Beim Öffnen eines Projekts starten einen Terminal-Tab im Projektordner. Standardmäßig sind das Claude Code und Codex, gestartet ohne Berechtigungsabfragen und mit aktiviertem Claude in Chrome:

claude --dangerously-skip-permissions --chrome
codex --dangerously-bypass-approvals-and-sandbox

Sie können stattdessen beliebige Agents aus der Liste der unterstützten Agents wählen (sie starten in der Reihenfolge, in der Sie sie auswählen) oder gar keinen.

Agents, die Sie selbst öffnen, starten auf dieselbe Weise. Ferret markiert den Projektordner außerdem für Claude Code und Codex als vertrauenswürdig, sodass sie nicht nach dem Ordner fragen. Um sie im normalen Modus zu starten, in dem sie nachfragen, bevor sie einem Ordner vertrauen, Dateien bearbeiten oder Befehle ausführen, deaktivieren Sie Einstellungen → Agents → Agents ohne Berechtigungsabfragen starten. Befehl und Argumente jedes Agents finden Sie unter Einstellungen → Agents (Befehl) und in settings.json (agents.launch); sie werden so verwendet, wie Sie sie eintragen. Entfernen Sie dort --chrome, um Claude Code ohne Claude in Chrome zu starten. Wählen die Argumente bereits einen Berechtigungsmodus (zum Beispiel --permission-mode plan oder bei Codex --sandbox workspace-write), wird das Skip-Flag nicht hinzugefügt.

Ist kein Agent ausgewählt, öffnet sich eine normale Shell. Das Menü + öffnet ein Neues Terminal, startet einen Ihrer Agents in einem neuen Tab oder springt zu den Agent-Einstellungen …. Sein Suchfeld findet außerdem Tabs, gespeicherte URLs und Dateien.

Dateien ins Terminal ziehen. Ziehen Sie Dateien, Ordner oder Bilder aus dem Finder (unter Windows aus dem Datei-Explorer, unter Linux aus Ihrem Dateimanager) auf einen Terminalbereich, und ihre Pfade werden durch Leerzeichen getrennt in diesen Bereich eingegeben, ohne Enter zu drücken. Das funktioniert genauso, während ein Agent läuft: Claude Code liest einen abgelegten Bildpfad als Bild. Zeilen, die Sie aus Dateien ziehen (mehrere auf einmal, wenn Sie sie auswählen), verhalten sich genauso: Der Pfad ist relativ zum Projektordner, solange sich das Terminal darin befindet, und absolut, nachdem Sie mit cd woandershin gewechselt haben. Pfade mit Leerzeichen oder anderen Sonderzeichen werden für die Shell in Anführungszeichen gesetzt: '…' in zsh und bash, "…" in der Eingabeaufforderung und '…' in PowerShell.

Tabs zeigen den Zustand des Agents: Läuft, Wartet auf Eingabe, Fertig (ungelesen), Inaktiv. Fertig (ungelesen) bedeutet, dass der Agent fertig geworden ist, während Sie einen anderen Tab angesehen haben; sobald Sie diesen Tab öffnen, wird daraus Inaktiv. Die Seitenleiste markiert jedes Projekt auf dieselbe Weise, sodass Sie es sehen, ohne das Projekt zu wechseln: bewegte Balken, während ein Agent läuft, ein Fragezeichen, während einer auf Sie wartet, und ein Häkchen, wenn die Agents dort fertig sind und Sie den Tab noch nicht geöffnet haben.

Benachrichtigungen. Aktivieren Sie Einstellungen → Agents → Benachrichtigen, wenn Agents fertig sind oder mich brauchen, um eine Systembenachrichtigung zu erhalten, wenn alle Agents in einem Projekt fertig sind oder wenn ein Agent auf eine Berechtigung oder eine Antwort wartet. Für den Tab, den Sie gerade ansehen, wird nichts angezeigt. Klicken Sie auf die Benachrichtigung, um zu diesem Projekt zu wechseln und den Tab zu öffnen.

## Unterstützte Agents

Ferret ist nicht an einen bestimmten Agent gebunden. Es erkennt die folgenden Coding-Agents: Es kann sie starten, sie für An Agent senden in einem Terminal erkennen und anzeigen, ob sie installiert sind. Einstellungen → Agents listet sie mit Installiert / Nicht gefunden auf, mit einer Schaltfläche Installieren, wo der Anbieter einen einzeiligen Installer veröffentlicht, sowie mit Befehl und Argumenten für jeden Agent.

{{agent-catalog}}

Nicht in der Liste? Einstellungen → Agents → Eigenen Agent hinzufügen registriert eine beliebige CLI oder ein Wrapper-Skript (einen Namen, einen Befehl und optional den Prozessnamen, an dem er erkannt wird), oder Sie fügen ihn unter agents.customAgents in der settings.json hinzu. Agents, die außerhalb von Ferret laufen, können Für Agent kopieren nutzen.

Einige Funktionen hängen vom Agent ab und sind vorerst auf Claude Code und Codex beschränkt:

  • Konten und Nutzung: Wechsel zwischen mehreren Logins und die Rate-Limit-Anzeige in der Fußzeile.
  • Ordnen: läuft über Ihr Claude-Code- oder Codex-Login oder über eine LLM-API, die Sie konfigurieren.
## An Agent senden / Für Agent kopieren {{clip:send|Vom Tab „Befunde“ mit „An Agent senden“ zum Agent im integrierten Terminal.}}
  1. Klicken Sie auf An Agent senden. Standardmäßig (Automatisch (aktueller Tab oder laufender Agent)) geht das Review an den Agent im aktuellen Terminal-Tab oder an einen laufenden Agent. Mit dem Pfeil neben der Schaltfläche (Agent zum Senden wählen) wählen Sie einen bestimmten Agent oder Tab.
  2. Ferret schreibt die Anweisung in die Eingabe des Agents und sendet sie ab. Den Fortschritt verfolgen Sie im Terminal.

Läuft kein Agent, startet Ferret zuerst einen und sendet, sobald er bereit ist. Solange der Agent auf die Antwort zu einer Berechtigungsabfrage wartet, wird nichts gesendet. Antworten Sie zuerst im Terminal.

Für Agent kopieren legt dieselbe Anweisung in die Zwischenablage, für einen Agent, der anderswo läuft (ein anderes Terminal, eine IDE oder eine App). Berücksichtigt werden nur Befunde, die auf Senden gestellt sind. Das Video wird nie mitgeschickt.

## Abnahmeprüfung mit einem Entscheidungsmodell {{clip:verify|Der Agent behebt die Befunde und prüft jeden mit dem Entscheidungsmodell, bevor Sie sie ansehen.}}

Schalten Sie dies ein, und Ihr Coding-Agent prüft seine eigene Arbeit einmal anhand jedes Befunds, bevor Sie sie ansehen. Ferret beurteilt selbst nichts: Es gibt dem Agent ein Entscheidungsmodell (eine beliebige System-One-kompatible API) und erklärt ihm in der feedback.md, wie er es nutzt. Das Entscheidungsmodell ist die eigene Prüfung des Agent, nie eine Frage an Sie: Der Agent fragt Sie nichts. Sie vergleichen nur VORHER und NACHHER und drücken OK oder NG.

  1. Der Agent setzt die Befunde um.
  2. Für jeden Befund erstellt er einen AFTER-Screenshot (gleicher Viewport und gleicher Seitenzustand wie das BEFORE-Standbild) und sendet eine Anfrage mit dem Text des Befunds, seiner Zeile „Done when“ und den BEFORE/AFTER-Bildern an das Entscheidungsmodell.
  3. Das Entscheidungsmodell wird höchstens einmal pro Befund aufgerufen, jedes Mal, wenn Sie Befunde an den Agent senden. Es gibt keine zweite Bewertung und keine Schleife, sodass ein Modell, das nie „done“ sagt, den Agent nicht endlos beschäftigen kann.
  4. Der Agent liest dieses eine Ergebnis. Ein Befund besteht, wenn P(done) mindestens den Schwellenwert erreicht (Standard 0,7) und die Wahl done lautet, und geht so, wie er ist, an Sie. Zeigt das Ergebnis sonst eine klare Lücke, die der Agent beheben kann, darf er die Korrektur noch einmal verbessern und NACHHER erneut erfassen, ohne erneut zu bewerten.
  5. In beiden Fällen setzt der Agent den Befund auf Zu prüfen, mit seinem NACHHER, diesem einen Wert und höchstens einer einzeiligen Notiz. Ein Befund außerhalb des Umfangs oder eine nicht erreichbare Entscheidungs-API halten die Arbeit nicht auf: Der Befund kommt ohne Wert auf Zu prüfen.
  6. Unter Befunde zeigt jeder Befund, der auf Sie wartet, VORHER, NACHHER und den Wert als Grundlage. OK markiert ihn als erledigt; NG mit einem Kommentar schickt ihn als neue Anfrage an den Agent zurück, in der er wieder einmal bewertet wird. Die abschließende Liste „Erledigt“ / „Nicht erledigt“ des Agent im Terminal enthält den Wert jedes Befunds und ob er die Korrektur noch einmal verbessert hat.

Richten Sie es unter Einstellungen → Entscheidungsmodell ein und aktivieren Sie Entscheidungsmodell-Prüfung zu Agent-Anweisungen hinzufügen. Voreinstellungen füllen nur die Felder aus; jedes Feld bleibt bearbeitbar, und Benutzerdefiniert funktioniert mit jeder kompatiblen API.

Für Ollama installieren Sie es (0.35.1 oder neuer für Clef / Clef Flash) und laden das Modell in einem Terminal herunter. Ferret führt keine Installer aus:

ollama pull clef-flash

Schlüssel kommen aus dem Schlüsselfeld (zusammen mit Ihren anderen API-Schlüsseln gespeichert), aus einer von Ihnen benannten Umgebungsvariable (aus der Umgebung der App, der .env des Projekts oder ~/.ferret/.env) oder aus apiKey in der settings.json. Zusätzliche Header können mit ${VAR} Werte aus Umgebungsvariablen lesen.

Wie der Schlüssel aus den Prompts herausgehalten wird

Agents sehen Ihren Schlüssel nie. Ferret betreibt ein lokales Relay auf 127.0.0.1 und gibt jedem Terminal FERRET_DECISION_URL (das Relay, mit einem Token pro Terminal), FERRET_DECISION_MODEL und FERRET_DECISION_IMAGES (für ein Release werden zusätzlich die alten Namen MOVIE_ADE_DECISION_* gesetzt). Das Relay fügt Schlüssel und Header hinzu und leitet die Anfrage unverändert weiter, sodass Prompts, feedback.md und Agent-Transkripte keine Geheimnisse enthalten. Das Token jedes Terminals erlaubt 500 Aufrufe, 30 pro Minute, 20 Mio. Tokens und 5 $ (wenn die Kosten bekannt sind), und jedes Projekt erlaubt 2.000 Aufrufe und 20 $ pro Tag; ist ein Limit erreicht, antwortet das Relay mit 429 und dem Grund, und ein neuer Terminal-Tab erhält ein neues Token. Wenn Sie die Einstellungen des Entscheidungsmodells ändern, werden die Tokens offener Terminals ungültig; danach geöffnete Terminals verwenden die neuen Einstellungen.

Cloudflare weicht in zwei Punkten von der System-One-Dokumentation ab (geprüft gegen die Live-API): Bilder müssen Data-URIs sein (data:image/jpeg;base64,…, sonst 422 „image must be an embedded base64 data URI“), und die Antwort ist als { "result": { … }, "success": true } verpackt (Fehler kommen als { "success": false, "errors": [ … ] } zurück). Die Cloudflare-Voreinstellung setzt Bildkodierung auf Data-URI, Agents erhalten dies als FERRET_DECISION_IMAGE_FORMAT, und die Anweisungen fordern sie auf, .result zu lesen, wenn vorhanden. Das Relay reicht beide Richtungen unverändert durch. Um statt eines API-Tokens einen Global API Key zu verwenden, setzen Sie Authentifizierung auf Kein Schlüssel und fügen die Header X-Auth-Email: ${CLOUDFLARE_EMAIL} und X-Auth-Key: ${CLOUDFLARE_API_KEY} hinzu.

Nur Clef und Clef Flash lesen Bilder. Bei einem reinen Textmodell schalten Sie VORHER/NACHHER-Bilder senden aus; der Agent urteilt dann nur anhand von Text, was weniger zuverlässig ist.

Ollama und große Bilder

Ollama 0.35.0 begrenzt Anfragen an /v1/systemone auf 64 KiB, daher schlagen Anfragen mit Screenshots mit HTTP 413 fehl. Die Anweisungen fordern den Agent auf, beide Bilder auf höchstens 1024px Breite als JPEG (Qualität etwa 70) zu verkleinern. Erhält er trotzdem 413, aktualisieren Sie Ollama auf 0.35.1 oder neuer oder wechseln Sie zu Cloudflare Workers AI.

## API-Nutzung in der Fußzeile

Entscheidungsaufrufe laufen über das Relay, daher kann Ferret sie zählen. Der Eintrag in der Fußzeile neben der Nutzungsanzeige des Agents zeigt das Entscheidungsmodell sowie die Aufrufe, Tokens und Kosten des heutigen Tages (zum Beispiel clef-flash · 42 calls · 18.3k tok). Ein Klick darauf zeigt die Werte für heute, diesen Monat, pro Projekt, pro Modell und pro Art (Entscheidung / Transkription / Ordnen) sowie die letzten 50 Aufrufe.

Kosten erscheinen nur, wenn die API sie meldet (Vercel AI Gateway tut das) oder wenn Sie unter Einstellungen → Entscheidungsmodell Preise pro 1 Mio. Tokens festlegen; andernfalls wird „—“ angezeigt. Protokolliert werden nur Metadaten (Zeit, Projekt, Modell, Status, Latenz, Größe, Bildanzahl, Tokens, Kosten), nie Bilder, Text oder Schlüssel, und zwar in ~/.ferret/usage/decision-YYYY-MM.jsonl, eine Datei pro Monat.

## Anweisung anpassen

Bearbeiten Sie Einstellungen → Agents → Anweisungen für Agent. Zwei Variablen werden ersetzt:

VariableWird ersetzt durch
{{path}}Absoluter Pfad der feedback.md
{{relpath}}Pfad relativ zum Projekt: .ferret/reviews/<id>/feedback.md

Lassen Sie das Feld leer, um die Standardanweisung zu verwenden. Die maximale Länge beträgt 2000 Zeichen, und Anweisungen zurücksetzen stellt die Standardanweisung wieder her. Beispiel:

Read {{relpath}} and the PNGs next to it. Fix only findings marked to send, one commit per finding, then run the tests.

Die Einstellung wird als agentPrompt in der settings.json gespeichert.

## Ferret auf GitHub einen Stern geben

Nach Ihrem ersten An Agent senden sowie bei 3, 10 und 30 abgeschlossenen Reviews bittet Ferret Sie möglicherweise, ihm auf GitHub einen Stern zu geben. Es fragt höchstens 3-mal, mit mindestens 3 Tagen Abstand, und nie während einer Aufnahme. Stern auf GitHub geben vergibt den Stern über Ihr eigenes gh-Login (oder öffnet GitHub, wenn gh nicht verfügbar ist), und Nicht mehr fragen beendet die Nachfragen. Sie können auch über Hilfe → Ferret auf GitHub einen Stern geben einen Stern vergeben.

## Dienst-CLIs

Einstellungen → Dienst-CLIs listet die Kommandozeilen-Tools häufig genutzter Dienste auf, damit Ihre Agents damit arbeiten können. Die Installation ist optional: Installieren Sie nur, was Sie brauchen; Ferret funktioniert auch ohne sie. Jede Zeile zeigt, ob das Tool installiert ist und in welcher Version, einen Link zur Website des Dienstes und Schaltflächen, die den offiziellen Installations- oder Anmeldebefehl für Ihr Betriebssystem in einem neuen Terminal-Tab ausführen:

  • Git-Hosting: GitHub (gh), GitLab (glab)
  • Hosting & Deployment: Vercel, Netlify, Cloudflare (wrangler), Firebase, Fly.io, Railway, Heroku
  • Cloud: AWS, Google Cloud (gcloud), Azure (az)
  • Datenbanken & Backend: Supabase, Neon, PlanetScale, Turso
  • Fehler & Monitoring: Sentry (sentry-cli), Datadog (datadog-ci)
  • Zahlungen: Stripe
  • Container: Docker, kubectl
  • Mobil: Xcode Command Line Tools (Nur macOS), Android Platform Tools (adb), Expo EAS, fastlane
  • Virtuelle Maschinen: UTM (Nur macOS), Lima, Multipass
  • KI & Modelle: Ollama

Hat ein Tool für Ihr Betriebssystem keinen offiziellen einzeiligen Installer, öffnet Doku stattdessen dessen Installationsseite. Die Liste prüft von selbst erneut, sobald eine Installation abgeschlossen ist.
