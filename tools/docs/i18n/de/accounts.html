Konten und Nutzung Wechseln Sie zwischen mehreren Logins für Claude Code oder Codex und behalten Sie Ihre Rate-Limit-Zeitfenster in der Fußleiste im Blick. Beide Funktionen gibt es vorerst nur für Claude Code und Codex; andere Agents verwenden wie gewohnt ihr eigenes Login. ## Mehrere Konten

Konten sind optional. Fügen Sie sie nur hinzu, wenn Sie zwischen mehreren wechseln.

  1. Öffnen Sie Einstellungen → Konten oder im Nutzungsmenü der Fußleiste Konten verwalten ….
  2. Konto hinzufügen startet das Login des Agents in einem Terminal-Tab innerhalb der App.
  3. Wählen Sie das Konto aus, das verwendet werden soll. Laufende Tabs behalten ihr Konto, neue Tabs verwenden das ausgewählte.

So funktioniert es: Jedes hinzugefügte Konto erhält einen eigenen Konfigurationsordner, <userData>/accounts/<agent>/<id>/. Ferret startet den Agent mit CLAUDE_CONFIG_DIR (Claude Code) bzw. CODEX_HOME (Codex), das auf diesen Ordner zeigt. Systemstandard verwendet unverändert Ihr übliches ~/.claude / ~/.codex.

Wenn Sie ein Konto entfernen, wird sein Konfigurationsordner gelöscht. Auf dem Server werden Sie dadurch nicht abgemeldet.

## Nutzung in der Fußleiste

Die Fußleiste zeigt, wie viel von jedem Rate-Limit-Zeitfenster verbraucht ist: das 5-Stunden-Fenster und das Wochenfenster, bei Claude zusätzlich das Wochenfenster pro Modell. Die Farbe wechselt ab 60 % zu Gelb und ab 80 % zu Rot. Die Werte werden alle 15 Minuten aktualisiert oder wenn Sie auf Nutzung aktualisieren klicken.

Wie viel angezeigt wird, hängt vom Platz in der Fußleiste ab. Ist genug Platz vorhanden, erscheinen Balken, Namen der Zeitfenster und Prozentwerte. Wird die Fußleiste schmaler, fallen zuerst die weniger wichtigen Teile weg, bis nur noch ein Prozentwert pro Agent übrig ist. Klicken Sie auf die Nutzung, um alles in einem Popover zu sehen.

Die Nutzung wird direkt bei Anthropic (api.anthropic.com/api/oauth/usage) und ChatGPT (chatgpt.com/backend-api/wham/usage) abgefragt, mit den eigenen Zugangsdaten des angemeldeten Kontos.

Erreicht ein Agent sein Nutzungslimit, setzt Ferret dieselbe Arbeit im selben Projektordner fort, sodass eine lange Aufgabe nicht am Limit stehen bleibt. Das ist standardmäßig aktiviert und wird unter Einstellungen → Konten → Wechsel bei Nutzungslimits eingestellt.

Die Arbeit wird über eine einzige Datei im Projekt übergeben, .ferret/handoff.md, daher funktioniert das zwischen Konten ebenso wie zwischen verschiedenen Agents. Die Anweisungen von An Agent senden bitten den Agent, diese Datei bei jedem Zwischenziel und kurz vor einem Nutzungslimit aktuell zu halten: das Ziel, was erledigt ist, die verbleibende Arbeit als Checkliste, die geänderten Dateien, den nächsten Schritt, die zugehörigen Pfade von feedback.md und Reviews sowie alles, worauf zu achten ist. .ferret/ bleibt außerhalb von git (es wird in .git/info/exclude eingetragen, nicht in .gitignore).

  1. Ferret erkennt das Limit an der eigenen Meldung des Agents im Terminal (zum Beispiel 5-hour limit reached ∙ resets 3pm in Claude Code, You've hit your usage limit in Codex) oder daran, dass die Nutzung in der Fußleiste den Schwellenwert erreicht (standardmäßig 95 %; maßgeblich ist der höchste Wert aus 5-Stunden-, Wochen- und modellbezogenen Zeitfenstern).
  2. Vor dem Wechsel bittet Ferret den aktuellen Agent, .ferret/handoff.md zu aktualisieren. Beginnt der Agent nicht damit (zum Beispiel weil er bereits am Limit ist), trägt Ferret selbst ein, was es weiß: die letzte Anfrage, wo feedback.md liegt, und die geänderten Dateien aus git status.
  3. Dann wechselt Ferret zu einem anderen angemeldeten Konto desselben Agents, und zwar zu dem mit der geringsten Nutzung. Sind alle Konten des Agents am Limit, geht die Arbeit an den nächsten Agent in der Reihenfolge der Agents (Standard: Claude Code → Codex → Gemini CLI).
  4. Der neue Agent öffnet sich in einem neuen Tab im selben Projekt und wird in der App-Sprache angewiesen, zuerst .ferret/handoff.md zu lesen und mit der verbleibenden Arbeit fortzufahren.
  5. Die Fußleiste zeigt Jetzt mit <agent>, und ein Hinweis sagt, was sich geändert hat, zum Beispiel Codex hat sein Nutzungslimit erreicht, daher hat Claude Code die Arbeit übernommen. Der Tab, der das Limit erreicht hat, wird geschlossen, damit er dieselbe Aufgabe nicht erneut aufnimmt, wenn sein Limit zurückgesetzt wird.
