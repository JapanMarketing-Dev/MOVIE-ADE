Installation Ferret ist eine Desktop-App für macOS, Windows und Linux. Der macOS-Build ist mit einer Developer ID signiert und von Apple notarisiert. Die Builds für Windows und Linux sind noch nicht codesigniert, daher verlangen diese Betriebssysteme beim ersten Start eine Bestätigung. ## Download

Laden Sie die Datei für Ihr Betriebssystem und Ihre CPU von der Download-Seite herunter. Die Dateien werden über Cloudflare R2 ausgeliefert, nicht über GitHub Releases, und nur die 10 neuesten Versionen werden aufbewahrt.

BetriebssystemDateien
macOS (Apple silicon / Intel)Ferret-<version>-mac-arm64.dmg, Ferret-<version>-mac-x64.dmg
Windows (x64 / arm64)Ferret-<version>-win-x64.exe, Ferret-<version>-win-arm64.exe (NSIS-Installer)
Linux (x64)Ferret-<version>-linux-x86_64.AppImage, Ferret-<version>-linux-amd64.deb

Releases bis einschließlich 0.1.x wurden unter dem alten Namen veröffentlicht, als MOVIE-ADE-<version>-…. Die Namen Ferret-… gibt es ab 0.2.0.

Ferret unterstützt macOS, Windows und Linux. Die Builds für Windows und Linux sind noch nicht codesigniert, daher verlangt der erste Start eine Bestätigung (siehe die Schritte unten).

## Download prüfen (signierte SHA256SUMS)

Jedes Release enthält eine Datei SHA256SUMS und deren Signatur SHA256SUMS.sig. Die Signatur wird mit dem Release-Schlüssel von Ferret erstellt, der getrennt vom Download-Server aufbewahrt wird. Ein auf dem Download-Server veränderter Installer kann daher keine gültige Signatur mitbringen. Der öffentliche Schlüssel wird nicht vom Download-Server bezogen: Holen Sie ihn aus dem Repository (build/release-signing/allowed_signers) oder kopieren Sie ihn von hier:

release@ferretade.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEpXERU8ST0MEOIMbzoL4zShkjIrMB4++NL3xBohKAS9

Sein Fingerprint ist SHA256:c7dvwwJQyY9qSstkmrO8JoVZ90DCaFZBAzjqV04N8zQ. Dieselben Dateien sind auch an jedes Release auf GitHub angehängt. Prüfen Sie die Signatur mit ssh-keygen (enthalten in macOS, Windows 10 und neuer sowie Linux) und vergleichen Sie dann den Hash Ihres Downloads mit der signierten Liste:

# the download server (currently the R2 public URL; it may move to a custom domain)
BASE=https://pub-588d93b3e875464f98d6cf98dc711a0c.r2.dev
VERSION=$(curl -s $BASE/latest.json | jq -r .version)
curl -sO $BASE/releases/$VERSION/SHA256SUMS
curl -sO $BASE/releases/$VERSION/SHA256SUMS.sig

# save the public key above as allowed_signers, then:
ssh-keygen -Y verify -f allowed_signers -I release@ferretade.dev -n ferret-release -s SHA256SUMS.sig < SHA256SUMS
# → Good "ferret-release" signature for release@ferretade.dev …

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
# Linux
sha256sum -c SHA256SUMS --ignore-missing
# Windows (PowerShell): compare with the line for your file in SHA256SUMS
Get-FileHash .\Ferret-<version>-win-x64.exe -Algorithm SHA256

Brechen Sie ab, wenn ssh-keygen nicht Good "ferret-release" signature ausgibt oder der Hash nicht in der Liste steht. Nach Updates suchen in Ferret führt dieselbe Prüfung mit dem in die App eingebauten Schlüssel durch und bietet keine Version an, deren Signatur nicht passt. Unter macOS können Sie außerdem die Developer-ID-Signatur und die Notarisierung mit spctl -a -vv /Applications/Ferret.app prüfen. Die Installer für Windows und Linux sind noch nicht von Microsoft oder einer Linux-Distribution codesigniert. Releases bis einschließlich 0.3.0 wurden vor Beginn der Signierung veröffentlicht und haben nur die unsignierten Hashes in releases/<version>/manifest.json.

## macOS
  1. Öffnen Sie die .dmg und ziehen Sie Ferret.app nach /Applications.
  2. Starten Sie die App. Sie ist mit einer Developer ID signiert und von Apple notarisiert (das Ticket ist angeheftet), daher öffnet sie sich ohne Warnung.

So prüfen Sie die Signatur selbst:

spctl -a -vv /Applications/Ferret.app
# accepted
# source=Notarized Developer ID

Nur ältere Versionen (0.2.0 Build 2 und früher) waren nicht signiert. Bei diesen meldet macOS, dass der Entwickler nicht überprüft werden kann: Schließen Sie den Dialog, öffnen Sie Systemeinstellungen → Datenschutz & Sicherheit, klicken Sie neben der Meldung zu Ferret auf Dennoch öffnen und bestätigen Sie mit Öffnen. Wenn gemeldet wird, die App sei „beschädigt“, entfernen Sie das Quarantäne-Attribut:

xattr -dr com.apple.quarantine /Applications/Ferret.app
## Windows
  1. Führen Sie Ferret-<version>-win-<arch>.exe aus.
  2. Wenn SmartScreen „Der Computer wurde durch Windows geschützt“ anzeigt, klicken Sie auf Weitere Informationen und dann auf Trotzdem ausführen.
  3. Wählen Sie den Installationsordner. Der Installer legt eine Verknüpfung auf dem Desktop an.
## Linux

AppImage:

chmod +x Ferret-<version>-linux-x86_64.AppImage
./Ferret-<version>-linux-x86_64.AppImage

Debian / Ubuntu:

sudo apt install ./Ferret-<version>-linux-amd64.deb

Das deb-Paket installiert das Paket und den Befehl ferret.

Unter Ubuntu 23.10 und neuer kann das AppImage beim Start mit einem Sandbox-Fehler abbrechen, weil AppArmor die User Namespaces einschränkt, die die Sandbox von Electron nutzt. Installieren Sie stattdessen das .deb; es richtet den Sandbox-Helfer ein.

## Aus dem Quellcode bauen

Voraussetzungen: Node.js 20+ (CI und lokale Entwicklung verwenden 22), pnpm und git.

git clone https://github.com/JapanMarketing-Dev/ferret.git
cd ferret
pnpm install          # postinstall prepares node-pty for Electron
pnpm dev              # run in development mode

So erstellen Sie Installer (Ausgabe in dist/release/, Konfiguration in electron-builder.config.cjs). Der Linux-Build läuft nur unter Linux.

pnpm dist:mac     # dmg (arm64, x64)
pnpm dist:win     # NSIS installers (x64, arm64)
pnpm dist:linux   # AppImage + deb (x64)

Die Skripte build:<os>:dev erzeugen nur eine entpackte App (--dir), was für lokale Tests schneller ist.

Unter Windows verwendet pnpm install die mitgelieferten vorkompilierten Binärdateien von node-pty, statt sie neu zu bauen (dafür wären die Visual Studio C++ Build Tools nötig). Setzen Sie ADE_FORCE_NATIVE_REBUILD=1, um einen Neubau zu erzwingen.

Wenn das Terminal meldet, dass node-pty nicht geladen werden konnte, führen Sie pnpm rebuild:native aus.

## Updates

Ferret aktualisiert sich nicht automatisch. Öffnen Sie in der Fußzeile Updates und klicken Sie auf Nach Updates suchen. Die App lädt latest.json vom Download-Server (R2), vergleicht die Versionen und verlinkt auf die Download-Seite. Ab 0.4.0 prüft sie außerdem die Signatur der SHA256SUMS dieser Version mit dem in die App eingebauten Release-Schlüssel und bietet keine Version an, deren Signatur sich nicht verifizieren lässt. Vor Ihrem Klick wird nichts geprüft, und nichts wird automatisch installiert.
